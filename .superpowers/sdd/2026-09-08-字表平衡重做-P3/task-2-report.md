## 2 · 对账新增的 `summonShield` 列(两边都动了)

### 2.1 脚本侧产出

`rebalance_2026_09_05.py` 此前**只把光环盾当 `PRICE` 条目扣预算,不产出点数**,
所以对账没有期望值可比。现在在 `sum` 分支里产出合并后的单个数值:

```python
ss=(MARK_SHIELD if marked else 0)
if '光环盾' in ts: ss+=int(round(hp*AURA_SHIELD_F/10.0))*10
sm=f"{n} 只 · {hp} 血 / {at} 攻"+(f" · 盾 {ss}" if ss else "")
```

两个关键取舍:

1. **合并成一个数值,不是两个字段**。spec §10.2 查实:「入场护盾」与「光环盾」都只能落到
   `EffectDef.SummonShield` 这一个字段上,而一个 `Summon` 效果只有一个该字段 ——
   不可能并存两份。所以 `ss` 是一个 int,不是 `(印记, 光环)` 二元组。
2. **值印在 §6 那张表里(召唤列的 `· 盾 S` 后缀),不只放在 row dict 里**。
   §6 是 P2/P3 落地的施工图 —— P2 Task 4a 漏掉土系入场护盾,根因正是
   「印记被 `remove` 之后从表上消失了,表上没写就落不了地」(脚本里 2026-09-07 那段注释)。
   放进 dict 而不印出来会重演同一个毛病。所以格式选了 `1 只 · 221 血 / 17 攻 · 盾 50`,
   盾为 0 时不印后缀 —— 木系 10 张召唤字的召唤列因此**逐字不变**。

### 2.2 测试侧断言

`test_summon_matches_target` 从比 3 元组扩到 4 元组:

```python
_SUMMON_RE = re.compile(r"(\d+) 只 · (\d+) 血 / (\d+) 攻(?: · 盾 (\d+))?")
...
got = (count, value, attack, summons[0].get("summonShield", 0))
want = (int(m.group(1)), int(m.group(2)), int(m.group(3)), int(m.group(4) or 0))
```

断言走**正则解析打印出来的召唤列**而不是直接读 `r["ss"]` —— 这样这一条同时守住
「脚本算对了没有」与「施工图印对了没有」两件事;只读 dict 的话,印错/不印仍然全绿。
可选组 `(?: · 盾 (\d+))?` 让 10 张无盾召唤字沿用原格式,不必给它们印一个 `盾 0`。

### 2.3 顺手补的第二个同类盲区:金系战意(**超出 brief 字面的一处增补**)

## 5 · 「全场加盾」这个措辞:**保留不改**

`gen_char_doc.py` 现在给这四个字印出:

- 特性技能列:`全场加盾 20` / `全场加盾 50` / `全场加盾 150`
- 功能列:`(全场召唤物 +20 盾)`

判断分两半。

**「全场」这半是准确的,不该改。** 我读了引擎那段(`BattleEngine.cs:2743`):

```csharp
foreach (var summon in _summons)
    if (summon != null && summon.Alive) summon.Shield += shieldGrant;
```

它遍历的是 `_summons` 全表 —— **场上所有存活召唤物,不限于这张字自己召出来的那只**。
只数收归 1 只**不等于**场上只有 1 只:召唤槽上限是 6(`BattleEngine.SummonCap`),
碉 / 堡 / 塔 / 桂 加上木系 10 张召唤字完全可以同场。桂 的 150 点盾会同时糊到
场上每一只召唤物身上,这正是「全场」二字要表达的、也是它区别于「只给自己那只」的地方。
把它改成「给召唤物加盾」反而会丢掉这条信息(而这条信息现在比以前更重要:
土系四张召唤字互相之间是有配合的)。

**真正缺的那半是「同时攒厚」,但我没改,理由是范围。** 同一段代码紧接着有:

```csharp
GainHeft(shieldGrant);   // 桂 的全场加盾同样攒厚(2026-09-02)
```

这是土系召唤字**唯一**能攒厚的路径(spec §10.2),也是这次给四张字补印记的一个主要动机
—— 而卡面与文档现在都完全不提它。玩家看不出「出一张 碉 也在给 崩 / 㙓 的厚积薄发攒层」。

不在本批改的理由:这是**玩家可见文案**,一改就是三处对账 ——
`strings.zh-CN.json` 的 `char.effect.summonshield` + `collection.trait.summon_shield.desc`
(卡面详情与收藏页特性两条各自的模板)+ `gen_char_doc.py` 的两处 `add(...)`;
且「厚」这个用词属于战斗状态词表,措辞该与 `StatusText` / `BattleView` 那套对齐,
不该由字表批次单方面定。本批的边界是「数值落地,不动 Core / Presentation」。

**建议(留给下一批)**:把三处模板统一改成「全场召唤物各 +N 盾,并攒厚 N」。
注意 `GainHeft` 按**单只量**攒(不是发出去的总量),所以文案里的两个 N 是同一个数,
不需要乘只数。字体子集不受影响 —— 「攒」「厚」都是已有字形(本批 `pytest tools/fonts/tests/`
全绿即证明本批零新增汉字)。
