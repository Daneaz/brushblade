**Goal**：把 spec v7 §1、§5.2、§10、§11 定下的全局规则落进 Core：

**Architecture**：分两段做，靠 `tools/trace` 区分「接错了」和「本来就该变」。

- **发散段（Task 9–11）**：冻结、冰滞、上限会真实改变战斗结果。
  - 每个任务都列出**预期变红的测试**和它们的新值。

## Review Focus

1. **全体范围不选目标（`targetIndex = −1`）**：`DamageSingle` 分支在循环外读 `_enemies[targetIndex]`（镇压、事件）会越界。Task 2 有「多敌人、无目标、All」的出字测试。
2. **冻结被拒时的副作用**：已冻结、霜抗中、冰滞中的目标再被冻结时，不应发 `StatusApplied` 钩子；概率冻结消耗的随机数次数必须和「没被拒」时一样。Task 9 有测试。
3. **冰滞把 Boss 行动条推成负值**：调度器、`Forecast`、行动条 UI 都要能处理负的 `ActionMeter`。Task 10 有调度测试，并在表现层确认行动条有钳位。
4. **护盾上限后飘字与入账不一致**：`Shield` 事件报的量必须等于实际入账的量，不能报请求量。Task 11 有测试。
5. **等级曲线浮点陷阱**：`100 × (1 + 0.06 × 2)` 在 double 下是 112.00000000000001，`Ceiling` 后得 113。Task 7 用整数算式，并加 (100, Lv3) = 112、(25, Lv3) = 28 两条守卫。
6. **格挡被铁画反噬吃掉**：反噬走 `DamagePlayerDirect(allowReflect: false)`，不是敌人挥击，不应消耗格挡。Task 5 有测试。

## Task 2：新增 `TargetArea.All`，退役 `EffectKind.DamageAll`（恒等）

**目的**：spec §3.2、§11.6。全体伤害改由 `DamageSingle` + `Shape = All` 表达，引擎只剩一条伤害分支。11 张字（燚 焚 焱 爆 炸 烈 㵘 溃 淋 㙓 崩）的数据表示会变，但战斗结果必须逐字节不变。

**口径（裁定）**：
- `All` 下**每个目标都是主目标**：都吃斩杀、`ExecuteBonus`、`Pierce`、`HitCount`，比例都是 100%，不读 `ShapePercent`。这与现有 `DamageAll` 逐位一致。
- `ExpandTargets(All)` 按下标升序返回**出字那一刻**的全部存活敌人。跨排 Boss 只出现一次，不走 `AddHits` 的双记。返回值本身是快照，出字途中分裂出的新怪不吃这一发，与 `DamageAll` 的 `aoeCount` 同口径。
- `All` 不需要目标：`EffectNeedsTarget` 对它返回 false，`targetIndex` 可以是 −1。
- 删除 `EffectKind.DamageAll` 这个枚举值，不留占位。EffectKind 序号不进存档（chars.json 按名字解析），项目未上线也不需要存档兼容。

  /// <summary>R3(spec v7 §10):本次出字**之前**每个敌人满足哪些 <see cref="DamageCondition"/>,
  /// 按敌人下标存位掩码。只在 ApplyEffects 的同步调用栈内非 null;不进快照存档
  /// (与 _critMoraleGrantedThisCast 同类的瞬时量)。</summary>
  private int[] _preCastConditions;

  private static readonly DamageCondition[] SnapshotConditions =
  {
      DamageCondition.Burning, DamageCondition.Bleeding,
      DamageCondition.Controlled, DamageCondition.ArmorBroken,
  };

  private int[] CapturePreCastConditions()
  {
      var masks = new int[_enemies.Count];
      for (int i = 0; i < _enemies.Count; i++)
          foreach (var c in SnapshotConditions)
              if (ConditionMet(c, _enemies[i])) masks[i] |= 1 << (int)c;
      return masks;
  }

  /// <summary>条件判据的唯一入口:出字中读出字前快照,不在出字中读现值。
  /// 出字途中才出现的敌人(分裂)出字前不存在,条件视为不满足。</summary>
  private bool PreCastConditionMet(DamageCondition condition, int enemyIndex)

      if (condition == DamageCondition.None) return false;
      if (_preCastConditions == null) return ConditionMet(condition, _enemies[enemyIndex]);
      if (enemyIndex >= _preCastConditions.Length) return false;
      return (_preCastConditions[enemyIndex] & (1 << (int)condition)) != 0;
  }

## Task 5：格挡（恒等：现有字表没有任何格挡数据）

**目的**：spec §3.1「格挡：下一次受到的伤害 −40%，并反击攻击者」，§4「铠：格挡 N 次（反击本体 30%）」，§5.2 第 1、3、4 律。

**口径（裁定）**：
- **状态**：`StatusKind.Block` 挂在玩家的 `StatusBag` 上。
  - `Magnitude` = 剩余次数，`CounterDamage` = 每次反击的伤害，`TurnsLeft = -1`（本场有效，用完为止）。
  - 木灵身上的格挡（§2.2 金·铠拖到木灵）归 Plan D。
- **出字**：`EffectKind.Block`，`Value` = 次数（离散量，不吃等级）。反击伤害 = 本字**攻击面**第一条 `DamageSingle` 的 `Value` 经卡等级缩放后 × `BattleConfig.BlockCounterPercent`（30）/ 100。没有攻击面就读 `Effects`，都没有则反击为 0（只减伤）。
  - 依据：designer 稿 `traits-data.js` 铠面「反击 = 94 × sc(L) × 30%」，94 是剑的攻击面伤害。
- **同类取最强**（§5.2.1）：已有格挡时，次数取较大值，反击取较大值，不累加。
- **触发**：只在敌人对玩家的挥击（`DamagePlayerDirect` 且 `allowReflect == true`）时触发。打空、免疫挡下时不消耗；铁画反噬不消耗。

  /// 拦截:冻结(已冻结 / 霜抗中不得再冻,R1;Boss 改冰滞见 Task 10)、减速合并(R1)、
  /// 格挡同类取最强(§5.2.1)。</summary>
  private bool ApplyStatus(StatusBag bag, StatusEffect effect, UnitRef target, UnitRef applier)
  {
      if (effect.Kind == StatusKind.Freeze && target.Side == UnitSide.Enemy)
      {
          if (bag.Has(StatusKind.Freeze) || bag.Has(StatusKind.FrostResist)) return false;
          effect.Magnitude = effect.TurnsLeft;   // 记下冻结时长,结束时发等长霜抗

      {

          {

              effect.TurnsLeft = Math.Max(effect.TurnsLeft, old.TurnsLeft);
              bag.RemoveEntry(old);
          }
      }
      // (Task 5 的 Block 同类取最强分支保留在这里)
      bag.Apply(effect);
      Raise(HookKind.StatusApplied, target, applier, effect.Magnitude, status: effect.Kind);
      return true;
  }

## Task 10：R1b Boss 冰滞（发散）

**目的**：spec R1b「Boss 被冻结时一律改为冰滞：行动条后退一半，下次行动前受伤 +15%」，任何字都不能真正冻结 Boss。

**口径（裁定）**：
- **转换**：`ApplyStatus` 的冻结拦截里，目标 `IsBoss` 时：
  - 已有 `IceStall` 或 `FrostResist` → 拒绝。
  - 否则改挂 `StatusKind.IceStall`：`Magnitude` = 本该冻结的回合数 N，`TurnsLeft = -1`，`Polarity = Debuff`。
  - 同时 `enemy.ActionMeter -= TurnScheduler.Threshold * BattleConfig.IceStallPushPercent / 100`，其中 `IceStallPushPercent = 50`。
  - 行动条可以变成负值：「后退一半」= 推迟半个行动条，不按当前进度打折。
  - 返回 true，发 `StatusApplied`，`status = IceStall`。
- **易伤**：`DamageEnemy` 在暴击之后、护甲折算之前：`if (enemy.Statuses.Has(StatusKind.IceStall)) damage = damage * (100 + BattleConfig.IceStallDamageTakenPercent) / 100;`，常量为 15。用整数乘除，不用 `1.15f`。
  - 灼烧、流血、引爆、斩杀直杀不走 `DamageEnemy`，**不吃**易伤。
- **结束**：Boss 下一次行动开始时（`ActEnemyTurn` 里 `TurnStarted` 之后、灼烧结算之前），移除 `IceStall`，挂霜抗 `TurnsLeft = N + 1`。这一拍末尾的 `TickTurns` 会减 1，所以霜抗完整覆盖之后 N 次行动。
- `ConditionMet` 的 `Controlled` 加上 `IceStall`：冰滞是 Boss 的冻结。
- `Targeting` 的 `preferUnfrozen` 同时避开冰滞。
