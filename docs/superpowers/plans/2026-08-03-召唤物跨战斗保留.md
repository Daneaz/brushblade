# 召唤物跨战斗保留 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 召唤物不再随战斗结束清空，改为与普通护盾同口径全程延续（层间、段间、挂起续爬都保留），直到死亡或整次登塔结束。

**Architecture:** 沿用护盾已铺好的三条传递路径，携带载体复用现成的 `SummonSnapshot`（战斗内断点存档已在用），不新增类型：`RunEngine._carriedSummons` 管段内跨层，`EndlessSaveState.CarriedSummons` 管跨段，战斗中挂起靠既有 `InProgressRun` 无需改动。带走时只取 `Alive` 的、保留当前 Hp。

**Tech Stack:** Unity 6000.5.2f1；Core/Data 为纯 C#（禁引 UnityEngine）；测试 NUnit，跑在 `tools/coretests` 离线工装；Presentation 用 `tools/prescompile` 离线编译验证。

**Spec:** `docs/superpowers/specs/2026-08-03-召唤物跨战斗保留-design.md`

## Global Constraints

- **Core 与 Data 禁止引用 UnityEngine**（asmdef `noEngineReferences: true`）。本计划的 Core 改动全是纯 C#。
- 随机性只走 Core 内带种子的 `GameRandom`，禁用 `UnityEngine.Random`。本计划不引入新随机。
- **测试断言禁用 `Is.AnyOf` / `Is.All.AnyOf`**（Unity 自带 NUnit 没有）。多选一用 `Is.EqualTo(a).Or.EqualTo(b)`。
