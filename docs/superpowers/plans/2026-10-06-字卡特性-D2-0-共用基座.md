# 字卡特性 Plan D2-0：专属特性的共用基座 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为五系专属特性（206 条）铺好共用机制：跨段开局效果在仿真里携带、嘲讽状态、五行面落到木灵（spec §2.2，含木灵格挡）、嫁接、本命（10 个木字 + 花灵）与本命强化、拆字 / 成字触发，以及 Lv4 目标条件在五行面上退化为精进。

**Architecture:** 全部沿用 D1 的运行时（反应队列、`TraitRules.Fold`、`ApplyStatus` 入口、附着载体）。本命落在 `SummonPassive` 的新字段上，Lv3 本命强化用「`Summon 0` 只覆盖被动」的替换语义；§2.2 是一条按「面 × 落点」的出字后规则，集中在一个方法里；「本场」改动（嘲讽、木灵格挡、属性、嫁接本命）在战后由 `RunEngine.CaptureAliveSummons` 复原。拆字 / 成字特性是新的 `TraitTrigger`，即时类走 `ApplyDetachedEffects`，「拆出的部件本回合出手时」类记成部件印记（计数字典，进快照）。

**Tech Stack:** Unity 6000.5.2f1；Core/Data 纯 C# 9（`noEngineReferences`）；NUnit（`tools/coretests`）；Python 3 管线（pytest）；`tools/trace` / `tools/balance`。

**Spec:** `docs/superpowers/specs/2026-10-03-字卡五特性体系-design.md`（v7，含 2026-10-06 补充裁定）。前序：`docs/superpowers/plans/2026-10-04-字卡特性-D1-运行时与池.md`（末尾「执行记录」的前置项）与 `docs/superpowers/plans/2026-10-04-字卡特性-D1-附录-机制缺口.md`（下文「附录 Mx」）。

**D2 的拆分**：D2-0（本 plan，共用基座）→ D2-火 → D2-金 → D2-水 → D2-土 → D2-木，每份执行前再写。各系 plan 的结构沿用附录 §5.3：本系独有机制 → 小扩展 → 本系专属数据（✅ 行）。本 plan 不落任何专属特性数据（字形特性的机制在这里，数据随各系 plan）。

**本 plan 裁定**（执行记录里写理由与代价）
- **E1 铠落木灵**：格挡挂到目标木灵身上；战意仍加给玩家。理由：木灵攻击本来就吃玩家战意（`SummonState.PlayerAttackPercent`，2026-09-05 裁定），另建一份木灵战意等于两套资源。spec §2.2「木灵获得格挡和战意」由此满足。
- **E2 §2.2 只看「本字是哪一系的五行面 + 落点是不是活着的木灵」**：水的五行面落木灵 → 本场改水属性；土的五行面落木灵 → 本场嘲讽；金的五行面落木灵 → 格挡落木灵（E1）；木的五行面落木灵 → 嫁接（Task 5）。火的燃面不选友方，不受影响。攻击面一律不触发。
- **E3 「本场」的复原点**：`RunEngine.CaptureAliveSummons`（战后带木灵进下一场的唯一出口）。按 Kind 白名单剥离本场状态：`Taunt`、`Block`、`Endure`、`DamageCut`、`CounterBoost`（顺带解决 D1 前置项「保命随召唤物跨场」）；属性与本命复原到嫁接 / 改属性之前。按 Kind 而不是按 `TurnsLeft` 剥离，是为了不碰现有跨场的入场护甲（`DefenseBuff`、`TurnsLeft = -1`）。
- **E4 解封与 §2.2 改属性**：解封（Unseal）是永久重掷。同一场里先润后解封：以解封为准，并清掉「战后复原」记号；先解封后润：战后复原到解封后的属性。
- **E5 嫁接**：生面拖到活着的木灵上 = 嫁接，不召新木灵（召唤位满也能用）：回满生命，本命换成本字的本命（按本字等级缩放，Lv3 已解锁则用强化版），本场有效。本字生面上的其他效果（幼苗、沃土等）照常结算。Core 先提供 `Cast(..., allySlot)` 入口，拖放交互归 Plan E。
- **E6 本命 = 召唤物被动的全部内容**：spec §9「本命沿用 v3」。召唤物被动只保留本命对应的字段和底速 `SummonSpeed`（底速是属性，不是被动）。现有数据里与本命无关的被动（森 / 林 / 藻的自愈、桂 / 森 / 𣛧 的荆棘、𣛧 的攻击光环、荆的嘲讽）与桂的入场全场护盾（附加效果）一并作废。数值（血 / 攻）不动，Plan F 定标。

**Interfaces**（Produces）：
```csharp
// StatusEffect.cs
public static class StatusRules
{
    /// <summary>「本场」状态:木灵战后带进下一场之前剥离(spec §3.3,E3)。按 Kind 判定,不看 TurnsLeft ——
    /// 入场护甲(DefenseBuff,TurnsLeft = -1)要跨场保留。</summary>
    public static bool IsBattleScoped(StatusKind kind) =>
        kind == StatusKind.Taunt || kind == StatusKind.Block || kind == StatusKind.Endure
        || kind == StatusKind.DamageCut || kind == StatusKind.CounterBoost;
}

// Targeting.cs —— 新增参数放在末尾,缺省 false,既有调用点不改也编译
public static int PickAllyTarget(AttackRange range, AttackFocus focus,
    IReadOnlyList<SummonState> summons, int frontRow, GameRandom random, bool playerTaunting = false);
```
- `TauntingSlots` 的判据改为 `summon.Passive?.Taunt == true || summon.Statuses.Has(StatusKind.Taunt)`。
- `PickAllyTarget` 第一行：`if (playerTaunting) return PlayerTarget;`（不摇随机数）。
