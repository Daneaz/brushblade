[Test]
public void ApplyDefense_IsPercentageReduction_NotSubtraction()
{

    Assert.That(BattleEngine.ApplyDefense(200, 100), Is.EqualTo(100), "甲 100 应减伤 50%");

`CORETEST`。预期:`ApplyDefense` 不存在,编译错 CS0117。

- [ ] **Step 4: 实现**

在 `BattleEngine` 类里加(放在 `EffectivePlayerDefense` 附近,与其他护甲函数同区):

```csharp
/// <summary>护甲折算(2026-09-16):DR = 甲/(甲+100),即 伤害 × 100 ÷ (100 + 甲)。
///
/// 推翻 2026-08-12 E-b4 的点数减法。选它的全部理由是**永远到不了 100%** ——
/// 「甲不能叠加」这条约束因此可以拆掉(<see cref="StatusKind.DefenseBuff"/> 随之改可叠)。
///
/// 三个承伤落点(DamageEnemy / DamagePlayerDirect / DamageSummon)共用这一个入口,
/// 不许各写一份:那正是两处口径分叉的起点。
///
/// 整数除法天然向下取整,不需要外层 Math.Max(0, …) —— 分母恒 ≥ 100、被除数非负。
/// 护甲在这里再钳一次 0 是防御性的:三个聚合函数已经钳过,但它们不是唯一调用面。</summary>
internal static int ApplyDefense(int damage, int armor)
    => damage * 100 / (100 + Math.Max(0, armor));
```

三处落点改成:

```csharp
// 3659(玩家打敌人)
if (!bypassDefense && !counters)
    damage = ApplyDefense(damage, EffectiveEnemyDefense(enemy, pierce, attackerBag));

// 3893(敌人打玩家)
damage = ApplyDefense(damage, EffectivePlayerDefense);

// 3997(敌人打召唤物)
taken = ApplyDefense(taken, summon.EffectiveDefense);
```

三处的既有注释里凡写「点数减法」「减甲」「甲厚过攻击力时不给召唤物回血」的措辞,
改成百分比口径,并注明日期 2026-09-16 与推翻的是 E-b4。

- [ ] **Step 5: 跑测试确认通过**

`CORETEST`。**预期会有既有测试变红** —— 全表按点数减法算过期望值的那些。
逐条看:期望值本身过时的,按新公式重算期望值;断言的是「护甲起作用了」这种性质的,不动。
**不许为了让测试变绿而改公式。**
