# 字卡特性 Plan E3：拍板 chip 落地 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 2026-10-04 至 10-11 用户已拍板、但还没实现的稿落进游戏。包括：
- 水土状态 chip 8 枚，加 10-04 补的反击加倍、保命两枚，另有封字代价态；
- 水土与嫁接的提示反馈；
- 部件印记角标，以及「山」全体落点；
- 字形特性飘字；
- 花灵形象；
- Boss 格 chip 放到 3 行；
- 顺带修掉 `gen_char_doc` 对已删接口的引用。

**Architecture:**
- Core 只做两类事：发出现在缺的信息（3 个新事件、2 个 EffectSource 标签、Graft 回复量），以及补只读接口（印记、本回合实际效果表、字形特性的「本场已用」）。全部走 TDD。
- 新事件只写在新状态存在的分支内，trace 两档必须恒等。
- Presentation 按稿接上 chip、飘字和角标。

**Tech Stack:** Unity 6000.5.2f1；Core/Data 纯 C# 9；NUnit（`tools/coretests`）；Python 3（图标、召唤物素材、字体子集管线）。

## 已定口径

**用户授权**：待裁定项由 controller 按推荐口径自行决定，事后汇报。设计验收跳过，体验时再反馈（用户 2026-10-11）。附录 §10 的 Q1–Q14 全部采用推荐口径，要点如下：

- **Q4**：多条「每回合效果」同时存在时，chip 上的数字取 `max(TurnsLeft)`。
- **Q5**：全量免疫减益和只拦灼两种同时存在时，各出一枚 chip（`ward`、`wardburn`）。
- **Q6**：倾覆封字（减益）和杜门不出封字（代价）同时存在时出两枚：一枚实底，一枚描边。
- **Q7**：木灵 Block > 0 时，木灵格也画反击加倍。这一点要回填进稿。
- **Q8**：删掉 `AppendGraftMessage` 的调用和 `battle.msg.graft`。代码里没有战斗记录，稿的本意就是「不弹文字条」。
- **Q9**：受击回复 / 受击得盾在详情里的 chip 不再印数字，数值放进说明文字。
- **Q10**：保命的触发反馈不在本 plan 做，归 TriggerFx / Plan E。
- **Q11**：拦截飘字用 `Popup` + 一条横线 Image 当删除线，60% alpha，状态色。旧 `Text` 不支持 `<s>`，所以要自己画线。不做 TriggerFx 的全套样式。
- **Q12**：杜塞、浮屠、碎玉的特性名用 `EffectNameOf(kind)` 取。现在的数据里每个 Kind 只出现在一张字上，所以取得到唯一结果。

- **Q14**：`Graft.Amount` 改为回复量。SkillCut 的时长用新 key「下次大招前」。
- **两个顺带修复的现有缺陷**（附录 §0 / §1.4）：
  - `TraitSpentThisBattle` 查不到字形特性：字形特性的次数阀键是裸 TraitKey。改成：Trigger 是拆字 / 成字时，查 `_traitUsesThisBattle[TraitKey]`。

## Global Constraints

- **分层**：Core / Data 禁止引用 UnityEngine。新的 Core 接口必须是 public（Presentation 只能访问 public，prescompile 按 asmdef 分程序集编译）。
- **trace 恒等是每个任务的硬验收**：普通档 sha `7235e89f…`，`--flat-scale` 档 `883954a3…`。
  - trace 的 sha 把每条事件都算进去，所以新事件必须严格写在 `bag.Has(...)` 或 `TryUseTrait` 通过的分支里。
  - 改热路径（`ApplyStatus`、`CastCore`、拆合）时，另加「无新状态时逐位恒等」的对照测试，期望值用 `git archive <base>` 导出改动前的代码实跑核验。
- **枚举**：`BattleEventKind`、`EffectSource` 只能在末尾追加。
- **玩家可见文案**：走字符串表，key 只写字面量；删掉调用时同时删表项。新增或改动文案后重跑字体子集，比对 cmap。

- **共享交互状态**：给共享状态赋予新含义时，grep 全部读取点。「山」的落点从静态查询改成实例查询，附录 §4 列了 5 个读取点，全部要改。

## Review Focus

1. **trace 与热路径**：在 `ApplyStatus`、`CastCore`、拆合里，没有新状态时事件流和 RandomState 逐位不变。拦截事件只在 `bag.Has(DebuffWard / BuffBlock)` 时发出。
2. **「山」的 5 个读取点**：`ShowDragTargets`、`OnDragHover`、`allyOnly`、`CastInDirection`、再点直出。这 5 处与 Core `CastCore` 的 needsTarget 必须同源（都用 `CastEffectsNow`）。不能出现「UI 要选目标、Core 不要」或反过来的情况，AP 也不能白扣。
3. **拆合路径接入播放流程**：输入锁、重绘次序、「重绘销毁正被拖对象」都要处理好。连拆、连合、拆后立即拖出这三种情况不能卡死，也不能重复播放。
4. **chip 组合**：Q5 两枚免疫同在、Q6 两枚封字同在、多条每回合效果同在、Boss 第 3 行，在两档宽下顺序要对、不能溢出。
5. **字形特性的「本场已用」**：双木 / 三焰等用过一次后，E2 字卡详情那一行要显示「本场已用」，下一场恢复。
