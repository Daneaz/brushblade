## 0. 先说结论(给 controller 的五句话)

1. **三块稿都有现成骨架可挂**:字卡详情 = `CharPreview.Show`(六个入口共用一份),升级预览 = `CollectionView.ShowUpgradePreview`。外壳尺寸与稿逐数吻合(1591×818 / 1591×670 / 1088×670),要换的是**内部全部段落**。
2. **特性在 UI 上目前完全不可见**:`TraitDef` 没有任何 Presentation 调用方,`CharInfo.TraitEffectsText` 只在注释里被点名「Plan E 的入口」。现在详情里的「特性 · 技能」是 `CardTraits.Of` 从**本体效果**反推出来的旧概念,与 spec v7 的 Lv3–Lv8 特性无关。
3. **稿的数据假设与真实数据有三处不一致**(第 7 节详述):Lv3 在数据里恒为**分面两条**;**22 张字的 Lv4 也是分面两条**(稿假设 Lv4 两面通用);文案来源 `TraitEffectsText` 是机械拼句,最长 60 字(稿用 spec §9 手写 ≤25 字)。
4. **屏比:横向基本放得下,纵向放不下**。16:9 下每面正文只有约 21 字 / 行,一面最多 8 行正文 + 4 个行头,远超稿上「一面三行」的竖向预算 → 两面区必须进竖向滚动(现成的 `Ui.ScrollList`,CP 里已经这么用);**不需要 `Ui.HScrollFill`**。有两处横向临界要特判(木的面头落点句、头部等级行)。
5. **「此刻的场面」与 2026-09-05 用户拍板冲突**:当时用户明确要求移除(提交 `d3cab4a2`),10-04 拍板稿又把它加回来。按时间,后拍板的稿优先,但建议 plan 里写明并请用户确认一句。

## 2. 数据来源

### 2.1 特性按(槽, 面)取

- 数据:`CharDef.Traits`(`IReadOnlyList<TraitDef>`)。`TraitDef` 在 `Core/TraitDef.cs:50`,字段有 `Slot`(枚举值 = 解锁等级)、`Face`(Both / Attack / Feature)、`Form`、`Trigger`、`Replaces`、`Name`、`Effects`、`MaxPerCast`、`MaxPerBattle`。
- 规则:`TraitRules.Unlocked(def, level)`(`Core/TraitRules.cs:14`)按槽位升序,**被替换的 Lv1 仍返回**(专为 UI 显示名字而设)。
- **真实数据分布**(55 张非部件字共 517 条,另 52 个是部件,没有特性):

  | 槽 | Both | Attack | Feature | 备注 |
  | --- | --- | --- | --- | --- |
  | Lv1 | 55 | – | – | 效果恒为空,`TraitEffectsText` 会印「无战斗效果(可兜底一击…)」,**不能当一行画** |
  | Lv3 | – | 55 | 55 | **恒为分面两条**,`Replaces=Lv1`;44 张两条同名(「灼·强化」),11 张木 / 花不同名(「种·强化」+「参天·强化」,五行面那条是本命强化 Passive) |
  | Lv4 | 33 | 22 | 22 | **22 张字是分面两条同名、效果不同**(例:焚风攻「伤害+25%(目标带灼烧时)」/ 燃「本字效果+25%」) |
  | Lv5 | – | 55 | 55 | 折桂是 Passive / OnKill |
  | Lv6 | – | 21 | 34 | 每张字一条 |
  | Lv8 | – | 55 | 55 | 2 条 Passive |

  每面行数(Lv4 若分面就计进面里;Lv5 / 6 / 8):3 行 55 面,2 行 33 面,**4 行 22 面**。
- 文案:`CharInfo.TraitEffectsText(TraitDef, CharDef, int)`(`Presentation/CharInfo.cs:408`)。仓库里**零调用方**,本 plan 是它的首个调用者。
  - 在 scratch 工程里对 517 条全跑过一遍,零异常。
  - 输出是机械拼句,带缩放后的实数、触发前缀(「击杀时:」)和次数后缀(「(每场限 1 次)」),**没有术语标记**。
  - 长度:中位 18 字,最长 60 字(冷 Lv8「冷却」);≥ 40 字的有 26 条。
  - 未解锁的行建议按 `max(cardLevel, UnlockLevel)` 印数值,`HealReshapeFace` 内部已经是这个口径。

### 2.2 本体数值按面

- 本体:`BattleEngine.EffectsOf(def, attackMode)`(`Core/BattleEngine.cs:1836`,**internal**)。
- 折叠:`TraitRules.Fold(body, def, face, level, skip)`(`TraitRules.cs:124`)/`CastEffects`(`:68`)。
  - Lv3 替换本体(`Replaces == Lv1`)只换同 Kind 的值,所以「Lv1 本体 + Lv3 替换」= spec 说的「本体」(`TraitRules` 注释:「Lv1 / Lv3 是本体」)。
  - 用 `skip: t => t.Slot >= TraitSlot.Lv4` 就能得到它。
  - Amplify 类修饰器只往 `AmpTerms` 里加条件项,不改 `Value`,所以把 Lv4 并进来也不会改伤害数字;但 Augment(如 㙓 深厚「护甲回合 +4」)会改回合数。
- 缩放:`MetaRules.ScaleEffectValue(kind, value, level)`(`Core/Meta.cs:859`)。层数、回合、次数不缩放。
- E1 相关:`CardFaceRules.HasTwoFaces`(`Core/CardFaceRules.cs:22`),55 张字全是两面字(部件除外),所以**单面字只剩部件这一种**,沿用旧分支即可。
- 现有的 `CollectionStats.Of` 不分面,不能用。需要新写按面取数的纯函数(见 2.7)。

### 2.3 等级 → 槽位映射

- `TraitSlot` 枚举值即等级(`TraitDef.cs:7`),「Lv2/7/9/10 只涨数值」写在注释里。`MetaRules.MaxCardLevel = 10`(`Meta.cs:68`)。
- 等级条记号:稿的规则是 Lv1 / 3 / 4 = 空心(两面),Lv5 / Lv8 = 两枚(左攻右五行),Lv6 = 它挂的那一面。
  - 数据里 Lv3 恒分面、Lv4 有 22 张分面。**建议记号按槽位定,不按数据里的 Face 定**(spec §1:Lv3、Lv4 写的是「两面」)。见 Q3。

### 2.4 「落点 · 范围」

- 落点:`CardFaceRules.Landing(def, face, level)`(`CardFaceRules.cs:27`,返回 `FaceLanding` flags,E1 已在拖拽路径使用)。映射到稿上的说法:
  - `Enemy`:「拖到敌人」
  - `Self|Summons`:「拖到自己或木灵」
  - 只有 `Self`:「拖到自己」(稿没画,真实数据里可能出现)
  - `EmptySlot(|Graft)`:「拖到空位召唤 · 拖到木灵上嫁接」
- 范围:没有现成的公开函数。`CharInfo.ShapeLabel` 是 private,而且是按效果取的。
  - 建议新写 `AreaOf`,取这一级**折叠后**本面的效果:第一条 `DamageSingle.Shape`;没有伤害时,含 `*All` 类或 `EffectPick.All` 算全体,否则单体;召唤面不印范围。
  - 剑 Lv8「横扫千军」会把范围改成横扫,所以必须按当前等级取。稿的数据固定写「单体」,是稿的简化。
- 范围文案现成:`char.shape.single / all / sweep / cleave / skewer / volley / chain`。

### 2.5 升级前后的数值差,现在怎么算

- 现在:CV:727–738 `CollectionStats.Of(def, level)` 与 `Of(def, next)` **按下标**比 `Value`;CV:754–770 `CardTraits.Of` 比 `Amount` 字符串。
- 新口径:按面逐格比本体数值。新解锁的特性 = `Slot == next`;下一级预告 = 大于 `next` 的最小槽位上的全部特性。

### 7.3 最大的 3 个风险

1. **纵向溢出,而且被误判成「一面三行」**:真实文案让一面在 16:9 下有 3–8 行正文,另有 22 张字的 Lv4 是分面的。滚动容器、等高两栏、按实际面宽算行高,这三样缺一样就会压扁头部或裁掉内容。CP:122–127 的注释写过这个坑。离线编译与单测都抓不到,只能两档实测截图。
