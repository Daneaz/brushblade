# 上状态动效统一 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 凡玩家可见的战斗状态在单位身上新增 / 增加时,Core 发 `StatusApplied` 事件,Presentation 统一播「chip 闪 + 状态名签」。

**Architecture:** Core 在 `ApplyStatus` 成功分支与四处旁路经一个 helper 发新事件(白名单过滤隐藏载体、排除已有专门事件的路径);
fingerprint / trace 过滤新 Kind 保住旧基线。Presentation 在 Juice 里新增一个 case,合并同批同单位同状态,复用 `FlashIcon` + `StatusLabel`,
并下线前后比对与手动 ChipCue。

**Tech Stack:** Unity 6000.5.2f1、C#(Core 纯 C#)、NUnit(dotnet 工装 tools/coretests)。

**Spec:** `docs/superpowers/specs/2026-10-18-上状态动效统一-design.md`;底稿 `docs/superpowers/specs/2026-10-18-上状态动效-审计.md`(文件位置与行号)。

## Global Constraints

- `BattleEventKind` / `StatusKind` 只在末尾追加。
- Core / Data 不引用 UnityEngine。
- 测试断言禁用 `Is.AnyOf`;集合包含写 `Assert.That(list.Contains(x), Is.True)`;不引用 Newtonsoft。
- 玩家可见文案走字符串表;本批预计不新增文案(名签用现有 `StatusText.Of`)。若新增,重跑 `python3 tools/fonts/subset_fonts.py`。
- worktree 里 prescompile 加 `-p:ProjectAsm=/Users/eugenewu/code/game/Brushblade/Library/ScriptAssemblies`。
- 改 Core 公开成员后 `tools/balance`、`tools/chestsim`、`tools/trace` 各 build 一次。
- trace 两档 sha 必须与改前一致(`cd tools/trace && dotnet run -c Release -- --out X` 与 `--seeds 0-15 --max-depth 30 --flat-scale` 两档;改前先在 main 上各跑一次记下)。
- 提交只提交自己改的文件;提交信息 conventional commits,末尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. 敌人回合内上状态(敌人给玩家上灼 / 封字;敌人互相加攻)——事件在敌人行动拍里发出,表现层要在那一拍播,不是攒到出字后。
2. 同一张字给全体敌人上同一状态(群体减速 / 破甲)——每个敌人各一条事件、各自播,不能只播第一个。
3. 刷新(增量 0,如再上一次减速)——要发、要播小一档,不能因 0 被吞,也不能播「+0」。
4. Boss 吃冻结转冰滞——发的是 IceStall 而非 Freeze;霜抗挡下冻结时不发。
5. 影子引擎 Estimate——不得把事件漏进本体 `LastEvents`;预估签数字不变。
