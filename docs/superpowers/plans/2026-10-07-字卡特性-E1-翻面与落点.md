# 字卡特性 Plan E1：手牌翻面、按面出手与落点 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 战斗里能把手牌翻到五行面并按朝上的面出手：点已选中的牌 = 翻面，拆合台有「攻击 / 五行面」两格翻面钮，拖出只点亮这一面能落的目标；五行面能落到自己与木灵（铠 / 润 / 固），生面落空位 = 召唤、落木灵 = 嫁接。

**Architecture:** 落点规则是游戏规则，放 Core（纯函数 `CardFaceRules.Landing`，可单测）；表现层只持有「每张手牌朝上的面」这一份交互状态（按卡位），出字时把面换算成 `attackMode` 传给现有 `Battle.Cast`。两面字从此不再进入「双向态」（拍板稿 FlipSpec：火的攻击面与燃都打敌人，落点分不出面）。面印是新组件 `FaceSeal`，先补进 `docs/design/component/` 再用。

**Tech Stack:** Unity 6000.5.2f1（uGUI，`Ui.*` 自绘）；Core 纯 C#；NUnit（`tools/coretests`）；`tools/prescompile` 离线编译。

**Spec:** `docs/superpowers/specs/2026-10-03-字卡五特性体系-design.md` §2.1（翻面）、§2.2（五行面落木灵）、§12。**拍板稿（唯一视觉依据）：** `docs/design/drafts/traits/`——`FlipSpec.dc.html`（手势、落点、动效）、`HandFlip.dc.html`（拆合台翻面钮、落点样式、提示文案）、`traits.css:82-91`（面印尺寸与配色）、`README.md`「已拍板」与「实现落点」。designer 2026-10-07 补充：铠 / 润 / 固落木灵的预估签按「只写结果」规则出（「格挡 +1」「本场改水」「本场嘲讽」），不另等稿。

**提前的原因**：D2-0 做的五行面落木灵、嫁接在 UI 上无法触发，用户无法验收（2026-10-07）；10 张火字的单体燃面多敌时打不出（D1 遗留）。

## 已定口径

- **F1 翻面状态**：表现层字段 `Dictionary<int, CardFace> _handFace`（键 = 字库卡位下标）。缺省 Attack（正面朝上）。出手成功后该卡位清除（回到正面）；回合结束不重置；字库重排（出字 / 合字 / 掉字）后按卡位失配的条目全部清除（宁可回正面，不翻错牌）。部件池的牌没有面：恒按「默认方向」出（现状逻辑），不显示面印。
- **F2 哪些牌能翻**：`CardFaceRules.HasTwoFaces(def)` = `def.AttackEffects.Count > 0 && def.Effects.Count > 0`。单面牌点第二下维持现状（= 出字），不显示翻面钮。
- **F3 面 → attackMode**：Attack → `true`；Feature → `false`。`BattleEngine.FaceOf(def, attackMode)` 已是同一判据。
- **F4 落点**（Core `CardFaceRules.Landing(def, face, cardLevel)` 返回 `[Flags] FaceLanding`）：
  - `Enemy`：这一面 `NeedsTarget(def, attackMode, cardLevel)` 为真，或这一面全体 / 散射伤害（落任一敌人即出手）。
  - `Self`：这一面 `NeedsAllyTarget(def, attackMode)`，或这一面不选敌且不召唤（护盾 / 治疗 / 增益落自己；与现状「直接出」等价，拖到玩家条出）。
  - `Summons`：这一面 `NeedsAllyTarget(def, attackMode)`（铠 / 润 / 固等落木灵）。
  - `EmptySlot`：这一面召唤（`SummonCountOf(def, attackMode) > 0` 的静态版）→ 空位 = 召唤。
  - `Graft`：这一面召唤且非攻击面（`HasSummonFace`）→ 活木灵 = 嫁接（`allySlot` = 该槽）。
  - 攻击面一律 `Enemy`（两面字的攻击面都打敌人）；燃面 `Enemy`。
- **F5 不再进入双向态**：两面字的点击出字、拖出都按朝上的面走单向；`OnCastPressed` / 拖拽 `dualDirection` / `EnterSummonDual` 三个入口对 `HasTwoFaces` 的字改走面路径。单面字保留原路径（不改行为）。
- **F6 嫁接落点的 Cast**：生面拖到活木灵 → `Battle.Cast(charId, -1, attackMode:false, libraryIndex, summonSlots:null, allySlot:slot)`，不进选位态、不弹顶替确认（Core 已保证召唤位满也能嫁接）。
- **F7 落点样式**（HandFlip 稿，pt × 2.093 = 逻辑单位）：可落 = 1.5pt（≈3）描环，色为朝上那面的字形色（攻击面 `ink`）+ 5% 墨底；悬停 = 2.5pt（≈5）+ 9% 墨底 + 墨底白字预估签（高 13pt≈27、圆角 6.5pt≈14、字 7.2pt≈15，位于格上沿 −9pt≈−19）；不可落 = 整格 alpha 0.42。空召唤位只在生面拖起时画：翠玉淡底 + 「召唤到这里」（7.5pt≈16，`wood-fg`）。**拖拽期间不许重绘字库行**（只就地改色，沿用 `ShowDragTargets` / `OnDragHover` 的做法）。
- **F8 面印**（traits.css）：一式实底白字；攻击面 `ink` 底白「攻」，五行面 `<el>-glyph` 底白面字（燃铠润固生）；尺寸档 xs 10pt / s 13pt / m 17pt / l 24pt。手牌用 xs（21 逻辑单位，字 7pt≈15，宋体 700，圆角 2pt≈4），**占拼音位**（锚 0.06–0.30），水平居中；朝上为五行面时牌面内层底色换 `<el>-soft`。
- **F9 翻面动效**：0.18s，横向 scaleX 压到 0.04 再展开，中点换底色与面印；不耗 AP、不进行动记录；动画中再次点击直接跳到终态。
