# 木灵属性、嫁接永久化与火系五行面改版（spec C）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 落地 spec C 的六件事：
1. 剑 Lv8 反击横扫（`counterShape Row`）；
2. 无效技能清理（湮 / 柘 / 桂 / 㵘 / 剁 / 铡 / 剑意等修饰器 / 鍂 / `perHit` 追加 / 14 条 Lv4 改名）；
3. 嫁接永久、回归木属性（删掉 `BaseElement` / `BasePassive`）；
4. Lv5 五行面「换属性」（新 Kind `Attune`），删掉「水字落木灵改水」；
5. 火系五行面改为「燃意」（新 Kind `Kindle` + 新状态 `StatusKind.Kindle`，拖到我方），Lv4–Lv8 适配；
6. 崩 / 㙓 / 溃 / 㵘 攻击面以「厚积薄发 / 涌泉相报」为核心（按释放层数的效果族）。

**Architecture：** 先做一个「地基」任务 F0：把全部新枚举、新字段、AmpTerms 的第 5 项、加载器透传和枚举穷举测试一次加齐，只加名、不加行为（对现有数据逐位恒等）。之后 Core 机制按写冲突拆开：`BattleEngine.Metal.cs`（横扫）、`TraitRules.cs`（perHit 追加）、卡面 Core（FaceStats / Glossary / CardSheet）、管线、七份数据文档可以并行；改 `BattleEngine.cs` 的三个任务（嫁接 + Attune → 燃意 → 释放层数族）串行。Presentation 与字符串表集中在一个任务里。数据只改源头（详表 / 特性表 / 池表），由一个任务统一 `export_chars`。最后按测试文件分组改锁旧口径的测试，全量验证，更新 trace 基线，后台跑 F1 快档。

**Tech Stack：** C# 9 / .NET 8（Unity 自带 dotnet SDK）+ NUnit（coretests）；Python 3 管线 + pytest；Unity 6000.5.2f1（只做离线编译）。

**Spec：** `docs/superpowers/specs/2026-10-15-木灵属性与火系五行面改版-design.md`（下称 spec C）。上位文档：spec A `2026-10-15-字卡两面对齐与数值归一-design.md`、spec B `2026-10-15-字卡详情说明区改版-design.md`、v7 `2026-10-03-字卡五特性体系-design.md`；冲突时以 spec C 为准。

## Review Focus

1. **燃意加灼的边界。** 只有玩家 `DamageSingle` 每段命中与木灵出手命中加灼；灼 tick、格挡反击、非 DamageSingle 的出字效果都不加。测试：C3 `BurnTick_DoesNotTrigger_Kindle`、`BlockCounter_DoesNotTrigger_Kindle`、`NonDamageEffect_DoesNotTrigger_Kindle`。
2. **嫁接与换属性跨场。** 嫁接后战后仍保留新本命且属性回木；Attune 跨场保留；先 Attune 后嫁接 → 木；水字润面落木灵不再改水。测试：C2 `Run_Carry_KeepsGraftedPassive_AndWood`、`Attune_PersistsAcrossBattles`、`Graft_After_Attune_ReturnsToWood`、`Wet_OnSummon_NoLongerChangesElement`。
3. **0 层释放。** 释放前没有泉 / 厚时，破甲 / 冻结 / 减速 / 回澜 / 地动 / ×2 全不触发、不发事件。测试：C4 `ZeroStacks_NothingReadsSpent_Fires`。
4. **火系燃面 Lv1–Lv8 每条特性都不需要敌方主目标**（含 Q2 补的两条）。测试：G1 `FireFeatureFace_NoTraitNeedsEnemyTarget_UpToLv8`。
5. **反击横扫不重复。** 攻击者只吃一次；横扫与贯穿同时有时，同排与同列的敌人各吃一次 70%，跨排 Boss 不双吃。测试：C1 `RowAndColumn_EachEnemyHitOnce`。

        /// <summary>燃意合并(spec C §5.1):同一单位只留一条 —— % 取大、回合取长,火力取大。由 ApplyStatus 调用。</summary>
        private static void MergeKindle(StatusBag bag, StatusEffect effect)
        {
            for (int i = bag.All.Count - 1; i >= 0; i--)
            {
                var old = bag.All[i];
                if (old.Kind != StatusKind.Kindle) continue;
                effect.Magnitude = Math.Max(effect.Magnitude, old.Magnitude);
                effect.TurnsLeft = Math.Max(effect.TurnsLeft, old.TurnsLeft);
                effect.Potency = Math.Max(effect.Potency, old.Potency);
                bag.RemoveEntry(old);
            }
        }

        private void ApplyKindle(StatusBag bag, int percent, int turns, int potency, string sourceId, UnitRef target) =>
            ApplyStatus(bag, new StatusEffect
            {
                Kind = StatusKind.Kindle, Polarity = StatusPolarity.Buff,
                Magnitude = percent, TurnsLeft = Math.Max(1, turns), Potency = potency, SourceId = sourceId,
            }, target, UnitRef.Player);

        /// <summary>燃意命中加灼(spec C §5.1,Q10):attacker 袋里挂着燃意且目标仍活着 → +KindleBurnPerHit 层,火力取燃意记下的。
        /// 只由 DamageSingle 每段命中与木灵出手调用;不进 _cast.BurnedTargets。没挂燃意时一次判断即返回(恒等)。</summary>
        private void KindleOnHit(StatusBag attacker, int enemyIndex)
        {
            var kindle = attacker.Find(StatusKind.Kindle);
            if (kindle == null || enemyIndex < 0 || enemyIndex >= _enemies.Count || !_enemies[enemyIndex].Alive) return;
            int gain = ApplyBurn(enemyIndex, KindleBurnPerHit, UnitRef.Player, Math.Max(100, kindle.Potency));
            if (gain > 0) _events.Add(new BattleEvent(BattleEventKind.Burn, enemyIndex, gain));
        }

        /// <summary>「释放前先 +N 层」(spec C §6,Q8):本面有释放泉 / 厚时,把排在第一条释放之后的同资源直接加层
        /// (AddWellspring / AddHeft,非 fill、非开局登记)稳定地挪到它前面。没有释放的面原样返回 —— 恒等。</summary>
        private static void HoistPreSpend(List<EffectDef> effects)
        {
            int spend = effects.FindIndex(e => e.Kind == EffectKind.SpendHeft || e.Kind == EffectKind.SpendWellspring);
            if (spend < 0) return;
            var add = effects[spend].Kind == EffectKind.SpendHeft ? EffectKind.AddHeft : EffectKind.AddWellspring;
            var moved = new List<EffectDef>();
            for (int i = spend + 1; i < effects.Count; i++)
                if (effects[i].Kind == add && !effects[i].Fill && effects[i].OpeningBattles == 0) moved.Add(effects[i]);
            if (moved.Count == 0) return;
            foreach (var m in moved) effects.Remove(m);
            effects.InsertRange(spend, moved);
        }
