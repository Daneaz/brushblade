# 奇遇重平衡与扩充 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 奇遇按 4 级权重抽取、每段保底、两种新代价(下一战首回合 AP −1 / 舍 1 字),奇遇池扩到 20 个并重写冷门选项。

**Architecture:** Core 的 `EventDef` / `EventOption` 加字段,`RunEngine.ProceedAfterBattle` 改加权抽取 + 保底,`ChooseEventOption` 接两种新代价;药铺的 AP 惩罚复用 `_carriedStatuses` 跨战斗携带一枚 `StatusKind.Seal`;舍字复用 `replaceLibraryIndex` 参数与表现层 `DrawReplaceSheet`。数值全部落在 `enemies.json`。

**Tech Stack:** Unity 6000.5.2f1 / C#(Core、Data 纯 C#),NUnit,Python 设计脚本。

**Spec:** `docs/superpowers/specs/2026-10-21-奇遇重平衡与扩充-design.md`

## Review Focus

1. **保底遇上「本层没有可出现的奇遇」**:可出现集合为空时不强制、也不掷骰,直接进选字,且不能抛异常 —— Task 1 测 `Pity_NoEligibleEvent_GoesToReward`。
2. **从段中断点续爬**:快照里「本段已出过奇遇」必须往返,否则续爬后保底会重复触发或失效 —— Task 1 测 `Pity_SurvivesSnapshotRoundTrip`。
3. **药铺 Seal 跨「奇遇 → 选字 → 下一战」与快照**:挂在 `_carriedStatuses` 上,下一战首回合 AP = 2、第二回合 = 3;段内最后一个非 Boss 层选了药铺,Boss 战首回合照样扣 —— Task 2 测 `NextBattleSeal_*`。
4. **舍字时字库只剩 1 张**:选项锁定(`IsEventOptionLocked` 返回 true,表现层置灰),不能把字库舍空 —— Task 2 测 `LibraryCost_LastChar_Locked`。
5. **手写的旧奇遇(Tier = 0)**:现有大量 Core 测试不写 Tier,加权后必须与原等概率逐位一致(权重 1、`_random.Next(count)` 同一次调用) —— Task 1 测 `Tier0_PickMatchesUniform`。
