### 3.2 必须走的同源路径(防「预估 ≠ 实际」)

1. 效果表:`ApplyEffects` 实际用的是「限次特性已用尽则整条不进 Fold」的版本(`BE:3311-3315`),**而 `CastEffectsNow` / `CastEffectsOf` 不扣已用**(`BE.Traits:416-420`、`BE:1826-1827`)。直接拿 `CastEffectsNow` 算杜门不出会把已用的 DamageCut 算进去 —— **预估必须走 ApplyEffects 的那份筛法**。
2. 印记:`CastCore` 的 `FindPartMark` + `FoldExtra`(`BE:1657-1659`、`BE:3319`);出手后 `ConsumePartMark`(`BE:1705`)。
3. 形状展开:`Targeting.ExpandTargets(..., volleyLeadsWithPrimary: true)`(`BE:3392-3393`,与 `BV:4064` 同)。
4. 伤害收口:`DamageEnemy BE:5609` 是对敌伤害唯一收口；任何「纯函数重抄」都要同时复刻 §3.1 表里 15 层以上的逻辑 + 效果之间的**顺序依赖**(同面先挂破甲 / 标记、后打伤害，后者吃到前者)+ PerHit 附带(`BE:3462-3467`)+ 推迟名单类效果(`BE:3321-3337`)。
5. 生克显示:必须用 `ApparentElement`(`Core/EnemyDef.cs:516`;`BV:439-442` 已有注释「伪装怪 / 生僻字没现形前是 null」),否则签上的 ×1.5 会**泄露**伪装 / 生僻字的真身。

### 3.3 推荐做法:克隆试算(而不是纯函数)

**结论:用「Capture → Restore 出一个影子引擎 → 在影子上真跑一次 CastCore → 读影子的事件」。** 理由:

- 出字效果有 ~100 种 `EffectKind`(`BE:3487-4399` 的 case 列表),伤害又依赖目标状态、出字前快照、效果顺序;纯函数必然与 `ApplyEffects` 分叉(这正是 `AttackShapeOf` 注释 `BE:1830-1840` 记录过的教训)。`MineHpLoss` 能手抄是因为它只有一种伤害源。
- `Capture / Restore` 已覆盖结算所需的全部可变状态(RNG 三流 `:1275-1277`、`TraitUsesThisBattle :1279`、`PartMarks :1280-1283`、forge、护盾桶、余数、敌我状态);`_cast` 是每次 ApplyEffects 新建的(`BE:3222-3228`)。
- 生产环境**没有 hook 监听器**(`AddHookListener BE:5020` 只有测试调用),`Raise` 在影子上空转。
- **trace 恒等硬线**:原引擎一个字节都不动(不摇它的 RNG、不写它的字段)→ `tools/trace` 记录的 `RandomState`(`tools/trace/Program.cs:236/248/255`)不受影响;trace / balance 机器人不调预估接口。

影子需要处理的三件事:

| 问题 | 位置 | 处理 |
|---|---|---|
| `BattleConfig.Tally` 是共享引用,Cast 会写 `Plays`/`MaxHit` | `BE:273`、`BE:1734-1738`、`BE:5695` | 影子用 config 浅拷贝且 `Tally = null`(仿 `WithPlayerMaxHp BE:277-282` 加一个 `internal BattleConfig ForEstimate()`) |
| `Restore` 要 `enemyDefs` | `BE:1305-1306` | 从 `_enemies[i].Def` 现建字典(Core 内部自足，不依赖 RunEngine) |
| AP 不够也要出签(起拖照样点亮，`BV:3789-3790`) | `CastCore` 的 AP 守卫 `BE:1651` | 影子 `Ap = Math.Max(Ap, def.ApCost)` |
| 暴击不能泄露 | 影子 RNG 与本体同态，真摇会**预知这一发暴不暴** | 影子置 `_estimate = true`,`RollCrit` 在 estimate 下直接 `return force`(不摇号、不兑现锋芒);本体 `_estimate` 恒 false → 逐字节恒等 |
| 反应链(OnKill / OnCrit / 溢出溅射等)是否算进签 | `DrainReactions BE.Traits:445-480`,在 `CastCore BE:1731` | 推荐 estimate 下 `DrainReactions` 直接清队返回(签只说「这一下」);见 §4 Q5 |
| `Capture` 断言反应队列为空 | `BE:1264` | 玩家回合拖拽时成立(安全点已排空) |

```csharp
    var shadow = Restore(Capture(), _graph, _config.ForEstimate(), _cardLevels, defs);

    shadow.Ap = Math.Max(shadow.Ap, def.ApCost);
    var err = shadow.CastCore(charId, targetIndex, replaceSummon: true, attackMode, libraryIndex, null, allySlot);
    // 读 shadow._events(Damage / Burn / Shield / Heal / MoraleGain)、shadow._cast 的 Nominal、效果表、已用特性
}
```

要点:

- **新增 `_estimate` 只在两处读**:`RollCrit`(不摇号)、`DrainReactions`(清队返回)。本体恒 false,两处都是「false 时原样」→ 恒等;`tools/balance / chestsim / trace` 只做追加，照 CLAUDE.md 逐个 build 确认。
- `ShieldNominal / HealNominal` 需要从影子 `_cast` 读:CastCore 结束时 `_cast` 已在 ApplyEffects 的 finally 里恢复外层(`BE:3222` 起的进出门逻辑)→ 需在 estimate 模式下把最后一次 `_cast` 留一份，或直接用事件量(见 Q4)。
- 「效果表」那一项不要用 `CastEffectsNow`(不扣已用);抽一个 `internal EffectsForCast(def, attackMode, partExtra)`,内容即 `BE:3311-3319` 那几行，并让 `ApplyEffects` 改调它(**同一函数，杜绝分叉**;逐字节不变)。
- `SpentTraits`:遍历 `TraitRules.Unlocked`(或 def.Traits 过等级)中 `AppliesTo(face) && MaxPerBattle > 0` 的，交给 `TraitSpentThisBattle`;**不能只用 `BattleLimited`**(它只收 Trigger == Cast,漏折桂)。
- 性能:影子 = 一次 Capture + Restore(列表拷贝，敌 ≤ 8、召唤 ≤ 8)。按「起拖时为每个可落格各算一次」(≤ 8 敌 + 玩家 + ≤ 8 木灵)一次拖拽 ≤ 17 次;全体面一次试算就能读出全部目标。

- **R1 全体悬停会让所有签同时亮**:`OnFaceDragHover` 在全体面时对所有敌人 `SetFaceMarkHover(mark, true)`(`BV:3892-3894`),而 `SetFaceMarkHover` 把 `Label.SetActive(hover)` 绑在同一个 hover 上(`:3904`)。今天敌人签为 null 所以看不出;一接签，全体面就会一排签全亮，违反「只挂悬停那只」。要把「描环加深」与「签显隐」拆成两个参数。

  - 因此**补上的效果是防御性的、和出字路径对称**，现有数据下不会改变行为。
- try / finally：整个 `P/` 目录里 `BattleView.cs` 与 `Juice*.cs` **没有一处 try / catch / finally**（grep 结果为空）。两条路径都是「`BeginAnim` 之后，任何同步异常或协程异常都会让 `_animsInFlight` 永不归零」，表现为输入永久锁死。拆合路径还会多留下两个残留：
  - `_forgeCuePlaying` 卡在 true，之后每次 Refresh 都在锁里照画操作区；
  - `_juice.ForgeChar` 不清，之后出字路径里的 `Summon` 事件会被误判成拆合，执行 `PopTile`（`P/Juice.cs:741`）。

### c3. Core 改动
无。trace 零影响。

### c4. 实现草案
1. **光环**：`OnDismantle` / `OnCompose` 在 `Battle.Dismantle / Compose` 之前取 `var aurasBefore = AuraKeys();`；成功后在 `BeginForgeCue` 之后、`CancelSelection` 之前调用 `CueNewAuras(aurasBefore)`，与 `ExecuteCast` 同序。
   - 注意：`BeginForgeCue` 在没有事件时返回 null、不上锁，这时 `OnAnimDone` 不会跑，`FlushWoodCues` 也不会被调用 → `_woodCues` 会滞留到下一次。
   - 对策：`forgeEvents == null` 时，在 `CancelSelection()` 之后直接调一次 `FlushWoodCues()`。现有数据下拆合里只要有光环，就一定先有 `GlyphTrait` 事件，此分支不可达，属于防御。
2. **同步段 try / catch，两条路径统一**：抽一个
   ```text
   RunLockedAction(Action redraw, Action startPlay, Action releaseOnFail)
   ```
   - `BeginAnim()` 之后执行 `try { redraw(); startPlay(); } catch (Exception ex) { Debug.LogException(ex); releaseOnFail(); }`；
   - `releaseOnFail`：拆合路径为 `_forgeCuePlaying = false; _juice.ForgeChar = null; _juice.ForgeResult = null; OnAnimDone(deaths)`；出字路径为 `OnAnimDone(deaths)`。
   - **用 catch 加日志，不用 finally**：成功时 `OnAnimDone` 必须等动画播完才调，finally 会提前解锁。E3 原话写的是 try / finally，按语义实现时需要用 catch 或一个 `started` 标志。
3. **协程层兜底**（推荐同批做，否则只修了一半）：`Juice.Play` 里的 `PlayRoutine` 一旦被异常打断，`onComplete` 永远不会被调用。
   - Unity 里嵌套 `yield return IEnumerator` 抛异常时，外层协程会被直接终止，外层的 finally 不保证执行。
   - 做法：在 `Juice` 加一个 `SafeRun(IEnumerator root, Action onDone)` 驱动器，用栈把嵌套的 IEnumerator 展平，每次 `MoveNext` 包一层 try / catch，异常时记日志并保证调用 `onDone`。
   - `Play` / `FlyGlyph` / `CastAttack` 的回调链都走它。
   - `AdvanceRoutine` 里的 `while (!done)`（:7004-7006）也因此一定能等到 `done`。

### c5. 风险与待裁定

| Q | 问题 | 推荐 |
| --- | --- | --- |
| Q-c1 | 「try / finally」要做到哪一层 | 两层都做：同步段（这次的明确要求）加协程驱动器（记忆里「攻击后卡死」的真正来源）。只做同步段的话，Juice 里一个假 null 就能锁死整场 |
| Q-c2 | 异常后画面状态 | 只保证解锁和复位；画面靠 `OnAnimDone → Refresh` 拉回终态。不做「补播」 |
| Q-c3 | `SafeRun` 会不会改变节拍 | 每帧最多推进一层；`WaitForSeconds` 这类 YieldInstruction 原样交还 Unity。要确认 `Beat()` 返回的是 IEnumerator 还是 YieldInstruction，两种都要支持 |

### 0. 先说结论

1. **稿要的东西不多**:术语加粗 + `ink-soft`、数字加粗 + 正文色;点整行(或单术语的数值格)开一个 248pt 定宽气泡,列出这一行全部术语;同一时刻只开一个,点任意处关;两种详情版本都要能点。没有新组件可复用,气泡要新写(约 150 行 Presentation)。

3. **推荐做法**:在拼好的纯文本上扫描标记,不改拼句结构。词表 = 术语名 + 别名(字符串表),最长匹配优先,外加少量排除上下文。函数放 **Data**(纯 C#,coretests 可 TDD);取词条文案的 `Strings.T` 字面量 switch 放 **Presentation**(`StringsTableTests` 只扫 Presentation)。同时改 4–5 条模板措辞,让缺席的术语出现在句子里。

### 3.2 推荐:在纯文本上扫描(不改拼句的结构)

**为什么不在 switch 里结构化地产出术语**:那样要给 90 多个 `EffectKind` 分支,外加条件、选择器、增益、范围、被动字段,再写一份「→ 术语」的平行映射,和文案 switch 必然各自漂移(仓库里这类「两份清单」的坑记过多次)。扫描的口径是「玩家看到哪个词,就标哪个词」,天然和文案一致。漏标的情况可以用全量对账测试抓出来(§3.5)。

**为什么不在模板里写标记(稿的 `[灼]{3}` 写法)**:要改 200 多条 `char.effect.*` 模板,而这些模板还给卡面 `EffectsText`、开局卷轴、状态详情共用,所有出口都得剥标记。

**分层**:

| 层 | 放什么 | 理由 |
|---|---|---|
| Core | `enum GlossaryTerm`(42 个,按 spec §3 顺序;ordinal 不进存档,可以随便排);`GlossaryRules.Group(term)`(关键词 / 范围 / 存续);`GlossaryRules.TermOf(FaceStatKind) → GlossaryTerm?`(R6 的格子映射) | 纯枚举和映射,可以 TDD |
| Data | `TermMarkup`(纯函数):`Scan(string plain, IReadOnlyList<TermSurface> lexicon) → TermScan { Spans(start, len, term), Terms(首次出现顺序、去重) }`;`Numbers(plain) → spans`;`Rich(plain, scan, termOpen, termClose, numOpen, numClose) → string` | 不碰 `UnityEngine`,coretests 毫秒级跑;颜色由调用方用字符串传入(Data 拿不到 Theme) |
| Presentation | `GlossaryText`(仿 `StatusText` 的写法):`Name(term)` / `Desc(term)` / `Lexicon()` 三个 switch,每个 key 都是**字面量** `Strings.T("term.burn.desc")`;`GlossaryBubble`(§4);`CardSheetParts` 接线 | `StringsTableTests` 只扫 `Presentation/**/*.cs`(`Tests/StringsTableTests.cs:80` 前后),放在 Data 里的调用会被当成孤儿 key |

**扫描规则**(都要有单测):
1. 词表 = 每条术语的显示名 + 别名(`灼烧→灼`、`持续治疗→润泽`、`召唤物→木灵`、`苗→幼苗`、`盾反→荆棘`、`连发→散射`(如果不改模板)),按长度降序,从左到右、不重叠地最长匹配。`留存护盾` 必须先于 `护盾`,`灼烧` 先于 `灼`。
2. 排除上下文(词表项可以带「前一个字 / 后一个字不能是 X」):`减伤` 前面是「(」时不标(护甲括注);`全体` 后面紧跟「敌人)」时不标(选择器后缀),前面是「我方」或「改为」+ 后面「(含」时不标(治疗改形)—— 具体怎么排由 Q5 决定。
3. 一行的 `Terms` 按首次出现排序;分面两小句的行(`RowModel.Lines.Count == 2`)取两句合并去重。
4. 数字 span:`[+−\-×]?\d+(\.\d+)?%?`,不和术语 span 重叠(比如「灼烧+2」→ 灼烧 是术语、`+2` 是数字)。
5. 输出富文本时**用纯文本测量**:`LineHeight` / `WrappedTextHeight` / `EstimateWidth` / `Truncate` 一律吃 plain,`Text.text` 才赋 rich。否则 `<color=#3D4E69>` 这 15 个字符会被当成正文去估行数(`Ui.cs:478-490` 是按 `segment.Length` 数的)。`CompactRow` 先截断 plain,再对截断后的串重新扫描、上色(截半的词不标)。粗体会让 ASCII 数字略宽,`EstimateWidth` 的 0.55 系数可以留 5% 余量,或者接受。

**接线点**:
- `RowModel` 加 `IReadOnlyList<GlossaryTerm> Terms`(整行合并后的结果),`Lines` 保持纯文本不变(`SharedRow :272` 的「两句文本相同就合成一句」靠的是纯文本比较,不能先上色)。
- `BodyLine(…, string text, …)` 内部调用 `GlossaryText.Rich(text, color)`;off / spent 态把术语色换成 `dimColor`(R3),只保留 `<b>`。升级预览 `CollectionView.cs:982` 走同一个 `BodyLine`,自动得到样式(R20)。
- `TraitRow :525`:`row.Terms.Count > 0` 时给 card 加 `Button`(`transition = None`)+ 回调 `onTermsTap(rowRect, title, terms)`;`Count == 0` 不挂(R7)。回调由 `CharPreview.BuildSheet` 往下传(`FacePanel` / `SharedStrip` / `CompactRow` 加一个可空参数),它手里有 `overlay`(`CharPreview.cs:102`)。

- 脚提示:`CharPreview.cs:300` 铺满版换成新 key `charsheet.foot.glossary`;`charsheet.foot.outside` 在 `:128`(部件那一支)还在用,不会变成孤儿。

**没有可复用件**:Presentation 里没有 tooltip / popover。`Ui.Sheet`(`Ui.cs:217`)是整屏遮罩 + 居中卡片,不适合挂在行旁边;`ShopView.ShowToast`(:882)是会自动消失的 toast;`Juice*.Popup` 是飘字。要新写 `UI/GlossaryBubble.cs`(静态类,约 150 行),积木用现成的 `Ui.OutlinedPanel`、`Ui.ThemedLabel`、`Ui.VStack`、`Ui.WrappedTextHeight`、`Theme.RoundedRing`(选中描边)。

```text
                    IReadOnlyList<GlossaryTerm> terms, Action onClosed)
```

**父节点必须是 overlay,不能是行**:两面区和右栏都在 `Ui.ScrollList`(`CharPreview.cs:285,289`,`Ui.cs:1161`)里,有 Mask,挂在行下面会被裁掉。挂在 overlay 上后,滚动时气泡不会跟着走;但 catcher 盖住了整屏,开着气泡时滚不动,一点就关,所以不会出现错位。
