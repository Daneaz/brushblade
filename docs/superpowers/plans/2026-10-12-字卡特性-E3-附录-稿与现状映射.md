### 1.3 「剩余次数」= TurnsLeft 的推导(每回合效果 / 护盾回流)

`BeginPlayerTurn`:清盾 → `CarryShieldOnTurnClear`(浮屠,:2842)→ `ApplyMoraleShield` → `EnqueueTurnPulses`(:2846)→ `TurnStarted` → `DrainReactions` → … → `TickPlayerStatuses`(:2857)。
回合 T 内挂上 `TurnsLeft = N`;T+1 开头先触发、再 tick 成 N−1;……共触发 N 次。所以任何时刻「还会再发生几次」恰好等于 `TurnsLeft`,chip 直接读,不需要 Core 新读口。(边角:回合初反应里挂上的,当拍即被 tick,显示与实际次数仍一致。)

## 3. 拦截反馈与 trace 恒等

- **trace 是否把事件写进 sha:是。** `tools/trace/TraceRecorder.Event`(:73)每条 `LastEvents` 写一行 `E … {Kind} {TargetIndex} {SecondIndex} {Crit} {Amount} {Absorbed}`,输出文件整体取 sha(Program.cs:166)。**不写 `Source`**。Trace 只在 `Cast` / `EndTurn` 之后读 `LastEvents`(Program.cs:340-347 的注释),不在 `Compose` 后读。
- **可达性:新事件在 trace 两档里全部不可达。** trace 机器人钉死 `AllLevelOne`(Program.cs:75),而所有涉及的特性都在 Lv4 以上(调研时从 `chars.json` 逐条核对):杜绝 Lv4、洗尽铅华 Lv5、浇熄 Lv6、濯身 / 大雨滂沱 / 栉风沐雨 / 堡垒 / 浮屠 Lv8、杜塞 / 碎玉 / 重土 Lv5、杜门不出 Lv8、八条字形特性全 Lv4;本体效果与 Lv1 特性里没有这些 Kind。敌人也不会施加 BuffBlock / DebuffWard。
- **因此方案**:新事件一律「只在新状态存在时才发」(拦截段本来就在 `bag.Has(...)` 之内;GlyphTrait 在 `TryUseTrait` 通过之后),Source 标签不进 trace。逐项风险点:
  1. `ApplyStatus` 拦截段(:4893-4900):事件只能写在 `bag.Has(BuffBlock)` / `WardOff` 返回 true 的分支里,不得在判断前做任何额外读写。
  2. `CastBossSkill` 挪 `TakeSkillCut` 到事件前:`TakeSkillCut` 不发事件,顺序互换不改事件流。
  3. `Dismantle`/`Compose` 进门清 `_events`:trace 不在拆合后读事件,下一次 `Cast`/`EndTurn` 本来就清,恒等。
  4. `CastCore` 改调 `CastEffectsNow`:纯重构,TDD 断「无印记时 = 原 `NeedsTarget`」。
  5. `Graft.Amount`:不可达。
- 每个 Core 任务跑两档 trace,对齐 `7235e89f…` / `883954a3…`(E2 记录,docs/superpowers/plans/2026-10-11-字卡特性-E2-字卡详情与升级预览.md:221)。

**删除线的实现风险**:`Juice.Popup`(Juice.cs:2155)用的是旧 uGUI `Text`,富文本不支持 `<s>`。删除线要另画一条 `Image` 横线(宽 = `label.preferredWidth`),跟着 `FloatAndFade` 一起淡出;60% 透明度直接乘到颜色 alpha 上。建议在 Juice 里加 `PopupStruck(text, color, anchor)`,不改 `Popup` 签名。
