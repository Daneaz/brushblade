# 升级宝箱主动领取 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 每级宝箱从自动发放改为在角色页「等级奖励」长轨道上逐级主动领取。

**Architecture:** Core 的 `LevelRewardRules` 换成「已领集合 + 领取 / 查询 / 轨道范围」纯函数,删除自动发放;Presentation 的 `CharacterView` 把里程碑 10 格窗口改为每级一格的独立横滚轨道,`LevelUpPopup` / `MapView` 跟着改读新规则。

**Tech Stack:** Unity 6000.5.2f1 C#,Core 纯 C#(无 UnityEngine),NUnit(dotnet 工装 `tools/coretests`)。

**Spec:** `docs/superpowers/specs/2026-10-19-升级宝箱主动领取-design.md`;拍板稿 `docs/design/drafts/character-chest-claim/README.md`(尺寸 / 颜色 / 文案的唯一出处)。

## Global Constraints

- Core 禁止引用 UnityEngine;测试断言禁用 `Is.AnyOf`、`Does.Not.Contain(非 string)`,集合包含用 `Assert.That(list.Contains(x), Is.True)`。
- 测试不得引用 Newtonsoft;序列化测试走 `Data.SaveSerializer`。
- 玩家可见文案只走 `Brushblade/Assets/StreamingAssets/config/strings.zh-CN.json`;改完重跑 `python3 tools/fonts/subset_fonts.py`。
- 领取只占空箱位(`ChestRules.SlotLimit = 4`),绝不写 `meta.PendingChests`。
- Lv.1 无宝箱;档位只由 `TierForLevel` 决定。
- 存档不写迁移:删字段即可。
- 只提交你改的文件。

## Review Focus

- 箱位满时点领取:必须返回 false 且 `ClaimedLevelChests`、`Chests`、`PendingChests` 全不变 —— Task 1 测试 `TryClaimChest_SlotsFull_ChangesNothing`。
- 重复领取同一级(连点 / 重建前再点):第二次 false,箱位只多一只 —— `TryClaimChest_Twice_SecondFails`。
- 未达等级 / Lv.1 / Lv.0 领取:false —— `TryClaimChest_NotReachedOrNoChest_Fails`。
- 已领集合里混入高于当前等级的值(手改存档):`PendingChestCount` 不得为负、不得少算 —— `PendingChestCount_IgnoresClaimsAboveLevel`。
- `FocusLevel` 在里程碑可领但宝箱已领、或宝箱可领但里程碑已领时都要停在那一格 —— `FocusLevel_EitherRewardPending`。
