## 0. 结论速览

- 土系专属 **35 条**（不是 33：土有 11 字，白 1、**绿 2 字**、**蓝 3 字**），与 §7 配额一致：白 1 + 绿 1×2 + 蓝 2×3 + 紫 4 + 金 5×2 + 橙 6 + 红 6 = 1+2+6+4+10+6+6。Lv4 两面在一面空转按 V4 拆行后，数据表新增 **37 行**。
- **A 直接 17 条**：据守反击、落石、杜绝、闭门、堵截、叠土、圭角、三土、移山、叠嶂、对峙、深厚、山压、厚土、镇塔、地动、重土（重土用水的 W7 `TurnPulse`，零新代码；镇塔 / 地动的「叠加」依赖 E27，见 §0-3）。
- **B 小扩展 8 条**：碉楼、载物、垒砌、厚德载物、塔基、山岳、三山、圭臬。
- **C 新机制 10 条**：铜墙铁壁、堡垒、地裂、碎玉、粉身碎骨、塔倾、浮屠、杜塞、杜门不出、土生金。17 + 8 + 10 = 35。
- 新机制：共用小扩展 **E27–E36（10 项）** + 土系新机制 **G1–G9（9 项）**。核心三团：「护盾的读 / 扣 / 转」（G1 扣盾、G8 盾转战意、G9 回合初留盾、E28 盾分给木灵、E29 留存、E36 按盾计击数）、「我方受击挂点」（G2 单次受伤上限、G3 受击得盾、G4 盾碎反伤——都落在 `DamagePlayerDirect`）、「敌人 / 回合侧」（G5 溢出平分、G6 Boss 大招减半、G7 AP 代价 + E35 每场 1 次）。
- **水预留件的实际可用度**：W4 `wardCount`（杜绝）、E14（杜塞 / 冷却同款）、W7 `TurnPulse`（重土，`Shield` 已在载荷白名单）**真的可直接用**；W5「预留护盾载荷」与 W6「预留伤害载荷」**只是注释**——`HurtHeal` 的 Magnitude 是百分比、每回合 1 次，`ShieldFrost.OnHit` 是拍尾兑现的定值反应、算不了「被打破量」也进不了同步的 60% 反伤预算。所以堡垒、碎玉各要一个新 StatusKind（G3 / G4），只复用挂点位置。
- **trace**：土字在卡池里（`MixedCards` 含 塔 / 堡 / 垒 / 崩，「基准杂食」起手含 塔 / 堡，全 1 级），但**实测 `tools/trace/out/x.txt`（sha `7235e89f…`）杂食画像 Shield 事件 0 条、玩家护盾恒 0**——trace 机器人选面后从不出土的固面（D1 d12 起如此）。所以 Shield 分支、留存桶、护盾吸收、反震等**土特有路径不受 trace 守护**，要靠「无新状态时逐位恒等」的单元对照测试（同金）。trace 真正守的是共享路径：`DamagePlayerDirect`（314 次敌人挥击）/ `DamageSummon`、`BeginPlayerTurn`（每回合）、`DamageEnemy` 击杀分支（619 次击杀）、`CastBossSkill`（42 次）、`StartTurn`、`CastEffectsOf`（每次出字）、`RunEngine` 战后携带——G2 / G3 / G4 / G5 / G6 / G7 / G9、E31 / E34 / E35 / E36 都改在这些路径上，**trace 两档 sha（`7235e89f…` / `883954a3…`）仍是每个任务的硬验收**，所有新挂点缺省一次判断即短路、不摇号。
- **最大风险**：① **圭臬 × 战后携带（§0-2）**：`RunEngine` 把玩家身上 `DefenseBuff && TurnsLeft < 0` 的条目带进下一场——圭臬若直接写 `TurnsLeft = -1`，本场护甲会变成整段永久护甲，违反 §5.1；② `DamagePlayerDirect` 一个函数里要再插三个挂点（G2 / G3 / G4），与既有的镜 → 格挡 → 反震 → 冰晶 → 栉风沐雨顺序交错，且 60% 减伤 / 60% 反伤两份预算都在这里算；③ E27 把 `shieldStrike` / `armorStrike` 改为同面相加后，㙓 攻面（山压 50 + 地动 30，全体每人都是主目标）每个敌人吃 +80% 当前护盾，护盾上限 = 最大生命，强度要 Plan F 盯。

**调研中发现的现存问题**

1. **「本回合减伤」在战斗里完全不可见。** `BattleView` 玩家状态栏没有 `DamageCut` 的 chip（`traits/StatusChips.dc.html` 补三枚「减伤 / 反击加倍 / 保命」仍是 `待审`，2026-10-04）。已上线的 碎·坚壁（池 Lv8）、铡·铡关（DamageCut 50）现在就看不到；本 plan 的杜门不出（−60%）、铜墙铁壁（G2）会继续看不到。**不需要新稿**，需要用户拍板那份待审稿（减伤 chip 图标 `bulwark`），见 Q20。
2. **玩家「本场护甲」会被带到下一场。** `RunEngine.AdvanceAfterBattle` 的 `_carriedStatuses` 白名单是 `(DefenseBuff | Heft | Wellspring) && TurnsLeft < 0`。2026-09-08「所有 buff 带回合数」后玩家身上已没有 −1 的 DefenseBuff（`SummonDefense` 只挂木灵），这一项是死的；圭臬（「本字的护甲持续到战斗结束」）一旦写成 −1 就会复活它，变成整段永久护甲。修法见 E34（删掉 DefenseBuff 这一项，对现数据恒等）。
3. **同面多条 Reshape 的 `shieldStrike` / `armorStrike` 是覆盖不是相加。** `TraitRules.ApplyReshape` 对两字段「非缺省即覆盖」。塔：Lv4 塔基 `armorStrike 300` 会被 Lv8 镇塔 `500` 覆盖成 500（应为 800）；㙓：Lv8 地动 `shieldStrike 30` 会把 Lv5 山压的 `50` **降**成 30——Lv8 让 Lv5 变弱。现数据（碉 / 壁 崩岩、垒 / 崩 震地）每面只有一条，改成相加逐位恒等。Ruling 14 修订只处理了散射的多段字段，没覆盖这两项。修法 E27。
4. **D1 遗留「Row / All 下 ShieldStrike 口径」至今未定**（D1 执行记录「留给后续 plan」）。现实现：每个**主目标**的第一段加，`All` 时每个目标都是主目标 → 每个敌人各加一份。地动 / 移山（贯穿只首个主目标）落地时要定，见 Q16。
5. **水给土的两件「预留」不可直接用**（见结论速览）：`HurtHeal` 只能回血、每回合 1 次；`ShieldFrost.OnHit` 是拍尾反应（`DeferToBeatEnd`），定值、绕开 60% 预算。堡垒 / 碎玉另建 G3 / G4，只复用挂点位置与「两桶归零」判据。
6. **护甲轴吃不到 Lv4 通用池。** `TraitRules.InScope(AmpScope.All)` 只含伤害 / 治疗 / 护盾 / 反击 / 种 / 灼，不含 `DefenseBuff` / `ArmorBreak`。碉 先声、垒 化险、壁 精进、堡 克敌（固面退化精进）只放大护盾或伤害，土的另一半关键词（护甲 / 破甲）从不受益；深厚的攻面拆行同理。不在 D2-土 改，记 Plan F。
7. **字形 Lv4 是长空窗。** 圭·叠土（拆圭时）、垚·三土（合成垚时）只在拆 / 合那一刻生效，正常出字从 Lv4 到 Lv5 毫无变化；从掉落 / 奖励拿到的垚永远触发不了三土。balance 机器人从不 `Dismantle`（叠土读数恒 0），`Compose` 只在合成更强的字时发生。与火（双焰 / 火山 / 三焰）、金（双金）、木（双木 / 三木）同为系统性问题，记 Plan F。
8. **杜门不出的「AP −1」若照倾覆写成 `Seal`（Debuff）会被杜绝拦下、被洗涤 / 新沐清掉**——违反 R4「代价不算减益」。G7 改用 Buff 极性的 Seal（不经 `ApplyStatus` 拦截段），见 Q2。
9. **「我方减益」来源仍只有灯花（灼）与 Boss 倾覆（Seal）**（水附录 §0-1）。杜绝在小怪关基本空转，但**能挡下倾覆的 AP −1**——这是它在 Boss 关的真实价值，测试要钉。
10. **balance 机器人对土系的偏差**：① 选面规则「半血以上或身上有盾 → 出攻面」（2026-09-17）——固面打出一张后立刻转攻面，固面 Lv5 / Lv8 / Lv6（垒砌、厚德载物、浮屠、堡垒、杜门不出、碉楼、闭门、山岳…）**几乎不被选中**；反过来所有「伤害 + 当前护盾 × N%」的攻面特性**每次出手都有盾可吃**，读数偏高。② `Power()` 只读本体、不读特性。③ 不拆字、不模拟 AP 代价与「每场 1 次」。④ 单系·土 D1 实测僵局判死 144 / 292 / 268（Lv1 / 5 / 8，/ 300），读数无效。**本 plan 以五系随机为准**，单系·土只报僵局数。
11. 碎玉 / 反震 / 冰晶的挂载都看 `_cast.ShieldGranted`（只计玩家入账）——固面拖到木灵上时这三者都不挂（现口径），本 plan 沿用。
12. 备忘：`DamageCondition.PlayerHasArmor`（加固）只看 `DefenseBuff > 0`，不含基础护甲 / 富甲；而镇压（`armorStrike`）读 `EffectivePlayerDefense`（含基础、富甲、减破甲）。山岳「护甲 ≥ X」按后者（Q12）。
13. 口径一致项（无需改）：崩 攻面 `DamageSingle … shape All` + `SpendHeft` 与 spec「攻：全体，释放厚」一致；崩固面是单体 `Shield`（2026-10-04 裁定②）；㙓 攻面 `SpendHeft 60` 即「释放厚」。
