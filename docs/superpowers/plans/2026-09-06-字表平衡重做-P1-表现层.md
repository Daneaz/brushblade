# 字表平衡重做 · P1 表现层接线 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 P0 落地的引擎规则接到玩家看得见的地方,并**织上一张 P0 缺失的护栏网** —— 让「新增 `EffectKind` / `StatusKind` 忘了接表现层」这类静默缺陷从此变成红灯。

**Architecture:** 纯 Presentation + 文档生成器改动,**不碰 Core 的任何行为**。本批的价值有一半在护栏测试上:`Charm` 之所以能静默溜过 P0 的 11 轮评审,是因为仓库里从来没有一条测试枚举 `EffectKind` / `StatusKind` 并要求它们被渲染 —— `CardFaceCoverageTests` 只覆盖 `EffectDef` 的**字段**和 `TargetShape` 的**枚举值**。

**Tech Stack:** C# / Unity uGUI(Presentation 层)、Python(`gen_char_doc.py`)、NUnit

**Spec:** `docs/superpowers/specs/2026-09-05-字表平衡重做-design.md`
**交接情报:** `docs/superpowers/plans/2026-09-05-字表平衡重做-P1-交接.md`(**开工前必读第 0 节**)

## Global Constraints

- **Presentation 没有自动化测试** —— 本批的验收主要靠三样:①`prescompile` 离线编译;②护栏测试(任务 1 织的那张网);③人工看一遍。**改完 Presentation 必跑 prescompile**,否则编译错会一路漏到用户打开 Unity 才炸(项目里已发生过两次)。
- ⚠ **编译器不会帮你**:C# 的 `switch` 对未覆盖的枚举值**不报编译错**,本项目相关 switch 又都带 `default` / discard 兜底,连警告都没有。所以**不能靠 prescompile 发现漏接**,必须靠任务 1 的护栏测试。
- ⚠ **新增/改动任何玩家可见中文文案后必须重跑字体子集**:游戏打包的是子集字体,新字不在里面就会在真机上显示成空白/豆腐块 —— 而离线编译和 Core 单测**都发现不了**,只有 `pytest tools/fonts/tests/` 会红。修法:`python3 tools/fonts/subset_fonts.py`,然后复跑该测试。
- ⚠ **注释里引用文案要用「」,不要用 ASCII 双引号** —— `tools/fonts/subset_fonts.py:32` 的 `_STRING_RE` 对整个 `.cs` 文本跑正则、**不区分代码与注释**。P0 已因此红过一次。
- ⚠ **字符串表的 key 必须以字面量出现在代码里**。`StringsTableTests` 的扫描只认写死的 key,拼出来的(`Strings.T($"status.{name}.desc")`)会被判成孤儿文案 + 缺失 key,两个方向都栽过。
- **Core 与 Data 禁止引用 `UnityEngine`**;本批不改 Core 行为,但护栏测试在 Tests asmdef 里,**只能引用 Core / Data**,不能引用 Presentation —— 所以它必须用「把源码当文本读」的手法(照 `CardFaceCoverageTests` 的既有做法)。
- 测试断言只用 Unity 自带 NUnit 也支持的 API:禁用 `Is.AnyOf` / `Is.All.AnyOf`;`Does.Not.Contain(x)` **只在 x 是 string 时**可用(传 int/枚举是编译期 CS1503),集合判包含写成 `Assert.That(list.Contains(x), Is.True/False, "…")`。
- 测试代码禁止引用 Newtonsoft;定位仓库根只能用 `TestContext.CurrentContext.TestDirectory`。
- 新建 `.cs` 要配 `.meta`(从同目录别的 `.meta` 复制、改几位十六进制 guid、`grep -rn` 确认全仓唯一)。
- **不要改任何字表数值**(`chars.json`、管线详表)—— 那是 P2。
- 提交信息用 conventional commits。**只提交你改的文件**,不要 `git add -A`。

- [ ] **Step 1: 写护栏测试(会红)**

新建 `EnumRenderCoverageTests.cs`。手法照 `CardFaceCoverageTests` 的既有做法 —— **把源码当文本读**,因为 Tests asmdef 只放行 Core / Data,引用不到 Presentation:

```csharp
using System;
using System.IO;
using System.Linq;
using NUnit.Framework;
using Brushblade.Core;

namespace Brushblade.Core.Tests
{
    /// <summary>全枚举的表现层渲染覆盖(2026-09-06,P1)。
    ///
    /// 为什么要这张网:2026-09-05 新增 EffectKind.Charm / StatusKind.Charm 之后,
    /// 卡面会直接印英文「Charm」、状态详情整条凭空消失、战斗画面零提示 ——
    /// 而 **11 轮任务评审 + 一次全分支终审都没抓到**,离线编译也是绿的。
    /// 根因:C# 的 switch 对未覆盖的枚举值不报编译错,相关 switch 又都带 default
    /// 兜底,连警告都没有;而仓库里从来没有一条测试枚举这两个 Kind 要求它们被渲染。
    /// CardFaceCoverageTests 覆盖的是 EffectDef 的**字段**与 TargetShape 的**枚举值**,
    /// 盖不到这两个。
    ///
    /// 与 CardFaceCoverageTests 同一套手法:读源码文本而不是反射 Presentation ——
    /// Tests asmdef 是 overrideReferences 且只放行 nunit + Core + Data。</summary>
    public sealed class EnumRenderCoverageTests
    {
        private static string Root()
        {
            // 只能用 TestContext.TestDirectory:AppContext.BaseDirectory 在 Unity Test Runner
            // 下指向编辑器安装目录,往上永远找不到含 Brushblade/ 的父目录。
            var dir = new DirectoryInfo(TestContext.CurrentContext.TestDirectory);
            while (dir != null && !Directory.Exists(Path.Combine(dir.FullName, "Brushblade")))
                dir = dir.Parent;
            Assert.That(dir, Is.Not.Null, "找不到含 Brushblade/ 的仓库根");
            return dir.FullName;
        }

        private static string Source(string relative) =>
            File.ReadAllText(Path.Combine(Root(), "Brushblade/Assets/_Project/Presentation", relative));

        /// <summary>每个 EffectKind 都要在 CharInfo.EffectsText 里有分支,或进豁免名单。
        ///
        /// 漏一个的表现不是报错,是卡面上**直接印英文枚举名**(EffectsText 的兜底是
        /// `_ => e.Kind.ToString()`)—— 2026-09-02 的势/水势、2026-09-05 的 Charm 都是这样。</summary>
        [Test]
        public void EveryEffectKind_IsRenderedInCharInfoOrExempt()
        {
            var src = Source("CharInfo.cs");
            var missing = Enum.GetNames(typeof(EffectKind))
                .Where(n => !EffectKindExempt.ContainsKey(n) && !src.Contains($"EffectKind.{n}"))
                .OrderBy(n => n).ToArray();
            Assert.That(missing, Is.Empty,
                "这些 EffectKind 在 CharInfo 里没有渲染分支,卡面会印出英文枚举名:\n  "
                + string.Join("\n  ", missing)
                + "\n补上卡面文案,或加进 EffectKindExempt 并写明为什么玩家不该看到它。");
        }

        /// <summary>每个 StatusKind 都要在 StatusText.Of 里有 case,或进豁免名单。
        ///
        /// 漏一个的表现是**整条状态在详情面板里凭空消失**(Of 的 default 返回 None,
        /// 四个字段全 null),不是显示错误文案 —— 比印错字更难发现。</summary>
        [Test]
        public void EveryStatusKind_IsRenderedInStatusTextOrExempt()
        {
            var src = Source("UI/StatusText.cs");
            var missing = Enum.GetNames(typeof(StatusKind))
                .Where(n => !StatusKindExempt.ContainsKey(n) && !src.Contains($"StatusKind.{n}"))
                .OrderBy(n => n).ToArray();
            Assert.That(missing, Is.Empty,
                "这些 StatusKind 在 StatusText.Of 里没有 case,详情面板会整条不显示:\n  "
                + string.Join("\n  ", missing)
                + "\n补上文案,或加进 StatusKindExempt 并写明理由。");
        }

        /// <summary>敌人身上会出现的减益,要在 BattleView 的敌人格 chip 列表里有提示。
        ///
        /// 那是一条**手写的 if 链**,不在里面就不显示 —— 冻结/减速当年零显示踩的就是这个。
        /// 只查会挂在敌人身上的那些:玩家专属增益(战意/厚/泉…)不该出现在敌人格上。</summary>
        [Test]
        public void EveryEnemyDebuff_HasBattleViewChip()
        {
            var src = Source("BattleView.cs");
            var missing = EnemyFacingStatuses
                .Where(n => !src.Contains($"StatusKind.{n}"))
                .OrderBy(n => n).ToArray();
            Assert.That(missing, Is.Empty,
                "这些会挂在敌人身上的状态,战斗画面的敌人格没有任何提示:\n  "
                + string.Join("\n  ", missing));
        }

        /// <summary>豁免名单不许有已经不存在的枚举名(改名/删除后的残留)。</summary>
        [Test]
        public void ExemptLists_HaveNoStaleEntries()
        {
            var effectNames = Enum.GetNames(typeof(EffectKind));
            var statusNames = Enum.GetNames(typeof(StatusKind));
            var stale = EffectKindExempt.Keys.Where(k => !effectNames.Contains(k))
                .Concat(StatusKindExempt.Keys.Where(k => !statusNames.Contains(k)))
                .OrderBy(k => k).ToArray();
            Assert.That(stale, Is.Empty, "豁免名单里有已不存在的枚举名:\n  " + string.Join("\n  ", stale));
        }
    }
}
```

⚠ 三张表(`EffectKindExempt` / `StatusKindExempt` / `EnemyFacingStatuses`)你要**自己建**在这个类里,内容按下面的原则填,**每一条豁免都要写为什么玩家不该看到它**(照 `CardFaceCoverageTests.PassiveExempt` 的样子,值是理由字符串):

- `EffectKindExempt`:只放**玩家永远看不到卡面文案**的 Kind。P0 休眠的那批(`PierceBuff` / `Cleanse` / `Dispel` / `ApBoost` / `BurnNoDecay`)**不算豁免** —— 它们只是当前无载体,卡面渲染仍应保留,删掉的话 P2 复活它们时又是一个静默洞。先跑一遍看哪些真的缺,再逐个决定。
- `EnemyFacingStatuses`:手工列「会挂在敌人身上」的 `StatusKind`(灼烧、流血、冻结、减速、致盲、封禁、诅咒、破甲、魅惑…)。**不要**用「全部 StatusKind 减去玩家专属」这种推导 —— 那需要引擎里并不存在的分类,写死一张表反而诚实,而且新增时会被 `ExemptLists_HaveNoStaleEntries` 的同类检查提醒。
