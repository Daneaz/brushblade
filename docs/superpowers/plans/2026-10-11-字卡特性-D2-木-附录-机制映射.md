## 0. 结论速览

- **规模**：木系专属 **46 条**（白 1 + 绿 1 + 蓝 2 + 紫 4×2 + 金 5×2 + 橙 6×3 + 红 6，与 §7 配额一致）。Lv4 两面在攻面空转按 V4 拆行（秋实 / 披荆 / 馥郁 / 水草 / 参天之力）；坚心照湮灭先例写一行空效果，双木 / 三木是字形单行 → `木.md` 新增 **51 行**。非专属格（通·X、池·X）`木.md` 里已全部存在，不需要补。
- **A 直接 13 条**：万箭齐发、落叶、秋风扫叶、荆鞭、林海、坚心（空效果占位）、桂花雨、月桂、缠足、藻缚、三木、丛林、独木生林。
- **B 小扩展 13 条**：移花接木、一叶知秋、双木、众木、柘弓、硬弓、馥郁、丛藻、森罗、林深、万木回春、参天之力、撼天。
- **C 新机制 20 条**：箭灵（按 Q1 推荐口径）、攀附、秋实、披荆、荆刺、荆天棘地、林荫、林立、守护、良弓、折桂、蟾宫、桂冠、水草、藻荇、绿潮、森严、四木成林、落木、擎天。13 + 13 + 20 = 46。
- **新机制**：共用小扩展 **E37–E50（14 项）** + 木系新机制 **M1–M11（11 项）**。核心五团：
  1. 「本命追加」（E37）：Lv4–Lv8 的木灵被动统一写成 `Summon 0` + 本命字段，Fold 合并进本体召唤的被动。这一条是 12 条特性的地基。
  2. 「木灵光环」（M1 玩家袋光环、M2 本命在场光环）。
  3. 「木灵生死挂点」（M3 阵亡、M4 受击、M5 守护）。
  4. 「敌人侧标记」（M6 荆刺、M7 攀附）。
  5. 「木灵编队操作」（E41 / E47 / E48 幼苗与召唤改形、M8 并入、M9 立即行动、E43 复活）。
- **可复用件（逐一读过调用点）**：
  - 现成可用：
    - W7 `TurnPulse`（BE.Water `EnqueueTurnPulses`）：一叶知秋用，但载荷白名单 `TurnPulseAllows` 不含 Vulnerable，且 `OpeningEffect` 没有 OnlyIf，所以要配 E50。
    - E35 `battleLimit`：只认 Cast 时机（ET:294 与 `TraitRules.BattleLimited` 都限 `Trigger == Cast`），折桂是击杀时，要配 E49。
    - D2-0 嫁接（`IsGraft` BE:2108、Summon 分支 BE:4283）与 §2.2 生面落木灵：嫁接读 Fold 后的 Summon，所以 E37 合并的本命会随嫁接带走（Q3）。
    - 花灵本命「迷香」（`OnHitCharmChance`，BE `ApplySummonOnHit` 5062）与移花接木的魅惑同用 `StatusKind.Charm`。
    - `SummonStrike`（BE:3716）：林海 / 万箭齐发直接用，柘弓经 E46 扩展后用。
    - `HealAll`（BE:4242，玩家 + 全部木灵）：桂花雨直接用。
    - `HealSummons percentOfMax`（BE:3684）：三木直接用。
    - `SummonSapling`（BE:3661）：丛林 / 独木生林直接用。
  - 木系用不上：
    - E28 `ofShield`：木的灵荫是池里的定值 `ShieldSummons 44`（箭 Lv8 生）。
    - G3 HurtShield：木表里没有「我方受击得盾」。土附录预告的「落木灵需另接 DamageSummon」本 plan **不需要**。
- **trace 覆盖（实测，§3 表头有细节）**：
  - 两档 sha 复核一致：`7235e89f…` / `883954a3…`。
  - 卡池情况：「基准杂食」卡池含 箭 / 林 / 藻 / 森；「基准1级」由 木+木 合出林，全 1 级。
  - trace 机器人对这四字**恒选生面**：`Power` 的召唤分 (血 + 攻 × 3) / 2 大于攻面伤害。
  - **实测事件**：Summon 309、SummonAttack 1724、SummonHit 884、EnemyAttack 314。Heal / Shield / Graft 均为 0，没有任何魅惑事件。
  - 推论：trace **守护**以下路径：
    - 本体召唤：`Summon` 分支（非嫁接）
    - 入场幼苗（森然）、丛生 `TrySprout`（藻）
    - 成林、远程选目标
    - `ActSummonTurn` / `StrikeOnceWithSummon` / `RefreshSummonAura` / `EffectiveAttack`
    - `DamageSummon`（无荆棘、无格挡、无嘲讽本命）、`DamagePlayerDirect`
    - 木灵跨场携带 `CaptureAliveSummons`
  - trace **完全不走**以下路径：
    - 种（`TriggerSeeds`，攻面 0 次）
    - 魅惑反打（`ActEnemyTurn` 魅惑支）
    - 嫁接
    - `SummonSapling` / `HealSummons` / `ShieldSummons` / `SummonStrike` / `Endure` / `Revive` 各效果分支
    - 桂香光环 `HealAlly`
    - 荆棘反伤段：荆 / 柘 / 桂 / 楸 / 藤 / 花 / 𣛧 都不在卡池
  - 后果：这些路径的改动只能靠「无新状态逐位恒等」单元对照测试守护（§3 末）。
- **最大风险**：
  1. **召唤超模叠加生存**。单系·木本来就是全画像最高（Lv1/5/8 = 24.3/26.7/28.9）。召唤超模来自「前排木灵硬拦截」这个机制（见记忆 `summon_dominance_is_the_block_mechanic`），本 plan 又在其上加了几层：
     - 守护：替玩家承担 30%
     - 林荫：我方减伤 ≤ 20%
     - 森严：木灵受伤 −25%
     - 良弓、绿潮嘲讽、万木回春
     - E38 让 Lv4 通用池第一次作用到召唤血 / 攻
     
     预计木系 Lv5 / Lv8 读数显著抬升。数值定标归 Plan F；如果要压，应当动机制而不是动数值。
  2. **热路径插桩密集，且有一个新随机流消费方**。下列挂点每一个都必须缺省一次判断即短路：
     - `DamageSummon`（trace 884 次）：M1 / M2 / M4 / M6
     - `DamagePlayerDirect`（314 次）：M2 / M5 / M6
     - `RefreshSummonAura` / `EffectiveAttack`（每次木灵出手都读）：M1 / 参天之力
     - `RollCrit` / `RollCritForSummon`（每次伤害都调）：M2 蟾宫
     
     其中蟾宫让木灵第一次有暴击率，`_random` 会多出一个消费方。它必须严格以「桂灵在场」为闸门，否则 trace 整条随机流会平移。
  3. **槽位身份与生命周期**。攀附（敌人身上记藤灵槽位）、擎天 / 桂冠（按槽位挂光环）、丛藻 / 绿潮（`SproutParentSlot`）都用**槽位下标**指代木灵。下标会被重新占用：
     - 顶替召唤不走 `OnSummonDeath`
     - 尸体槽会被复用
     - 跨场按槽位携带
     
     三个时钟口径也并存：木灵身上状态按木灵自己出手递减（D2-0 遗留）、玩家袋按玩家回合递减、敌人袋按敌人行动递减。这类缺陷 trace 一条都抓不到，只能靠「死亡 / 顶替 / 跨场」三类回归测试兜底。

**调研中发现的现存问题**

1. **生面上的 Lv4 通用池全部空转**。`TraitRules.InScope(AmpScope.All)`（TR:432）只含伤害 / 治疗 / 护盾 / 反击 / 种 / 灼，**不含 `Summon` / `HealSummons` / `ShieldSummons`**。受影响的已上线格子：
   - 花·先声（`Amplify 15 All if FirstCastThisTurn`，两面）
   - 藤·精进（`Amplify 12 All`，两面）
   - 箭·破敌的生面行（`Amplify 15 All`，D2-0 按用户裁定退化成精进）
   
   这三格在生面上什么也不放大，用户「克敌 / 破敌 / 补刀在五行面按精进生效」的裁定对木系实际落空。本 plan 木专属 Lv4 空转面写的精进只落在攻面，不受影响；但生面若再写精进同样落空。修法 E38。
2. **花·Lv5·攻「池·寄生」（`Augment 1 of Seed field Turns`）永久空转**：花的攻面 Lv1 是魅惑不是种。见 Q27。
3. **箭灵与箭的 Lv1 本命重复**：箭本体 passive 已经是 `ranged: true`，Lv3 远射·强化再加 `BackRowBonus 50`；箭灵原文「召唤的木灵为远程，可打后排」照字面零收益。见 Q1。
4. **木灵身上的限时状态会跨场**：`RunEngine.CaptureAliveSummons`（RunEngine:918）只剥 `StatusRules.IsBattleScoped` 与圭臬的本场护甲。`TurnsLeft > 0` 的 AttackBuff（剡 turns）、DefenseBuff（铠 / 叠嶂拖到木灵）、Reflect（壁）等会带着剩余回合进入下一场。玩家侧早已按「限时的不跨场」处理（RunEngine:672 注释）。修法 E44（trace 恒等：trace 木灵身上只有 −1 的灼）。
5. **木灵身上的 N 回合状态按木灵自己的出手递减**：`ActSummonTurn` 末尾 `summon.Statuses.TickTurns()`（BE:2507）。速度 150 的林 / 森 / 藻 / 𣛧 灵每轮约 1.5 拍，「2 回合嘲讽」实际只撑约 1.3 轮，可能在敌人出手前到期（D2-0 执行记录遗留）。本 plan 的「全部 / 其他木灵 N 回合」一律做成**玩家袋光环、按玩家回合计**（M1），绕开这个问题；绿潮的嘲讽见 Q18。
6. **`SummonState.MaxHp` / `Attack` 只读**（EnemyDef.cs:200–201）。绿潮「属性相加」需要改成 internal set；快照本来就存这两项，存档结构不变。
7. **顶替召唤不算阵亡**：Summon 分支 `_summons[slot] = newborn`（BE:4364 附近）直接覆盖活木灵，不走 `OnSummonDeath`。所以秋实 / 落木 / 藻荇在顶替时不触发；攀附 / 光环这类槽位记号必须在落位处另行清理（同 `ClearSproutParent` 的做法）。
8. **Boss 吞噬绕开 `LoseSummonHp`**（BE `CastBossSkill` Devour，6170）：扎根保命挡不住吞噬（D1 附录 ❓，现状），但 `OnSummonDeath` 会照常调用，所以秋实 / 落木 / 藻荇对吞噬生效。
9. **`ScaledAmpPercent` 的缺省分支会落到「带灼敌人数」**（BE.Fire:89–94，三元表达式最后一支是 `PreCastBurningEnemies()`）。新增 `ScaleBasis.SummonCount` 若漏写分支，会静默按带灼敌人数算，测试不一定红。E39 必须显式加分支并配反向测试。
10. **`OpeningEffect` 不带 OnlyIf**（Core/OpeningEffect.cs:11–33），所以 TurnPulse 的载荷做不了条件门。`Retaliate` 只挂玩家袋、载荷不收伤害（BE.Fire `RetaliateAllows`），良弓不能复用。
11. **机器人对木系的偏差**：
    - trace 机器人：恒出生面，所以种 / 魅惑 0 次。
    - balance 机器人选面：半血以上或有盾就出攻面，否则出生面。实测攻面 74–83 次 / 局，召唤 14–17 次 / 局。
    - balance 机器人从不嫁接、从不顶替。召唤位满时 `Cast` 返回 `SummonCapFull`，机器人直接 `break` 结束本回合，白丢 AP。
    - `Power()` 不读特性。
    
    所以拆字（双木）、嫁接、编队类特性（绿潮 / 四木成林 / 擎天）在 balance 里几乎测不到。
12. 备忘：
    - 木灵没有基础暴击通道：`RollCritForSummon`（BE:1000）只读木灵袋子里的 CritBuff，缺省 0 不摇号。
    - `EffectiveCrit`（BE:939）只给玩家用。
    - 玩家战斗格的暴击 chip 读 `EffectiveCrit`，木灵格读状态总量（BattleView `AddSummonStatusChips` 2631）。
    - 木灵格的本命 chip 只出一枚（`SummonPassiveChip` 2555，按优先级取第一个）。
