# Plan D2-火 机制映射（只读调研稿）

> 2026-10-07。基于 main `f77b0d97`（D2-0 `eded8edf` + E1 合并）。代码行号指 main 的 `Core/BattleEngine.cs`（下称 BE）。
> spec = `docs/superpowers/specs/2026-10-03-字卡五特性体系-design.md` v7；附录 = `2026-10-04-字卡特性-D1-附录-机制缺口.md`。
> 分类口径：**A 直接** = 现有 EffectKind + 现有 token 就能写；**B 小扩展** = 给现有机制加字段 / token / 枚举值 / 选择器；
> **C 新机制** = 要新 EffectKind / StatusKind / 新挂点。

## 0. 结论速览

- 火系专属 **44 条**，与 §7 配额一致（白1 绿1 蓝2 紫4×3 金5×2 橙6×2 红6）。
- **A 直接 13 条**：升温、双焰、火上浇油、蒸腾、蒸笼、火山、炫目、三焰、飞焰、焚风、焚甲、火海、烈焰天幕。
- **B 小扩展 14 条**：气盛、连爆、惊爆、烈风、燥裂、燥火攻心、温润、炎刃、流光、火花四溅、星星之火、焚林、四炎、焚天。
- **C 新机制 17 条**：埋雷、火烧连营、烈焰护身、干涸、焦土、水火相激、上炎、炎炎、光耀、灿然、星火、炽焰、烈焚、焚城、玉石俱焚、四火、焚身。
- 合并后的新机制约 **12 组**（见 §3）。全部数据都在 Lv4 及以上，**对 trace 恒等**（trace 用全 1 级卡组）。
- **调研中发现的现存问题（建议 D2-火 一并修）**：
  1. **池·烟熏在燃面上永远不生效**。池表写的是 `Blind 15` `pick HitTargets` `rider Burn`，而 `_castHitTargets` 只由 DamageSingle 填（BE 3253）。燃面没有伤害，所以 HitTargets 恒为空。热、炸、燥的 Lv6 都是 `燃·池·烟熏`，三条全部空转。现有测试 `TraitTriggerRiderTests.Smoke_*` 只测了攻击面，没覆盖到。修法：新增选择器 `BurnedByThisCast`（读 `_castBurnedTargets`），把池表的烟熏改用它。干涸、上炎、炽焰、焚城、焚身也要用这个选择器。
  2. **M19 开局登记没有落地**。`RegisterOpening`（BE 4512）在生产代码里没有调用方，`EffectDef` 也没有 `OpeningBattles` 字段，管线没有 `battles` token。D2-0 Task 1 只接了仿真的跨段携带。炎炎和星星之火（以及金、水、土的跨场特性）都需要这一项。
  3. **特性施加的减攻会和本体减攻同源合并**。Weaken 的 SourceId = 字 ID（BE 3339），ApplyStatus 对同源条目「量取大、回合取长」（BE 4483）。流光要的是「−40%，持续 1 回合」，并进本体「−15%，3 回合」后会变成「−40%，3 回合」。焦土、星星之火、火海、烈焰天幕也有同样的问题。
  4. 致盲的命中惩罚是**相加**的（`AttackHits` 用 TotalMagnitude，BE 5387），不是取最强。烟熏 15 + 炫目 20 + 蒸笼 25 可以叠到 60%。§5.2 第 1 律没有点名「命中」，需要裁定（见 §4）。
