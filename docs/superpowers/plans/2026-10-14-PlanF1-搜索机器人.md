# Plan F1 · 仿真搜索机器人 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `tools/balance` 的价目表贪心机器人换成「副本试算 + 整回合剪枝搜索」机器人，读数能看见特性、会拆合嫁接替换、跨段携带与生产一致；快档 ≤ 5 分钟、慢档 ≤ 30 分钟。

**Architecture:** 新代码放 `tools/balance/Bot/`（候选 / 搜索 / 打分 / 估值 / 驱动五个文件），只读 Core 的 public 接口（`Capture`/`Restore`、`Cast`、`EstimateCast`、`CanGraftAt`/`CanReplaceAt` 等）；新建 `tools/balance.tests`（NUnit，链接 Core/Data/Bot 源码）做 TDD。trace 机器人不动；旧机器人保留 `--legacy-bot`。

**Tech Stack:** C# 9 / .NET 8（Unity 自带 dotnet SDK）；NUnit；Core/Data 以源码链接（同 `tools/balance` 现有 csproj）。

**Spec:** `docs/superpowers/specs/2026-10-14-PlanF1-搜索机器人-design.md`（实现者必读对应章节；冲突以 spec 为准）。

## 已定口径

- 用户授权：待裁定项由 controller 按 spec 精神自定，事后汇报。
- 打分常数用 spec §3 初值；只做一次 ±50% 灵敏度检查（Task 5），不调优。
- 剪枝：快档 K=4 / 叶子上限 256；慢档 K=12 / 叶子上限 4096。速度超标时先降叶子上限、再降 K，记入执行记录。
- 叶子跑敌人回合的副本：在 `BattleSnapshot` 上把 `RandomState` / `TargetRandomState` / `TraitRandomState` 换成由（种子, 层, 回合, 叶子序号无关）派生的固定值后再 `Restore`（spec §2.4：同一局面多次评估结果一致，与本体 RNG 无关）。
- 局外估值参考局面：该层段深度的普通战编成（`EndlessGenerator` 固定种子）+ 满血玩家 + 无木灵。
- 不调任何数值、不改机制、不改 trace 机器人。

## Global Constraints

- **Core 改动**只允许纯追加的只读 public 接口（不改结算）；有改动则 coretests 全绿、prescompile、`tools/balance` / `tools/chestsim` / `tools/trace` 三工装 build、trace 两档 sha 恒等（默认档 `7235e89f…`、只加 `--flat-scale` 档 `883954a3…`；取法见 `docs/superpowers/plans/2026-10-12-字卡特性-E4-余项.md` 执行记录）。
- Core / Data 禁止引用 UnityEngine。
- 新工程 `tools/balance.tests`：NUnit；仓库根用 `TestContext.CurrentContext.TestDirectory` 定位；禁 `Is.AnyOf`、`Does.Not.Contain` 只用于 string（与项目习惯一致）。
- 确定性：同一种子单线程与并发卒层逐位相同；并发只在种子之间。
- **git**：不用 stash；不 `git add -A`；只提交自己改的文件；conventional commits（`feat(balance): …` / `test(balance): …`），末尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。`tools/balance/bin|obj`、`tools/balance.tests/bin|obj` 不入库（检查 .gitignore）。

## Review Focus

1. **副本隔离**：搜索与估值只在 `Restore` 出的副本上执行，本体 `Capture()` 前后逐字段相等（含三条 RNG 流）——否则读数被搜索过程污染。
2. **不偷看**：叶子敌人回合的 RNG 与本体无关；换本体 RNG 状态，搜索选出的序列不变。
3. **确定性**：并发与单线程卒层逐位相同；估值缓存线程安全、与访问顺序无关。
4. **候选完备且合法**：嫁接 / 替换 / 拆 / 合 / 两面 / 全部落点都在；被 Core 拒的候选不会进入执行（不会白扣 AP 或静默打空）。
5. **生产对齐**：跨段携带 `CarriedHp`、`MaxHpBonus`、扩容标志、开局效果；~~不带木灵与护盾~~ 按生产另带护盾、木灵、厚 / 泉（2026-10-14 改正，见 spec §4.3 与执行记录）。
