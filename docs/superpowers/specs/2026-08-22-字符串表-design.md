# 字符串表(i18n)落地 — 设计稿

日期:2026-08-22
状态:已与用户逐节确认,待写实现计划

## 1. 目标

`docs/architecture.md` §5 把 i18n 列为「R13,第一天执行」,但至今**一行未落地**:全项目 Presentation 层有 529 处硬编码中文字面量(其中 498 处是真文案,差额见 §3),`Brushblade.Data` 职责表里写着的「字符串表(i18n)」是一格空白。

本设计把它补上:在 Data 层建一张 `key → 文本` 表,把 Presentation 的玩家可见文案全部迁进去,并用测试锁住 key 的完整性。

**触发这件事的是另一个问题**:用户观察到字卡详情的内容「一部分在 chars.json,一部分在别的地方」,问能否统一到 chars.json。结论是**不能也不该** —— 见 §3 的边界。真正该收敛的是「文案没有归宿,只能散落在各 .cs 里」这一点。

## 2. 范围

**做**:Data 层 `Strings` 静态表 + 命名占位符替换器、`strings.zh-CN.json`、`GameRoot` 注入、Presentation 498 处文案迁移(16 个文件)、三条对账测试。

**不做**:

- **多语言翻译**。首发只带 zh-CN 一张表(`architecture.md` §5 原话:「表结构即预留了后续英/日本地化,短期不投翻译资源」)。
- **运行时语言切换 UI**。表结构支持换文件,但不做设置项 —— 只有一种语言时那是死按钮。
- **Core/Data 的 128 处异常消息**。见 §3。
- **Presentation 的结构重构**。只替换字面量,不动 UI 组织方式。`BattleView.cs` 一家占 200 处,它该拆,但不在本次(与「攻击形状」spec §2 同一条自律)。

## 3. 边界:什么进表,什么不进

`architecture.md:89` 已经画过这条线,本节把它落到具体文件:

> 字卡的「字形 / 拼音 / 释义」是**游戏数据**(来自配置表),不是 UI 文案,不进字符串表;进字符串表的是按钮 / 提示 / 奇遇文案 / 系统消息等。

| 类别 | 条数 | 例 | 判定 | 理由 |
|---|---|---|---|---|
| 按钮 / 标题 / 提示 / 引导 / 飘字 | 498 | 「继续战斗」「战意+{stacks}层」「分裂!」 | **进表** | 玩家可见 UI 文案 |
| 状态图标单字(`UI/Icons.cs`) | 17 | 炎 / 灭 / 冰 / 盲 | 不进 | 字形符号,与字卡字形同性质 |
| 敌人 / Boss 名(`Mobs/MobAssets.cs`) | 12 | 错字鬼 → `cuozigui` | 不进 | 是 `enemies.json` 的**主键**,兼美术 slug 的查表键。翻译掉会直接断资源查找 |
| 字卡字形 / 拼音 / 释义 | — | 「焚」 | 不进 | 游戏数据,归 `chars.json`(拼音/释义当前缺失,是另一件事,见 §12 U1) |
| Core / Data 异常消息 | 128 | 「战役 JSON 解析失败」 | 不进 | 开发者面向。配置错了游戏根本起不来,玩家永远看不到这句 |
| `Debug.Log` | 2 | `[TimeSync] 校时成功…` | 不进 | 同上 |

**边界的一句话判据**:这句话错了,是玩家看到错字,还是开发者看到报错?前者进表。

⚠️ `Juice.cs` 的 19 处飘字里混着一个 `"木"`(召唤物默认字形),迁移时要挑出来留在代码里。这类「文案堆里混着数据」的地方需要逐条过眼,不能批量替换。

## 4. 方案空间:只有一个

`Brushblade.Data.asmdef` 是 `noEngineReferences: true`,这条硬规则排掉了两个常见方案:

- **ScriptableObject 表** — 要 UnityEngine,Data 层引不了。
- **Unity Localization 包** — 同上,且引入一个大依赖来管一张只有 zh-CN 的表,是典型的过度工程。

剩下的唯一形态是**纯 C# 静态表 + 路径由上层注入**,与 `ConfigLoader` 完全同构(`architecture.md:26` 的「路径由上层注入」正是为此)。不硬凑三个方案。

## 5. 表:位置与格式

```
Brushblade/Assets/StreamingAssets/config/strings.zh-CN.json
```

```json
{
  "battle.btn.exit": "退出",
  "battle.hint.pickcard": "点击字库中的字开始行动",
  "effect.morale": "战意+{stacks}层(每层攻击+{per},上限 {max} 层)",
  "char.rarity.white": "白"
}
```

**为什么放 `config/`**:放到 `Resources/` 或别处都要改 `CODE_DIRS`,平白给字体管线添一个必须记住的联动。

⚠️ **这段原来写错了,留作教训**:原稿在这里断言"`json_chars()` 已经覆盖整个
`StreamingAssets/config` 目录,文案挪进来后字形安全网自动跟上"——错的。`json_chars()`
这个*函数*确实能扫任意 JSON,但当时它的*调用点*(`subset_fonts.py` 的 `charset()`)
硬编码的是 `for name in ("chars.json", "enemies.json")`,压根没列
`strings.zh-CN.json`。只读了函数签名、没读调用点传了什么参数,就下了"自动覆盖"的结论。

结果是本次迁移把约 240 个玩家可见字从 `.cs` 字面量挪进 `strings.zh-CN.json` 后,
这些字**没有**被自动收进字体子集(旧字面量消失、新 JSON 没被扫),子集从 1016 字形
掉到 778,且 `tools/fonts/tests/test_subset.py` 当时的覆盖检查也只核对
`chars.json`/`enemies.json` 这两个名字,同样没读到 `strings.zh-CN.json`,所以两道
安全网**同时**失效、一声不响。任务 7 实跑重新子集化时用 cmap 计数比对才捞出这个问题
(architecture.md/CLAUDE.md 那条"必须实跑,不能靠推理确认字符集不变"的规矩,
就是为了拦住这类只读函数不读调用点的错法)。

已修复:`charset()` 与 `test_charset_covers_config` 都改成
`sorted(CONFIG.glob("*.json"))` 按目录扫描,新增配置表不用再记得改列表;
并用故障注入验证过——临时还原旧的硬编码扫描,测试确实变红。

**为什么扁平不嵌套**:一层 `{key: text}` 让 grep 和对账测试都是直筒逻辑。嵌套结构要写递归展平,换来的只是 JSON 好看一点。

**文件名带 `zh-CN`**:换语言 = 换文件名,加表不改结构。这是 §2 说的「预留」,不是现在就做多语言。

## 6. API

Data 层,纯 C#:

```csharp
public static class Strings
{
    /// <summary>启动时注入表内容。重复调用覆盖(换语言即换文件)。</summary>
    public static void Load(string json);

    public static string T(string key);
    public static string T(string key, params (string name, object value)[] args);
}
```

调用形态:

```csharp
Strings.T("battle.btn.exit")
Strings.T("effect.morale", ("stacks", v), ("per", 10), ("max", 5))
```

**命名占位符,不用 `string.Format`**。替换器约 20 行:遍历 args 做 `Replace("{" + name + "}", value)`。

理由是语序。中文「战意+3层(每层攻击+10)」译成英文会变成 "+3 Morale (+10 ATK each)",参数顺序未必守得住;`{0}`/`{1}` 在这种时候会静默插错值,而读表的人也看不出 `{0}` 是什么。命名占位符两个问题一起解决,代价只是那 20 行。

**缺 key 返回 `?key?`,不抛异常。** UI 不该因为漏了一句话整屏白掉 —— 这与 `BattleView.cs:1347` 那条取舍同型(「白屏的代价 vs 画错一只怪的代价不对称,所以兜」)。防线交给 §7 的对账测试:漏 key 在 coretests 里毫秒级变红,根本活不到运行期。

**格式化的口径**:`T` 只做字符串替换,不管数字格式。像 `CritMultiplierPercent / 100f:0.##` 这种格式化留在调用点算好再传进来 —— 表里只有文案,没有计算。

## 7. 注入点

`GameRoot.cs:37-39` 已经有配置加载段,`Strings.Load` 紧挨着放:

```csharp
string configDir = Path.Combine(Application.streamingAssetsPath, "config");
Strings.Load(File.ReadAllText(Path.Combine(configDir, "strings.zh-CN.json")));  // 新增,必须在最前
_graph = ConfigLoader.LoadGraph(...);
```

**必须在其它加载之前** —— `ConfigLoader` 抛的异常消息虽然不进表,但后续任何 UI 构建都可能取文案。

## 8. key 命名

`模块.子域.名`,全小写点分:

| 前缀 | 覆盖 |
|---|---|
| `battle.*` | 战斗界面(按钮、提示、引导、状态标签) |
| `char.*` | 字卡描述(稀有度名、五行名、效果模板) |
| `enemy.*` | 敌人详情面板 |
| `map.*` | 主界面 / 无尽外层 / 宝箱 |
| `shop.*` `collection.*` `perk.*` `bestiary.*` | 各二级界面 |
| `juice.*` | 飘字 |
| `common.*` | 跨界面复用(「知道了」「取消」) |

**去重是收益也是风险**:498 处去重后 431 条,即有 67 处是重复文案(「继续战斗」「知道了」出现多次)。合并进 `common.*` 是对的,但要确认它们**语义**相同而不只是字面相同 —— 同样是「确定」,在删除确认和领奖确认里将来可能要分开译。拿不准就不合并,重复 key 的代价远小于合并错。

## 9. 测试

三条,放 `Brushblade/Assets/_Project/Tests/StringsTableTests.cs`,走 coretests 工装(毫秒级,不占编辑器锁):

1. **正向对账** — 扫 Presentation 全部 `.cs` 里的 `Strings.T("…")` 字面量 key,每个都必须在表里。挡「文案漏迁 / key 拼错」。
2. **反向对账** — 表里每个 key 都必须至少被一处引用。挡「删了调用忘了删表项」的孤儿堆积。
3. **占位符对账** — 表里模板的每个 `{name}`,在其调用点必须都被提供;调用点提供的每个 name,模板里必须存在。挡「改文案时加了占位符但没改调用」。

外加一条常规单元测试:`Strings.T` 的缺 key 回退、占位符替换、重复 `Load` 覆盖。

⚠️ **仓库根只能用 `TestContext.CurrentContext.TestDirectory` 定位**。`AppContext.BaseDirectory` 在 Unity Test Runner 下指向编辑器安装目录(`Unity.app/Contents`),往上永远找不到含 `Brushblade/` 的父目录 —— 这类测试会整类变红而 dotnet 工装全绿。项目已在 `DefenseValuesTests`(15 条)和 `PierceBuffCharTests`(4 条)上犯过一次。

⚠️ **测试不能引用 Presentation 程序集**。Tests asmdef 是 `overrideReferences: true`,只放行 Core / Data / nunit。前三条测试因此是**读 `.cs` 源码文本**做正则扫描,不是反射。这也正是 `ConfigLoaderTests.cs` 被 coretests 排除的同一类约束(它依赖 `Application.streamingAssetsPath`)—— 本设计的测试刻意避开引擎 API,好让两套工装都能跑。

## 11. 风险

1. **Presentation 没有自动化测试,`prescompile` 是唯一编译期防线。** 对账测试能挡 key 错,挡不住「文案搬错位置」(把「确认退出」贴到了「继续战斗」的按钮上)这类语义错。**最后必须由用户在 Unity 里过一遍主要界面** —— 这是本设计唯一无法自动化的验收环节。
2. **498 处替换触及 16 个文件**,与任何并行分支冲突面很大。建议在 worktree 里一次做完、尽快合回。注意 worktree 里跑验证要补软链与程序集路径覆盖(见 `CLAUDE.md`)。
3. **`Juice.cs` 那类「文案混着数据」需要逐条过眼**(§3 末),批量正则替换会把 `"木"` 一起卷走。
