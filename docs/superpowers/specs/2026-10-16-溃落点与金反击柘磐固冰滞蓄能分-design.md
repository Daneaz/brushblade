## §1 Bug:我方全体类五行面只能落玩家(溃)

**现象**:溃 五行面(`HealAll 45`,群体治疗)拖出时只能落玩家,不能落木灵;崩 五行面(`ShieldAll 45 + DefenseBuff`)能落木灵。

**根因**:`CardFaceRules.Landing`(`Core/CardFaceRules.cs:46-52`)只在 `NeedsAllyTarget` 为真时给 `Self | Summons`。崩 能落木灵只是因为带了 `DefenseBuff`(在 `EffectNeedsAllyTarget` 名单里),`ShieldAll` 本身并不算;溃 只有 `HealAll`,落点只剩 `Self`。

**修法**:`Landing` 里「本面含我方全体效果」(`HealAll`、`ShieldAll`,及 pick AllAllies 的 `Cleanse` / `Kindle`,口径与 `CardSheetRules.IsAllyAllTargeted` 同源)时,落点 = `Self | Summons`。
- 溃 Lv5+ 解锁溃围后落点 = 敌 / 玩家 / 木灵。
- 只改落点(拖到哪都能放手),**不改结算**:效果照旧覆盖我方全体,落在哪只身上都一样。
- **不**把 `HealAll` 加进 `EffectNeedsAllyTarget`(那会让引擎要求选目标,波及仿真与所有群治字)。
- 影响面:所有带上述效果的五行面(溃、淋 等)一并获得木灵落点;`EffectNeedsAllyTarget` 旁「群治不在内」的注释同步改写为「免选,但落点放开」。
- 测试:`CardFaceRulesTests` 补 溃 / 淋(HealAll)、单 ShieldAll 面 → `Self | Summons`;Cast 传木灵 slot 时结算与传玩家一致(全体都被治疗)。

## §2 金系反击按格挡前伤害算(整份预算)

**现状**:反击类共用一份预算 `基数 × CombatCaps.ReflectPercent(60%) − 已用`,基数取**格挡等减伤之后**的伤害(玩家侧 `BattleEngine.DamagePlayerDirect` 约 `:6220`、`:6244-6246`;木灵侧 `DamageSummon` 约 `:6436`、`:6439`)。格挡减伤 40% 叠在预算上,反击上限 ≈ 36%,单系·金 Lv5 / Lv8 反击被削 78% / 83%。

**改为**:预算基数 = **减伤前**伤害(两侧已有局部变量 `preCut`)。整份预算一起换:反击、镜、荆棘、反震、碎玉、良弓都按 `preCut × 60%` 起算,扣减顺序不变。
- 每击反击量(`本体伤害 × 反击% × 加倍 / 刀光 / 横扫 70%`)不变,只是上限放宽到 60%。
- Boss ×2(立威)仍在预算之后,不变。
- 玩家可见文案不涉及基数,不改;同步改 Core 注释(`EffectDef.cs`、`StatusEffect.cs` 提「60% 预算 / 减伤后」处)与 D2-金 plan 的 Q1 口径注记(写一行「2026-10-16 改为格挡前」)。
- 测试:`MetalBlockRidersTests` / `BlockTests` / `SummonBlockTests` / `MetalExecuteTests` 中按减伤后断言的预算数值按新基数改写(如攻击 1000 → 预算 600,而非 360);新增一条「格挡在场时反击可达 preCut × 60%」与一条「镜 + 反击共用预算,基数同为 preCut」。
- trace sha 预期会变(trace 机器人出过铠面则变;若不变需说明原因)。

## §3 柘 Lv6 生面:守护 → 磐固

**原因**:守护(玩家受挥击伤害 30% 转给柘灵)挂在玩家受击路径上,而柘灵天生嘲讽,敌人单体攻击都打它,守护几乎不触发。

**新特性「磐固」**:柘灵每次受到攻击(挥击,任意来源敌人),自身护甲 +10;本场战斗内叠加,上限 +50。
- 叠在柘灵本命护甲(`SummonArmor`,Lv3 后 60)之上;护甲的减伤公式与上限沿用现有木灵护甲规则(若有总上限,磐固受同一上限约束)。
- 「本场」:战斗结束清零;跨段携带的柘灵下一场从 +0 起。柘灵阵亡清零。
- 判定点:`DamageSummon` 中柘灵实际被命中(未被免疫抵消)后 +10,先结算本击再加(本击不吃本次加成)。DOT(灼 / 流血)不算「受到攻击」。
- 数据:`特性表/木.md` 柘 Lv6 行 `Guard 30` → 新被动标记(建议 `SummonPassive` 新增 `Harden`,值 10、上限 50),管线导出 chars.json;`SummonPassive.Guard` 若无其他载体,保留枚举(append-only)但删除数据与文案引用,`GuardSlot` / `TransferToGuard` 无载体后删除。
- 文案:字卡特性行「磐固:受到攻击时护甲 +10(本场,至多 +50)」;木灵详情(`SummonInfo`)本命被动区同步;状态 chip 显示当前叠层护甲(若需新 chip → 先交 `designer` 出稿;过渡期复用现有护甲 chip 的数值显示)。
- 测试:受击 6 次 → 护甲 +50 封顶;DOT 不加;本击不吃本次加成;战斗结束清零;无 Guard 载体后 `TransferToGuard` 路径无引用。

## §5 冰封类效果对冰滞 Boss 同样生效

**现状**:Boss 吃冻结时被转为 `IceStall`(行动条后退 50% + 受伤 +15%,下次行动前移除并挂霜抗)。以「本字冻结的目标」为条件的特性只认 `StatusKind.Freeze`,对 Boss 全部空转:
| 特性 | 字·级 | 效果 |
|---|---|---|
| 冰封 | 冰 Lv4 攻 | 标记:受伤 +30%,持续到解冻 |
| 冰缚 | 湮 Lv6、冻 Lv6 | 标记:受伤 +20%,持续到解冻 |
| 寒彻 | 冰 Lv6 | 冻结结束时受本体 50% 伤害 |
| 冰水 | 淼 Lv6 | 冻结结束后减速 2 回合 |

(湮灭无踪、水火相激 已把冰滞算作被控,不动。)

**改为**:冰滞视作 Boss 版的「冻结中」,上述四条对冰滞照常生效:
- 本字把 Boss 打进冰滞时,该 Boss 也记入 `FrozenByThisCast` 名单(`BattleEngine.cs` Freeze 分支约 `:3606-3608`)。
- 冰封 / 冰缚 的标记附着到冰滞上:冰滞移除时一并移除(「持续到解冻」= 持续到冰滞结束)。
- 寒彻 / 冰水 在冰滞结束时触发(冰滞移除处约 `:2777` 与 `Thaw` 解冻路径,都走同一个「冻结结束」结算)。
- 冰滞结束时先移除冰封 / 冰缚标记,再结算寒彻 / 冰水(与小怪自然到期一致)。
- 霜抗、冰滞本身规则不变;冰滞 15% 易伤与冰封标记独立相乘 / 相加按现有易伤合并规则。
- **字卡描述**:相关文案键补 Boss 口径:
  - `char.effect.vulnerable.bind`(已落地措辞):「标记 受伤+{value}%,至冻结/冰滞结束」;
  - `char.effect.thawstrike(.body)` / `thawslow`:「本字的冻结结束时」→「本字的冻结(Boss 为冰滞)结束时」;
  - `char.effect.pick.frozen`:「(被冻结的敌人)」→「(被冻结或冰滞的敌人)」。
  - 重跑字体子集。
- 测试:四条特性各一条 Boss 用例(冰滞期间标记生效、冰滞结束标记消失、结束时寒彻伤害 / 冰水减速落地);非 Boss 原有用例不变;D2-水 附录 Q3「对 Boss 不生效」口径注记改为本节。

## §6 A1:增益类五行面的蓄能分(balance 机器人)

细节见议题清单 A1。只改 `tools/balance/Bot/`,不改 Core。

- `Evaluator.Terms` 新增燃意项(`Quick` / `Full` 共用,剪枝阶段即可见):
  `Σ(玩家, 各存活木灵) 剩余回合 × 燃意% × 该单位每回合预计输出 × 换算`,另加每段命中 +1 灼的 DOT 当量。
  - 玩家每回合预计输出:当前手牌 + 字库中攻击面的平均单次伤害估值(不含燃意本身),乘每回合可出字次数(AP / 平均费用)。
  - 木灵:攻击力 × 出手段数。
  - 换算:预计伤害 ÷ 场上敌人总最大生命 × `DamageWeight`(与 offense 同口径)。
  - 剩余回合按燃意 `TurnsLeft`;已在本回合打出的部分已计入 offense,不重复。
- 厚 / 泉 / 战意的 `StackValue = 3` 一并按「预计兑现伤害」重估(同一换算口径;厚 / 泉 = 层数 × 释放字每层值,战意 = 每层增伤 × 预计输出),无释放字在手 / 库时打折。
- 测试(`tools/balance.tests`):挂燃意的局面分 > 未挂;「燃意 → 攻击面」序列在 K = 4 下不被剪;厚 / 泉 / 战意 重估后分数随层数单调。
- 验收:快档重跑,报 火系两面字 攻:五行 出手比、单系·火 与五系随机卒层前后差;读数进议题清单 A1。trace 不受影响(trace 机器人不动)。
