# 战斗屏与局内流程接稿 — 设计

2026-08-30。把 `docs/design/ui/scenes/` 里**稿子先行**的那一批落到实现，屏上与稿一致。

稿是唯一权威。本文只记**决策**与**边界**；每一格的尺寸、配色、文案以稿为准，
不在这里抄一遍（抄一遍就是第二个真相源，迟早对不上）。

## 背景

`docs/design/ui/scenes/README.md` 记着三批「稿子先行」：

- 2026-08-28 补的 8 块局内流程与弹窗 —— 实现侧仍是 `ModalShell` 默认外壳与两张朴素居中卡。
- 2026-08-29 的单位详情弹窗 —— 实现侧是 `Ui.Modal` 一段 StringBuilder 长文本，
  执笔人**根本没有入口**。
- `Battle.dc.html` 自身的三栏版面、敌人护盾、29 枚状态图标。

顺带回填一条**已过期**的记载：README「稿子先行」小节说「每排 4 格位」待实现，
实际 2026-08-27 已完成（`FrontRowSize = 4`、`EnemyCap = 8`、`SummonCap = 8`）。

## 已定决策

1. **落地方式：骨架换布局组，绘制方法原地不动。**
   `BattleView.BuildSkeleton` 从「比例锚点 + 手算纵向预算」改成
   `Horizontal/VerticalLayoutGroup + LayoutElement`，直译稿的 flex 语义；
   `DrawEnemies` / `DrawPlayerStats` / `DrawPool` 等挂到新父节点上，方法体不搬家。
   本轮**新增**的能力（单位详情、统一弹窗外壳、引导弹层）一律开新文件。

   理由：稿是 flex 写的（中区 `flex:1` 吃富余、分隔线靠 `margin:auto` 把余量对半堆到
   敌我之间、`.foe` 用 `flex:none` 防压扁）。比例锚点只能把稿在某一台设备上量出来的
   结果钉死成一串小数 —— `BuildSkeleton` 顶上那串「改动任何一格的内容高度时请重算」
   的人肉加法正是实现慢慢偏离稿的来源。把 4007 行切成六个文件对「和稿一致」没有贡献，
   而 Presentation 一行自动化测试都没有，重排与搬家捆一起出问题分不清是哪件引起的。

2. **敌人护盾：机制就位，来源留白。**
   `EnemyState` 加 `Shield`、`DamageEnemy` 在护甲减法之后扣血之前插吸收段、
   补 `ShieldBroken` 事件、进快照。但**不改 `enemies.json`、不做结盾技能** ——
   用户拍板：盾的来源将来是「加盾辅助怪给同伴挂 buff」，那类小怪还没设计。
   所以现在场上敌人的 `Shield` 恒为 0，稿上那条 `shb` 只在 `Shield > 0` 时出现。

   ⚠ 这意味着盾条**在真机上暂时看不见**。别因为「看不见」就把它当没做 ——
   Core 侧的吸收逻辑要有测试，表现侧要能在 `Shield > 0` 时正确画出来。

3. **相克即破甲不穿盾。** 相克那一击绕过护甲（硬度），但护盾（一层临时血）照常吸收。
   护甲是「难打进去」，护盾是「先打空这层」，两回事；连盾一起穿会让护盾对
   带对属性的玩家形同虚设。

4. **相生环图去掉，左窄栏只留相克。** 战斗中要实时查的是「我这张字克不克它」；
   相生是 ×3 去重不叠乘的加成，不需要每帧摆在屏上。去掉一张腾出右上角。

5. **单位尺寸按 1pt = 2.093 逻辑单位换算。** 稿的设备基准是 iPhone 16 Pro Max
   横屏 932×430pt，而 `CanvasScaler` 是 1600×900 按高匹配 → 实际逻辑画布 1950×900。
   稿上 68pt 的左窄栏 = 142 逻辑单位；132pt 的拆合台 = 276；40pt 的玩家条 = 84。
   详见 `Device.dc.html`。**换算结果写进代码时要在常量旁注明稿上的 pt 值**，
   照 `MapView` 顶部那批常量的先例。

## 三轮

按序做完，每轮一份 plan。轮次之间是**依赖**关系不只是顺序：轮二用轮一新增的
图标与 `status.*` 文案，轮三用轮二定下的详情骨架。

### 轮一 · 战斗屏本体

权威：`Battle.dc.html`。

1. **三栏骨架**：左窄栏（相克环图 + 配字表）/ 中区 / 右栏拆合台。
2. **敌人格竖排 → 横排**：立绘在左、信息列在右。稿里写明了理由 ——
   中区横向本就富余，横排后格高由立绘单独决定，纵向反比竖排省 24px/排，
   省出来的全给敌我之间的留白。这会**推翻** `BuildSkeleton` 顶上那串纵向预算注释，
   连同注释一并删除，不留一段描述已不存在的布局的长注释。
3. **我方格同样横排**，召唤物立绘反而放大。
4. **玩家条**与战场格同构：立绘方块 + 信息列 + 三条 + AP 竖笔画格 + 定宽状态栏。
5. **手牌与部件池**进中区，各带广告扩容位。
6. **拆合台**：选中字 + 出/拆/弃 + 可合成列表 + 结束回合钮，收进右栏一栏。
7. **顶栏**：关卡名 / 层·场 / 墨锭 / 回合 / `?` 引导 / `✕` 退出。
8. **敌人护盾**（决策 2）：Core 字段 + 吸收 + 事件 + 快照；表现侧盾条与盾角标。
9. **状态图标 18 → 29**：补
   `armorbreak` `bleed` `scorch` `sear` `split` `obscure` `focus` `ranged`
   `sweep` `skewer` `thorns` 十一枚。SVG **逐字抄稿**（`Battle.dc.html` 的 `icdefs`），
   与 `build_icons.py` 的 `nav_*` 同一条戒律：改稿就重抄一遍，别在脚本里手改坐标。
   `Icons.Glyphs` 的兜底汉字同步补齐（`test_icons.py` 守着两张表一一对应）。
10. **新手引导**：屏底单行 `◆ 提示` → 屏幕中央四步故事弹层
    （一句道理 → 一个动作 → 一句结果），遮罩只压到 38% 以便看得见被点名的牌/怪。
    顺带修 README 记的一处不一致：`Tutorial.DemoChar` 是「刺」而四条
    `battle.hint.tutorial.*` 写的是【剑】—— 新手会被指去点一张手上没有的牌。

### 轮二 · 单位详情

权威：`UnitFoe.dc.html` / `UnitAlly.dc.html` / `UnitMe.dc.html` / `StatusGlossary.dc.html`。

三类单位共用一个骨架（立绘 + 名与三条 + 左状态右特性 + 底部提示行），只换内容不换版式。
**不做二级弹窗** —— 玩家点开详情正是为了对着战场看，再弹一层就得先关掉才看得回去。

- `EnemyInfo` / `SummonInfo` 从「返回整段文本」改成返回**逐条结构**。
- 玩家条加点击入口（执笔人详情，实现侧此前根本没有）。
- 新建 `status.*` 两族 strings key，底稿是 `StatusGlossary.dc.html` ——
  29 枚图标 + 4 条走文字 chip 的能力，逐条写清机制 / 挂在谁身上 / 时长口径 / 能不能清掉。

### 轮三 · 局内流程串联

权威：`SafeLayer.dc.html` `Settle.dc.html` `Reward.dc.html` `Replace.dc.html`
`Event.dc.html` `RunEnd.dc.html` `Dialogs.dc.html` `Popups.dc.html`。

功能全都已经有，缺的是版面与统一的外壳。

- **两个整屏**：`GameRoot.ShowSafeLayer` / `ShowTowerSettle` 从朴素居中卡改成整屏版面。
- **`BattleView` 五阶段**：战利品选字 / 字库已满换字 / 广告复活 / 奇遇 / 段末横幅。
- **弹窗族**：`Ui.Modal` / `ModalShell` / `Alert` 的 13 个调用点统一外壳。
- **飘字口径**：`Juice.cs` 的 18 种飘字对齐 `Popups.dc.html`。

贯穿这一轮的一条规矩（稿上定死的）：**凡是不可逆的，都要在按下去之前说清楚** ——
安全层把「深入 / 撤退」的取舍写在钮下面而不是一行小字，换字把「永久失去」
做成标红告警条。

## 风险

- **版面回归无自动化兜底。** 三轮都在动同一屏，前一轮试玩过的东西可能被后一轮碰坏，
  而没有任何测试会红。缓解：每轮结束交付一次可试玩的提交，不攒到最后。
- **新文案必然引入新字形。** 轮二的 `status.*` 是 29+ 条说明文字，轮一的引导弹层
  是三段故事模板 —— 两轮都要重跑字体子集，且**光看 diff 大小说明不了变没变，要比 cmap**。
- **护盾看不见。** 决策 2 让盾条在真机上暂时不出现，人工试玩验不到它。
  Core 侧靠单测，表现侧只能靠代码审阅 + 将来加盾怪上线时的回归。
- **手牌与部件格尺寸变化。** 稿上手牌 46×56pt = 96×117 逻辑单位，比现在的 68×85
  **大**约四成；中区被左右两栏夹窄之后满员 12 张是否还排得下，要在最坏情形下量一次。
