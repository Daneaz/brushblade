# 子项目 C:召唤物被动族 — 设计

**日期:** 2026-08-05
**范围:** 详表 §7.2 的 P2「召唤物被动族」9 字(烓 灶 桂 蕉 楸 荆 桃 槐 桤)
**目标:** 字表可用字数 100 → 109

---

## 一 · 背景与既有事实

`BattleEngine` 已有召唤物基础设施(2026-07-19 拍板,2026-08-04 接入行动计量器):

- `SummonState`:`Char / Element / Hp / MaxHp / Attack / Speed / ActionMeter`
- 召唤物顶前排替玩家承伤(`DamageSummon`),回合末在「召唤段」出手打首个存活敌人
- 出手次数走行动计量器:`ActionMeter += Speed`,每满 `ActionMeterThreshold = 100` 出手一次,
  单回合封顶 `MaxActionsPerTurn = 2`
- 召唤物血量/攻击都是**平值**,不过 `WuxingResolver`(详表 §1.2)

探索期确认的三条会改变范围的事实:

1. **详表给 桤 的「当回合即可反击」已是既有默认行为** —— 新召唤物 `ActionMeter = 0`,
   回合末 `+Speed(100) = 100` 就够出手一次。这条差异化是空的,桤 需重新定义。
2. **`桂` 已在 `chars.json` 里,但是个空壳条目** `{"id": "桂"}`,当前被 `溎`(氵+桂)
   当叶子部件使用。要变成召唤字得补 `recipe` 与 `effects`。
3. **三个配方部件缺库**:`桃` 需 `兆`、`槐` 需 `鬼`、`荆` 按 IDS 需生僻字 `茾`。

## 二 · 数据形状

按详表 §7.5.5「P2 召唤物被动做成 `EffectDef` 扩展字段而非新 `Kind`,与 `SummonCount` 同构」。

### 2.1 `SummonPassive`(新增,Core 纯数据)

```csharp
/// <summary>召唤物被动(2026-08-05):随 Summon 效果整体拷进 SummonState,伴随召唤物生死。</summary>
public sealed class SummonPassive
{
    public int Speed { get; }         // 基础速度,默认 100        —— 桤 150
    public int Thorns { get; }        // 被打时反弹的固定伤害      —— 荆 3
    public int HealAlly { get; }      // 每回合给玩家+全召唤物回血  —— 桃 3
    public int OnHitBurn { get; }     // 出手时给目标挂灼烧层数     —— 烓 3 / 灶 2 / 楸 1
    public bool OnHitBurnAll { get; } // true = 全体挂;false = 只挂被打的 —— 烓 true
    public int OnHitCurse { get; }    // 出手时挂诅咒(减攻百分比)  —— 槐 25
}
```

`EffectDef` 新增两个字段:

- `SummonPassive Passive`(默认 `null` = 无被动,等价于全 0 / Speed 100)
- `int SummonShield`(桂 = 6;不进 `SummonPassive`,理由见 §3.4)

`SummonState` 新增两个字段:

- `SummonPassive Passive { get; internal set; }`
- `int Shield { get; internal set; }`

`SummonState.Speed` 的初始化改为读 `Passive?.Speed ?? 100`。

### 2.2 关键简化:光环与「攻击附灼烧」是同一件事

详表把 烓/灶 记作 `SummonAura`、楸 记作 `SummonOnHitBurn`,是三种机制。实际上三者都是
「召唤物出手时额外挂灼烧」,只差伤害数值和目标范围:

| 字 | 攻 | `OnHitBurn` | `OnHitBurnAll` |
|---|---|---|---|
| 烓 | 0 | 3 | true |
| 灶 | 0 | 2 | false |
| 楸 | 6 | 1 | false |

一个字段对覆盖三种机制。语义也更对:将来召唤物被冻结/减速,挂灼烧的节奏跟着变,
而不是脱离行动系统的独立计时器。

**代价与约束:** 攻 0 的召唤物必须照常进出手循环。现有循环不因 `Attack <= 0` 提前返回
(`DamageEnemy(target, 0, ...)` 是无害的),但要有测试钉死这一点。

## 三 · 结算口径

### 3.1 召唤段时序(`BattleEngine.EndTurn` 内)

```
召唤段开始:
  ① 逐只结算 HealAlly —— 与出手无关,场上没有存活敌人时也照常回血
  ② 逐只累积行动计量器,满 100 出手一次(单回合封顶 2 次):
       DamageEnemy(首个存活敌人, summon.Attack)
       OnHitBurn > 0 → 挂灼烧:OnHitBurnAll ? 全体存活敌人 : 该目标
       OnHitCurse > 0 → 给该目标挂 Curse
```

`HealAlly` 复用既有 `HealPlayerAndSummons(amount)`,不越玩家血量上限。
挂灼烧复用既有 `ApplyBurn(index, stacks)` 并发 `BattleEventKind.Burn` 事件。

### 3.2 反伤(`Thorns`)

在 `DamageSummon` 里,扣完护盾与血量后结算:若 `Passive.Thorns > 0` 且攻击者仍存活,
对攻击者造成 `Thorns` 点**固定伤害,不走生克**(与 `Bleed` 同口径,可预期)。

三条边界:

- **反伤会引爆连锁**:`DamageEnemy` 可能触发分裂、焦痕自燃、敌人死亡、Boss 换阶。
  现有敌方回合循环已能处理召唤物中途死亡;反伤打死敌人后必须补 `CheckWin()`,
  否则玩家清场了仍在走敌方回合。这条要专门写测试。
- **`吞噬`(`BossSkill.Devour`)不触发反伤** —— 它直接 `victim.Hp = 0`,不经 `DamageSummon`。
  这是「无视血量必杀」的既有语义,保留。
- 反伤发生在承伤之后:召唤物被打死的那一击**仍然反伤**(荆棘扎人不看自己死没死)。

### 3.3 护盾吸收

`DamageSummon` 里,伤害先扣 `Shield` 再扣 `Hp`:

```
int taken = WuxingResolver.ResolveEffect(damage, ..., summon.Element);
int absorbed = Math.Min(summon.Shield, taken);
summon.Shield -= absorbed;
summon.Hp = Math.Max(0, summon.Hp - (taken - absorbed));
```

`SummonHit` 事件的 `Amount` 仍报 `taken`(表现层的掉血动画自会因为 Hp 没降而不动),
护盾吸收量走 `BattleEvent` 的第五个参数 `absorbed`,与 `DamagePlayerDirect` 同构。

### 3.4 `桂` 的护盾为什么不是 `SummonPassive` 字段

`桂` 的效果是「出字瞬间给**全场**召唤物各 +6 盾」,不是「这只召唤物自带盾」。它作用于
出字时已在场的其他召唤物,所以是 `EffectDef.SummonShield` 的一次性效果,在 `Summon`
分支把新生的都加进 `_summons` 之后执行:

```
if (effect.SummonShield > 0)
    foreach (var s in _summons) if (s.Alive) s.Shield += effect.SummonShield;
```

一次性额外血条:吸完即无,不刷新,不随回合清空(与玩家护盾的回合末全清不同 ——
召唤物本身就是消耗品,再加个衰减太碎)。

### 3.5 诅咒(新 `StatusKind.Curse`)

`StatusKind` 新增 `Curse`,`Magnitude` 解读为**减攻百分比**。`EnemyState.Attack` 改为:

```csharp
public int Attack
{
    get
    {
        int raw = BaseAttack + Statuses.TotalMagnitude(StatusKind.AttackBuff);
        int curse = Math.Min(100, Statuses.TotalMagnitude(StatusKind.Curse));
        return curse <= 0 ? raw : Math.Max(0, (int)Math.Floor(raw * (1 - curse / 100f)));
    }
}
```

施加参数:`Polarity = Debuff`、`TurnsLeft = 2`、**`SourceId = "槐"`**。
同 `SourceId` 走 `StatusBag.Apply` 的去重刷新路径 —— 两只槐仍是 −25%,
否则 4 只槐能把敌人减攻打到 0。

Boss 大招(`CastBossSkill`)读的就是 `enemy.Attack`,诅咒自动对大招生效,无需额外接线。

### 3.6 `桤` 的速度

`Speed = 150`。计量器节拍:`0+150=150`(1 次,余 50)→ `50+150=200`(2 次,余 0)→ 循环,
即 **1,2,1,2 = 平均 1.5 次/回合**。攻 7 × 1.5 = 10.5 期望伤害/回合,略高于同档 楸(6),
但只有 20 血,是脆皮打手,档位成立。

`MaxActionsPerTurn = 2` 已经封顶,不需要改。

### 3.7 `蕉` 不需要任何机制

详表已注明:引擎召唤物本就替玩家承伤,28 血 / 攻 3 的高血低攻就是天然肉盾。纯数据落地。

## 四 · 数据落地(`chars.json`)

召唤血量与攻击都是**平值**,直接填最终值,不做 ÷3(已验证 `ApplyEffects` 的 `Summon`
分支只经 `MetaRules.ScaleByCardLevel`,不经 `WuxingResolver`)。灼烧层数同样是平值。

| 字 | 稀 | 系 | 配方 | 召 | 血/攻 | 被动 |
|---|---|---|---|---|---|---|
| 烓 | 🟡金 | Fire | 火+圭 | 1 | 22/0 | `OnHitBurn 3`, `OnHitBurnAll` |
| 桂 | 🟡金 | Wood | 木+圭 | 2 | 22/9 | `SummonShield 6` |
| 蕉 | 🟣紫 | Wood | 艹+焦 | 1 | 28/3 | — |
| 楸 | 🟣紫 | Wood | 木+秋 | 1 | 24/6 | `OnHitBurn 1` |
| 荆 | 🟣紫 | Wood | 艹+刂 | 1 | 18/6 | `Thorns 3` |
| 桤 | 🟣紫 | Wood | 木+岂 | 1 | 20/7 | `Speed 150` |
| 灶 | 🟣紫 | Fire | 火+土 | 1 | 11/0 | `OnHitBurn 2` |
| 桃 | 🟢绿 | Wood | 木+兆 | 1 | 12/3 | `HealAlly 3` |
| 槐 | 🟢绿 | Wood | 木+鬼 | 1 | 12/4 | `OnHitCurse 25` |

`summonChar`:木系一律 `"木"`(既有惯例);火系的 烓/灶 用 `"火"`。

**新部件 2 个:`兆`、`鬼`** —— 以无 `recipe`、无 `effects` 的条目形式加进 `chars.json`
(与 `圭`/`秋`/`岂` 同形状)。`鬼` 已在字体子集里(敌人「错字鬼」带进去的),`兆` 是新增,
`subset_fonts.py` 重跑覆盖。

**`荆` 用 `艹+刂`**(评分版 §召唤 第 3 行的口径),不用 IDS 的 `⿰茾刂` —— `茾` 是生僻字,
字体子集与玩家辨识都是负担,而 `艹`/`刂` 都已在库。

**`桂` 从空壳部件变成召唤字**:补 `recipe: ["木","圭"]` 后它成为可拆的字,`溎`(氵+桂)的
派生部件池从 `{氵,桂}` 变成 `{氵,木,圭}`。这与 `森`(木+林)/`林`(木+木)的关系同构,
有先例,是加深度不是破坏。`溎` 不在起手出阵表,不影响 `StartingSetupTests`。

## 五 · 存档

### 5.1 必须顺手修的既有 bug

`SummonSnapshot` 只存 `Char / Element / Hp / MaxHp / Attack / ActionMeter` —— **`Speed` 没存**。
子项目 0 给 `SummonState` 加了 `Speed` 字段但漏了存档接线,桤 一旦跨战斗保留就会退回 100。

本子项目补三项进 `SummonSnapshot`:`Speed`、`Shield`、`Passive`。

### 5.2 兼容性

这次是**纯新增字段**,不改名、不改形状。Newtonsoft 遇到缺字段填默认值(`Passive = null`
= 无被动,`Speed = 0`),不会像 `CarriedDamageReductions` 改名那次抛 `JsonException`
导致 `SaveSerializer` 兜底清档。

⚠ `Speed` 缺字段会填 **0 而不是 100** —— 老存档恢复出来的召唤物速度为 0 就永远不出手。
`SummonState.Restore` 必须做 `speed <= 0 ? 100 : speed` 的兜底。这条要有显式测试。

## 六 · 表现层

`BattleView.DrawSummons`:

- 有盾时在血条旁画盾值(复用敌人 chip 样式)
- 带被动的召唤物加一行小字:`反伤3` / `光环3` / `回血3` / `疾` —— 让玩家看得出这只树
  跟别的树不一样

`BattleView.DrawEnemies`:

- 敌人 chips 加 `诅咒 −25%`。攻击力 chip 本来就读 `enemy.Attack`,诅咒后数字自动降,
  但需要一个标记解释原因。

**不做新动效**:反伤走既有伤害飘字(它就是 `DamageEnemy`),光环走既有灼烧 chip 与
`BattleEventKind.Burn`,回血走既有 `Heal` 事件。YAGNI。

⚠ 别用 emoji 做被动标记 —— 字体子集补不出来,上线渲染成空框(`test_subset_fonts_cover_charset`
正是拦这个的)。用中文短词。

## 七 · 测试

### Core 单测(`tools/coretests`,首选)

每机制一条,加这些边界:

1. 反伤打死敌人 → 敌方回合中途 `CheckWin()` 生效,`Phase == Won`
2. 反伤对「吞噬」不触发
3. 反伤在召唤物被打死的那一击上仍然结算
4. 护盾先于血量吸收;吸完不刷新;不随回合清空
5. `桂` 的护盾给到出字时**已在场**的其他召唤物,不只给新召的
6. 诅咒同 `SourceId` 只刷新不叠(两只槐 → 仍 −25%)
7. 诅咒对 Boss 大招生效(`CastBossSkill` 走 `enemy.Attack`)
8. 诅咒到期后攻击力复原
9. 桤 `Speed 150` 的节拍是 1,2,1,2
10. 攻 0 的 烓/灶 仍能挂灼烧(出手循环不因 `Attack <= 0` 提前返回)
11. 烓 的 `OnHitBurnAll` 挂全体,灶 的只挂被打的那只
12. 桃 的 `HealAlly` 在场上无存活敌人时也照常回血
13. 存档往返保住 `Speed / Shield / Passive`
14. 老存档(无 `Speed` 字段)恢复后速度兜底为 100,不是 0
