# 上状态动效统一 — design

日期:2026-10-18 ・ 状态:用户已在对话中认可方案(2026-10-18)
审计底稿:`docs/superpowers/specs/2026-10-18-上状态动效-审计.md`(现状、旁路、测试影响面、隐藏载体,行号以 33aa9308 为准)

## 背景

给单位上状态时的动效不统一:约 12 种控制状态有「chip 闪 + 状态名签」(前后比对 `CueNewStatuses`),灼 / 敌人加攻只有一个小飘字,
其余约 30 种(玩家 / 木灵全部增益、流血、破甲、减攻、种、厚、泉、字卡战意…)什么都不播。用户举例:出字上「灼」无动效,
「引燃」有(实为灼结算的伤害动效)。用户补充:因技能 / 特性生效附带的状态也要覆盖(如暴击时锋芒 +1 战意)。

## 目标

凡**玩家可见**的战斗状态(含层数)在某单位身上新增或增加时,都播同一套「上状态」动效;来源不论是出字、特性 / 被动、敌人行动。

## §1 Core:新事件 `BattleEventKind.StatusApplied`(末尾追加)

- 参数:`TargetIndex` = 敌人下标 / 木灵槽位(玩家 −1);`SecondIndex` = 阵营(0 敌、1 玩家、2 木灵);`Amount` = `(int)StatusKind`;
  `Absorbed` = 本次增量(层数 / 量,刷新为 0);`Source` 照常(调用方的来源,无则默认)。
- 发射点:`ApplyStatus` 成功分支(在 `HookKind.StatusApplied` 钩子同处)+ 审计 §1 的四处旁路 ——
  `AddPlayerCounter` 已有条目分支(战意 / 厚 / 泉)、金汇加格挡次数、磐固 `Harden`、杜门不出 `ApplyApCost`。集中到一个 helper。
- 木灵光环类(SummonEmpower / SummonThorns / SummonRanged,存在玩家袋、TargetSlot 指向木灵):按 TargetSlot 发到木灵(−1 = 每只存活木灵各一条)。
- **不发**:
  - 隐藏载体(`StatusText.Of` 无名的 kind,审计 §5)与 `ApBoost`(无 chip,反馈是 AP 格数)。Core 侧白名单 + 对账测试。
  - 被拦下的施加(已有 `BuffBlocked` / `DebuffWarded`)、冻结被霜抗 / 已冻结静默挡下。
  - 已有专门事件的:灼(`Burn` / `SummonBurn`)、敌人加攻(`EnemyBuff`)—— 表现层把它们路由到同一套动效。
  - 锋芒(`GrantMoraleFromCrit`):已有 `MoraleGain`,该路径不再发新事件(避免两个 +N)。
  - 影子引擎(Estimate)可短路不发。
- 增量为 0 的刷新照发(`Absorbed = 0`)。
- **恒等**:identity fingerprint 测试与 `tools/trace` 记录**过滤掉新 Kind**,旧基线不动(trace 两档 sha 应与当前一致,作为「只加事件、没动结算」的证明)。
  会被插队的按位置断言(审计 §4:`BattleEngineTests:1083`、`FireBurnOpsTests:296`、`InfoHidingTests:142` 等)按「新事件不打断原有相邻关系」处理:
  能通过排除规则避开就避开,避不开的把断言改成忽略 StatusApplied 后再比,不改原语义。
- 顺手修:桂给全场木灵加盾(`effect.SummonShield`)不发 `Shield` 事件。

## §2 Presentation:统一动效

- 复用现有「上状态」动效:目标单位的状态 chip `FlashIcon` + 头顶 `StatusLabel`(名签:chip 底色 + 图标 + 名),**不新增视觉元素**(故不走 designer 出稿)。
- 名签:带量的状态(灼、战意、厚、泉、格挡、流血等有数字 chip 的)接「+N」;首次上身 = 正常名签;叠层 / 刷新 = 小一档名签(同款、缩小)。
- 同一批里同一单位同一状态多次增加合并成一次(增量相加)。同一单位多个名签错开,不重叠。
- `Burn` / `SummonBurn` / `EnemyBuff` 原有小飘字改走这套(上炎 等特性名照旧在前)。
- 锋芒:保留批末飞光;落点那一下改为战意 chip 闪 + 名签「战意 +N」(特性名「锋芒」照旧)。
- 特性 / 被动附带的状态(披荆流血、藻荇减速、绿潮嘲讽等)由新事件统一覆盖;原三处手动 `ChipCue` 删除,特性名播报保留。
- 下线前后比对:`CueNewStatuses` / `AnnounceSnapshot` 的状态部分、`TraitCueRules.AnnouncedKinds`、`CueNewAuras`。冰滞的行动条结霜 `FrostSnap` 保留(挂到新事件上)。
- 护盾不是状态 chip,原「盾+N」不变。

## §3 范围外

- 状态结算(灼每回合跳伤、引燃、流血跳伤)动效不动。
- 新视觉(如「点燃」火花)不做;要做先交 designer。
