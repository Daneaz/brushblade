上游:Plan F「群体攻击占比」「后期只能靠群攻」(`specs/2026-10-16-PlanF-议题清单.md`)。用户 10-18 拍板:先试方向 2(各系群攻入口)+ 5(混编),

## §1 各系群攻入口(方向 2)

**现状**:本体攻击面带范围的只有 火 6 / 水 2 / 土 2(崩 全体、㙓 释放厚);金、木 0。金木土的范围都在 Lv5 / Lv8 特性里(剑 横扫千军、锥 锥心、楸 秋风扫叶、森 林深、碎 碎石…),前中期摸不到。

**改为**:金、木、土各给 2 个字的**本体攻击面**改成群体范围(Lv1 起就有)。数值按 spec A §2 范围系数:单体 1.0 / 群体(横扫、贯穿、溅射)0.75 / 全体 0.5,
即 蓝字锚值 90 → 群体 68。范围内每个目标都吃同一数值(`ShapePercent 100`)。

| 系 | 字(稀有度) | 本体改为 | 本体伤害 | 原同范围特性的处理 |
|---|---|---|---|---|
| 金 | 剑(蓝) | 横扫 Row | 90 → 68 | Lv8 横扫千军 Row 50 → 改为「全体 50」 |
| 金 | 锥(蓝) | 贯穿 Column | 90 → 68 | Lv8 锥心 Column 70 → 改为「全体 50」 |
| 木 | 箭(蓝) | 贯穿 Column | 90 → 68 | Lv8 万箭齐发(散射)不变 |
| 木 | 楸(紫) | 横扫 Row | 133 → 100 | Lv8 秋风扫叶 Row 60 → 改为「全体 50」 |
| 土 | 碎(蓝) | 溅射 Adjacent | 90 → 68 | Lv5 碎石 Row 50 → 改为「全体 50」(碎石落满场) |
| 土 | 垒(绿) | 横扫 Row | 62 → 47 | Lv8 劈山 Row 50 → 改为「全体 50」 |

- 选字原则:字义贴范围(剑扫、锥穿、箭穿、秋风扫、碎石溅、垒成排),优先蓝及以下(前期能拿到),每系一横一纵 / 溅。
- 改动走数据管线:`技能机制详表.md`(本体)+ `特性表/{金,木,土}.md`(特性)→ `extract_values` / `export_chars`。`SpecAAlignmentTests` 补「群体 0.75」口径。
- 字卡文案由现有范围词条自动生成(横扫 / 贯穿 / 溅射已有),不新增文案。
- 验收:快档重跑,报各系群攻占比(本体)与单系卒层变化;群攻占比进 Plan F。

## §2 后期混编:头领 + 少量小怪(方向 5)

**现状**:普通层敌人数 `MinionCountFor = 1 + min(7, (depth−1)/6)`,43 层满 8 只,同档小怪。

**改为**:深度 ≥ 25(敌人数 ≥ 5 起)的普通层,遭遇 = **1 只头领 + (MinionCountFor − 3) 只小怪**(头领顶 3 只的份量)。
- 头领 = **小头领**,从本层怪池抽一只(前排优先),属性在本层缩放之上再乘:生命 ×2、攻击 ×1.3,护甲不变;占 1 格(不做 2 格大怪,免新立绘尺寸)。
- **必须弱于本段 Boss**(用户 10-18):头领生命 ≤ 本段 Boss(同深度缩放、各阶段生命合计)的 50%,攻击 ≤ 本段 Boss 各阶段攻击的最大值;
  超出则钳到上限。对账测试遍历全部段落与怪池断言这两条。(参考:最肥的杂兵 版牍 260 × 2 = 520,成语 Boss 四阶段合计 830 → 上限 415,会被钳。)
- 头领只「顶 3 只的位置」,不顶 3 只的血量:后期总血量与输出压力下降,难度变化由快档实测,F3 定标时再调倍率。
- 人数:25 层 5 → 1+2 = 3 只;31 层 6 → 4 只;43 层 8 → 6 只。
- 经济:头领击杀墨锭 ×3(与它顶掉的 3 只持平),总墨锭不变;`economy_model.py` 同步。
- 召唤槽:`SummonSlotsFor ≤ 敌人数` 的对账改为按「敌人当量」(头领记 3)比较,解锁表不动。
- Boss 层与随从不变。
- 仿真 / trace:遭遇生成变,trace sha 必变,记新基线。

## §3 斩首:杀头领 → 其余敌人减攻(方向 3)

- 头领(§2)或 Boss 阵亡时,其余存活敌人获得**慑(减攻)30%,2 回合**(按该敌人行动递减,与现有慑同口径;多源取最强)。
- 挂在 `ResolveDefeat`(所有死亡路径汇流点),写法参照余烬 `SpreadEmbers`;发事件后由「上状态」动效统一播放。
- 战斗内播报:头领阵亡时飘「斩首」(新文案一条,重跑字体子集)。

## §4 敌人档位 chip(小怪 / 精英 / 头领 / Boss)

- 敌人格**第一行**(名字 + 属性徽章那行)新增一枚档位 chip(用户 10-18):
  - **小怪**:普通层杂兵、Boss 层随从;
  - **头领**:§2 的小头领;
  - **精英**:精英层(第 5 / 15 / 25… 层)的 Boss(`eliteIdiomBosses` / `EliteBossPool`);
  - **Boss**:主题 Boss 层的 Boss。
- Core 给 `EnemyDef` / 敌人状态加档位字段(`EnemyTier`),由生成处写入;详情弹窗同步显示。
- **这是新 UI 元素,按项目规则先交 `designer` 出稿**(含两档屏比下第一行宽度验算:Boss 列、16:9 前排小怪格最窄),拍板后再实现 Presentation。
- Core / 数据部分(§1–§3、§5 与 §4 的档位字段)不等设计稿,先行实现;chip 未落地前,头领只在详情弹窗写明。

## §5 技能树:广纳改条件、兼收 → 「斩获」

- **广纳**(wide_1):回合开始掉字时,**字库 ≤ 1 张**则本回合多掉 1 张(原:字库为空才触发)。
- **斩获**(wide_2,替换兼收,节点 id 不变、存档无影响):**击杀敌人时掉 1 张字进字库,每回合至多 2 张**;字库满则不掉(不进替换流程)。
  - 任何来源的击杀都算(出字、木灵、灼、流血)。
  - 抽字走独立随机流(同折桂 `GrantChar` 的 `_traitRandom`),不让主随机序列平移。
  - 抽取范围与回合开始掉字相同(已解锁卡池均匀抽)。
- 新 `PerkEffect`(wide_1 与 wide_2 不再共用一个效果相加);`PerkInfo` 名称 / 描述 / 详情三处同步;文案改「广纳」描述、「斩获」名与描述,删兼收文案;重跑字体子集。
- 名字备选:斩获(推荐)/ 收锋 / 拾遗。
