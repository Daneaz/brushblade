# 群攻入口 · 战场 3×2 · 双字头领 · 斩首 · 广纳 / 斩获 — design

日期:2026-10-18 ・ 状态:待用户审阅
上游:Plan F「群体攻击占比」「后期只能靠群攻」(`specs/2026-10-16-PlanF-议题清单.md`)。用户 10-18 拍板:先试方向 2(各系群攻入口)+ 5(混编),
加方向 3 的「杀头领 → 其余减攻」;技能树「兼收」换成击杀掉字(新名),「广纳」改为字库 ≤1 时多掉 1 张。

## §1 各系群攻入口(方向 2)

**现状**:本体攻击面带范围的只有 火 6 / 水 2 / 土 2(崩 全体、㙓 释放厚);金、木 0。金木土的范围都在 Lv5 / Lv8 特性里(剑 横扫千军、锥 锥心、楸 秋风扫叶、森 林深、碎 碎石…),前中期摸不到。

**改为**:金、木、土各给 2 个字的**本体攻击面**改成群体范围(Lv1 起就有)。数值按 spec A §2 范围系数:单体 1.0 / 群体(横扫、贯穿、溅射)0.75 / 全体 0.5,
即 蓝字锚值 90 → 群体 68。范围内每个目标都吃同一数值(`ShapePercent 100`)。

| 系 | 字(稀有度) | 本体改为 | 本体伤害 | 原同范围特性的处理 |
|---|---|---|---|---|
| 金 | 剑(蓝) | 横扫 Row | 90 → 68 | Lv8 横扫千军 Row 50 → 改为「全体 67」 |
| 金 | 锥(蓝) | 贯穿 Column | 90 → 68 | Lv8 锥心 Column 70 → 改为「全体 67」 |
| 木 | 箭(蓝) | 贯穿 Column | 90 → 68 | Lv8 万箭齐发(散射)不变 |
| 木 | 楸(紫) | 横扫 Row | 133 → 100 | Lv8 秋风扫叶 Row 60 → 改为「全体 67」 |
| 土 | 碎(蓝) | 溅射 Adjacent | 90 → 68 | Lv5 碎石 Row 50 → 改为「全体 67」(碎石落满场) |
| 土 | 垒(绿) | 横扫 Row | 62 → 46 | Lv8 劈山 Row 50 → 改为「全体 67」 |

- 「全体 67」= spec A 全体系数 0.5 ÷ 群体系数 0.75 ≈ 67%:本体已是群体值,升全体后每个目标(含主目标)落到全体锚值(如 剑 68 → 45),换覆盖全场,不再是「群体 × 50%」的双重压低(10-18 控制方裁定)。秋风扫叶原 `hitPercent 60` 是横扫版的主目标折扣,随形状去掉;锥 Lv8 叠 Lv5 连斩照现有规则叠乘。
- 垒 绿档群体取 spec A §2 表值 46(锚点 88 × 0.7 × 0.75 = 46.2),不按 62 × 0.75 = 46.5 → 47 算。
- 选字原则:字义贴范围(剑扫、锥穿、箭穿、秋风扫、碎石溅、垒成排),优先蓝及以下(前期能拿到),每系一横一纵 / 溅。
- 改动走数据管线:`技能机制详表.md`(本体)+ `特性表/{金,木,土}.md`(特性)→ `extract_values` / `export_chars`。`SpecAAlignmentTests` 补「群体 0.75」口径。
- 字卡文案由现有范围词条自动生成(横扫 / 贯穿 / 溅射已有),不新增文案。
- 验收:快档重跑,报各系群攻占比(本体)与单系卒层变化;群攻占比进 Plan F。

## §2 战场改 3 × 2:敌人数上限 8 → 6、格子加宽(方向 1,用户 10-18 追加)

- 敌方战场由「4 列 × 2 排 = 8 格」改为 **3 列 × 2 排 = 6 格**;`EnemyCap` 8 → 6,`Targeting.RowCapacity` 4 → 3,`ColumnOrder` 改为居中优先的 3 列顺序。
- 普通层敌人数 `MinionCountFor = 1 + min(5, (depth−1)/6)`:31 层满 6 只(原 43 层满 8)。
- **格子加宽**:每格宽 = 战场宽 / 3(原 / 4),状态栏(chip 行)跟着变宽;立绘尺寸、字号、行数的具体值交设计稿定(§6)。
- **我方召唤槽同步 8 → 6**(`SummonCap`),解锁表改为与新 `MinionCountFor` 逐层对齐(1 / 7 / 13 / 19 / 25 / 31 层各开一槽,槽位顺序随新布局定),
  「召唤物不超过本层敌人数」两条对账测试照守。召唤格布局同改 3 × 2。
- **Boss / 精英 / 头领都只占上下两格**(1 列 × 2 排,原 Boss 为 2 列 × 2 排);`BossColumnSpan` 2 → 1。随从上限 = 6 − 2 = 4(`EscortCap` 不变)。
  立绘按 1 列宽的竖块重排(§6)。
- 横扫 / 贯穿 / 溅射等范围按新格位自然生效(3 列一排、2 排一列);依赖 4 列的测试数据同步改。
- 存档无需兼容(项目未上线):带 7–8 只召唤物的旧快照直接作废。
- 经济:击杀墨锭按只计,敌人数下降 → 后期墨锭收入下降;`economy_model.py` 同步并报差额,是否补偿(层墨锭上调)由用户看数后定。

## §3 头领:双字讹熔小头领 + 混编(方向 5)

- **概念**(用户 10-18 采用):敌人档位与字数挂钩 —— 小怪单字、**头领两字词语讹熔**、Boss / 精英四字成语讹熔。
- **头领名单**(用户 10-18 采用候选):字林 朽木 / 荆棘;朱砂 烽燧 / 余烬;文山 碑碣 / 磐石;金石 钟鼎 / 刀笔;墨海 漩涡 / 浊浪。
  词渊(51 层起)为全池混合段,头领同样全池随机:十只全收(2026-10-18 用户 bugfix)。
  ⚠ 「荆棘」与词条「荆棘」、「余烬」与火系技能「余烬」同名:敌人名不进词条扫描,技能名只在技能树出现,判断不冲突,实现时核对一遍。
- 每只头领是独立的 `EnemyDef`(新入 `enemies.json`,段落新增 `leaderPool`),有自己的生命 / 攻击 / 护甲,可带一个**现有**的 `EnemyAbility`(不新增能力),占上下两格。
- **必须弱于本段 Boss**:头领生命 ≤ 本段 Boss(同深度缩放、各阶段生命合计)的 50%,攻击 ≤ 本段 Boss 各阶段攻击的最大值;对账测试遍历全部段落断言。
  起值:生命 ≈ 本段小怪均值 × 2.5、攻击 ≈ 本段小怪均值 × 1.3(再受上面两条约束),F3 定标再调。
- **出场**:普通层,敌人数 ≥ 3 时(13 层起)每层 1/3 概率出头领,25 层起必出;出头领时遭遇 = **1 头领 + (MinionCountFor − 2) 只小怪**(头领占 2 格,总占格 = MinionCountFor)。
  字林(1–10 层)因此见不到头领,其名单为日后循环 / 调参保留。
- 经济:头领击杀墨锭 ×2(与占格相当)。
- 头领随深度缩放,用普通层的缩放口径(`ScaleFor`)。
- 仿真 / trace:遭遇生成变,trace sha 必变,记新基线。

## §4 斩首:杀头领 → 其余敌人减攻(方向 3)

- 头领(§3)、精英或 Boss 阵亡时,其余存活敌人获得**慑(减攻)30%,2 回合**(按该敌人行动递减,与现有慑同口径;多源取最强)。
- 挂在 `ResolveDefeat`(所有死亡路径汇流点),写法参照余烬 `SpreadEmbers`;发事件后由「上状态」动效统一播放。
- 战斗内播报:头领阵亡时飘「斩首」(新文案一条,重跑字体子集)。

## §5 敌人档位 chip(小怪 / 精英 / 头领 / Boss)

- 敌人格**第一行**(名字 + 属性徽章那行)新增一枚档位 chip(用户 10-18):
  - **小怪**:普通层杂兵、Boss 层随从;
  - **头领**:§3 的双字头领;
  - **精英**:精英层(第 5 / 15 / 25… 层)的 Boss(`eliteIdiomBosses` / `EliteBossPool`);
  - **Boss**:主题 Boss 层的 Boss。
- Core 给 `EnemyDef` / 敌人状态加档位字段(`EnemyTier`),由生成处写入;详情弹窗同步显示。
- **这是新 UI 元素,按项目规则先交 `designer` 出稿**(含两档屏比下第一行宽度验算:Boss 列、16:9 前排小怪格最窄),拍板后再实现 Presentation。
- Core / 数据部分(§1–§4、§7 与本节的档位字段)不等设计稿,先行实现;chip 未落地前,头领只在详情弹窗写明。

## §6 战场布局设计稿与头领立绘

- **交 `designer` 出稿**(一份稿覆盖):敌我战场 3 × 2 加宽格、Boss / 精英 / 头领 1 列 × 2 排竖块、§5 档位 chip;两档屏比(基准机 ≈1951 宽、16:9 1600 宽)逐栏验算 chip 行能放下几枚。
  拍板后实现 Presentation;拍板前 Core 先行,Presentation 只做「能编过、不崩」的最小适配(列数改常量)。
- **头领立绘**:在 `tools/design/build_boss_art.py` 上加双字变体(两字各一层、运行时着色、讹熔成团),画幅为 1 列 × 2 排竖块;
  先出 1 张样张给用户看风格,确认后批量生成 10 张。Boss / 精英现有立绘随竖块重新裁切或重排(由设计稿定)。

## §7 技能树:广纳改条件、兼收 → 「斩获」

- **广纳**(wide_1):回合开始掉字时,**字库 ≤ 1 张**则本回合多掉 1 张(原:字库为空才触发)。
- **斩获**(wide_2,替换兼收,节点 id 不变、存档无影响):**击杀敌人时掉 1 张字进字库,每回合至多 2 张**;字库满则不掉(不进替换流程)。
  - 任何来源的击杀都算(出字、木灵、灼、流血)。
  - 抽字走独立随机流(同折桂 `GrantChar` 的 `_traitRandom`),不让主随机序列平移。
  - 抽取范围与回合开始掉字相同(已解锁卡池均匀抽)。
- 新 `PerkEffect`(wide_1 与 wide_2 不再共用一个效果相加);`PerkInfo` 名称 / 描述 / 详情三处同步;文案改「广纳」描述、「斩获」名与描述,删兼收文案;重跑字体子集。
- 名字备选:斩获(推荐)/ 收锋 / 拾遗。
