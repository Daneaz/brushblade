# 奇遇重平衡与扩充(2026-10-21)

> 状态:待审。2026-10-20 已落地的前置:字摊按层拆两档(`EventDef.MinDepth/MaxDepth`)、淬骨两档、赌书观战 HP +300。

## 1. 目标

- 每个奇遇的前两个选项**战斗价值对等**,不再有「几乎没人选」的选项。
- 选项 3 统一为**离开**(三个负面奇遇例外,见 §3.5)。
- 新增 7 个奇遇:其中 2 个只在 25 层起出现,3 个是负面奇遇。
- 奇遇分 4 级,级数越大越难抽到(§4.4)。
- 触发概率下调,并加**每段保底**。

## 2. 对等原则

两种写法,每个奇遇的选项 1 / 2 二选一:

- **同价不同货**:付一样的代价,换不同的东西(例:HP −200 换橙字 / 换上限)。
- **同货不同价**:拿一样的东西,付不同的代价(例:舍 1 部件 / HP −100 换同一批金字)。

固定数值的回血不随上限增长,所以**不拿回血去对位按百分比涨的上限**(换气 2026-10-20 用户指出)。

字池记号:**金字** = 鍂 / 林 / 冰 / 炎 / 圭;**橙字** = 鑫 / 森 / 淼 / 焱 / 垚(与原字摊同一批)。

### 3.5 负面奇遇为什么没有「离开」

拦路虎、瘴林、查禁是纯损失奇遇:三个选项都是代价,玩家挑最不痛的。三个奇遇的选项 3 都是只扣血,
扣血至少留 1 点(现有规则),所以任何时候至少有一个选项可选,不会卡住。
三者的代价组合各不相同:拦路虎 = 部件 / 字 / 血,瘴林 = 部件 / AP / 血,查禁 = 字 / 墨锭 / 血。

负面奇遇按 §4.4 的权重,1~24 层占触发次数的 (4 + 3 + 2) / 56 ≈ 16%,25 层起 ≈ 15%。保底强制出的那次照常从全池按权重抽,也可能抽到负面奇遇。

## 4. 新机制

### 4.1 下一战首回合 AP −1(药铺、瘴林)

- `EventOption` 加 `NextBattleSeal`(int,AP 扣减量)。
- 复用现有 `StatusKind.Seal`(Boss「封字」用的那个:`StartTurn` 时 AP −Magnitude,下限 1):开下一场战斗时给玩家挂 1 回合、Magnitude = 1 的 Seal。
- 表现层已有 Seal 的状态 chip(BattleView 封字 debuff),不新增 UI。
- 待挂的 Seal 跨「奇遇 → 选字 → 下一战」与续爬存档都要保住:进 `RunSnapshot`;若奇遇发生在段内最后一个非 Boss 层,下一战仍在本段(Boss 层),不跨段。

### 4.2 舍 1 字(拦路虎、查禁)

- `EventOption` 加 `LibraryCost`(int)。
- 玩家点选字库里要舍的那张,**复用**现有满库替换的点选流程(`DrawEventReplaceStep` / `replaceLibraryIndex`),不新增界面。
- 字库只剩 1 张时该选项不可选(与部件不足同一套置灰)。

### 4.3 触发概率与每段保底

- `eventChance` **40 → 30**。
- **每段(5 层)至少一次**:Boss 层不掷,一段只有 4 次机会;若本段前 3 次都没中,第 4 次(段内最后一个非 Boss 层)**必中**,不掷概率骰。
- 计数「本段已出过奇遇」进 `RunSnapshot`,段中续爬时保住;每段开头清零,不进跨段存档。
- 从段中续爬时(`FromDepth` 不在段首),保底仍按**整段**算 —— 段首到断点之间是否出过奇遇由快照里的计数给出。
- 首塔剧本段(`BuildFirstTowerSegment`)同样适用。

### 4.4 奇遇分级与抽取权重

触发奇遇后,从当前层可出现的奇遇里**按等级加权**抽一个(取代原来的等概率):

| 等级 | 权重 | 奇遇 |
|---|---|---|
| 1 | 4 | 篝火、宝库、换气、废稿堆、赌书、淬骨、当铺、拦路虎 |
| 2 | 3 | 测字先生、墨池、书院、残碑、养气、瘴林 |
| 3 | 2 | 字摊、药铺、查禁 |
| 4 | 1 | 老字号、古战场、炼字炉(都是 25 层起) |

- `EventDef` 加 `Tier`(1~4),配置里每个奇遇写 `tier`;等级 → 权重的映射是 Core 里的常量表,不进配置。
- 漏写 `tier` 视为配置错误:加载时报错,不默认成某一级(真实配置测试兜底)。
- 抽取走 run 主 RNG:`_random.Next(总权重)` 落到哪个奇遇的区间就是哪个,一次调用,与原来等概率时消耗的随机数个数相同。

已经触发奇遇时,单个奇遇被抽中的概率:

| 等级 | 1~24 层(总权重 56) | 25 层起(总权重 59) |
|---|---|---|
| 1 | 7.1% | 6.8% |
| 2 | 5.4% | 5.1% |
| 3 | 3.6% | 3.4% |
| 4 | — | 1.7% |

按每层约 29% 的触发频率(§4.3 每段 1.44 次 ÷ 5 层)折算,每层遇到某个 1 级奇遇约 2.1%,4 级约 0.5%。

每段期望奇遇数:改前 4 × 0.4 = **1.6**,且有 13% 的段一次都没有;改后 3 × 0.3 + 0.343 × 1 + 0.657 × 0.3 ≈ **1.44**,没有空段。

## 6. 测试(Core / Data,TDD)

- `NextBattleSeal`:选了之后下一战首回合 AP = 2、第二回合恢复 3;中间隔着选字、续爬快照往返都不丢。
- `LibraryCost`:舍掉玩家指定的那张;字库 1 张时选项锁定;未给下标时拒绝。
- 保底:概率设 0 时,每段第 4 次机会必出奇遇;前面出过一次则不再强制;段中续爬按快照计数判定。
- 权重:同种子下大样本抽取频率与 4:3:2:1 相符(容差内);只剩一个可出现的奇遇时必抽到它;层数门槛先过滤、再加权。
- 真实配置:20 个奇遇 id 唯一、每个都有 1~4 的 `tier` 且与 §4.4 一致、层数门槛与 §3.4 一致、每个奇遇选项 3 为离开(三个负面奇遇除外)、`EventLabelWidthTests` 照旧通过。
