# Plan F1 · 仿真搜索机器人 — design

日期：2026-10-14 ・ 状态：待用户审阅
上游：Plan F 立项讨论（2026-10-13）；`docs/superpowers/specs/2026-10-03-字卡五特性体系-design.md` v7；E4 的 `EstimateCast`；`docs/superpowers/specs/2026-10-13-护盾回合保留与木灵替换-design.md`（替换木灵）。

## 0. 背景与已拍板的前提

Plan F 拆三段：**F1 仿真机器人**（修尺子）→ F2 机制裁定 → F3 数值定标。本文只管 F1。

用户拍板（2026-10-13）：
- **F3 只做相对校准**：五系拉平、同档特性对齐、修明显错价；不定绝对卒层目标，等试玩。F1 因此只需让读数**可信、可解释**，不追某个绝对值。
- **机器人用试算打分**，不再用手写价目表（`tools/balance` 的 `Power()` / `CardValue()`）。
- **整回合搜索**（不是单步贪心）。
- **速度分两档**：快档（日常）+ 慢档（定标拍板前），并报两档差。

现状问题（为什么要换）：
- `Power()` 只读字的本体效果，**完全看不到特性**；Lv5 / Lv8 读数里的特性贡献是「碰巧出了这张字」。
- 选面只有一条血线规则 +「身上有盾就出攻面」。护盾改为战斗内常驻（2026-10-14）后，后一条让木字几乎不出生面召唤：木混·木土 Lv5 卒层 24.9 → 20.3，召唤出字减半 —— 是机器人自缚，不是平衡。
- 不拆字、不嫁接、不替换木灵、召唤位满时白扣 AP。
- 跨段携带与生产不一致：没带 `CarriedHp`（胜利回血）、`MaxHpBonus`、字库 / 部件池扩容标志。

## 1. 架构

- 新机器人写在 `tools/balance/Bot/`，按职责拆文件：
  - `Candidates.cs`：候选动作生成；
  - `Search.cs`：整回合搜索（剪枝、转置表）；
  - `Evaluator.cs`：局面打分；
  - `CardAppraiser.cs`：局外字估值（参考局面，带缓存）；
  - `BotRunner.cs`：一局爬塔的驱动（取代 `Program.cs` 里的 `PlayTurn` / `ResolveDropChoice` / `PickBestReward`）。
- 只读 Core 的 public 接口：`Capture()` / `Restore()`、`Cast(..., dropMode)`、`Dismantle` / `Compose`、`EstimateCast`、`CanGraftAt` / `CanReplaceAt`、`CardFaceRules.Landing` 等。若缺「列出某字某面全部合法落点」这类只读查询，在 Core 纯追加（public、不改结算）。
- **trace 机器人不动**：它是恒等基线，换机器人等于换基线。trace 两档 sha 必须不变。
- 旧机器人保留开关 `--legacy-bot`，仅用于新旧读数对照；F1 合并后另开一项删除。
- Core 若有改动：coretests 全绿、prescompile、`tools/balance` / `chestsim` / `trace` 三工装 build、trace 两档恒等。

## 2. 每回合搜索

### 2.1 候选动作

在当前状态下列出：
- **出字**：手牌字与可出的部件（叶子）× 可用的面 × 合法落点（敌人各格、自己、木灵各格、召唤空位）。
- **对活木灵**：嫁接、**替换该格**（`SummonDropMode.Graft / Replace`，用 `CanGraftAt` / `CanReplaceAt` 判可行）。
- **拆字**、**合字**（`ForgeEngine.Suggest` 给出的可合目标；需腾位时「弃最弱一张 + 合」算一个复合动作）。
- **结束回合**。
- 不列：AP 不够的、落点不可落的、已知会被拒的（以 Core 返回 `BattleError` 为准，副本上执行被拒即剪掉）。

### 2.2 展开与剪枝

1. 对当前状态 `Capture()`；每个候选在 `Restore` 出的副本上真执行一次，得到子状态。
2. 子状态按「到这一步为止的局面分」（§3，不跑敌人回合的快速版）排序，**每层只留前 K 个**继续展开。
3. 展开到 AP 用完、或选了「结束回合」为止，形成完整的回合序列（叶子）。
4. 叶子用 §3 的完整打分（含敌人回合）。选总分最高的序列。
5. **转置表**：同一局面只展开一次。局面键 = 字库、部件池、AP、玩家与各单位血量 / 护盾 / 状态摘要、木灵布局的哈希。
6. 档位：**快档 K = 4**，**慢档 K = 12**。另设每回合叶子数上限（快档 256、慢档 4096）防爆。

### 2.3 执行与重搜

- 选出的序列在本体上逐步执行。每执行一步，若本体结果与副本预期不同（暴击、击杀导致目标变化、随机落点不同），从当前状态**重新搜索**剩余 AP。
- 副本上暴击按不暴击算（与 `EstimateCast` 同口径）；随机落点用副本自身的随机流。

### 2.4 防偷看未来

叶子跑敌人回合的副本，把 RNG 换成**固定的新种子**（由「种子 + 层 + 回合」派生，不取自本体），机器人看不到本体接下来会摇出什么（闪避、敌人择目标）。同一局面多次评估结果一致（确定性）。

## 3. 局面打分

### 3.1 完整打分（叶子）

在副本上执行「结束回合 → 敌人回合 → 停在下一个玩家回合开始」，再对那个局面打分：
- **战斗已赢**：`+1,000,000 − 已用回合数`（越快赢越好）。
- **玩家已死**：`−1,000,000`。
- 否则 `Score = 进攻 + 生存 + 蓄能`：
  - **进攻**：Σ 各敌人损失血量占比 × 100；每打倒一只 +50。
  - **生存**：(玩家剩余血量 + 护盾) / 最大血量 × W；+ Σ 存活木灵 (血量 + 护盾) / 其最大血量 × W/2。W：玩家血线（不含盾）> 50% 时 80，≤ 50% 时 200。
  - **蓄能**：厚、泉、战意、各 1 层 +3。

护盾、治疗、减速、冻结、嘲讽、反击、木灵挡刀的价值，都体现在敌人回合打掉的血上，**不给任何状态单独定价**。

### 3.2 快速打分（中间层排序）

同 §3.1 但不跑敌人回合，生存项用当前值。只用于剪枝排序，不决定最终选择。

### 3.3 常数

上述常数（100、50、80 / 200、3、W/2）是 F1 的初值；F1 内允许做一次「常数灵敏度」检查（各 ±50% 看卒层变化），结果写进执行记录，不追求调到最优。

## 4. 局外选择与生产对齐

### 4.1 字的估值（`CardAppraiser`）

- 每张字在一个**参考局面**里试算：当前层段深度的一组标准敌人（按 `EndlessGenerator` 该深度的普通战编成，取固定种子）+ 满血玩家 + 无木灵。
- 对该字两面 × 全部合法落点各 `EstimateCast` 一次，取最好的一下，用 §3.2 快速打分（进攻 + 生存）记分。
- 结果按「字 × 卡等级 × 层段」缓存。旧 `CardValue` / `Power()` 在新机器人里**不用**。

### 4.2 用途

- **战利品 5 选 2**、**回合掉字换入**：估值高于字库最弱一张则换入（与旧口径同型，只换估值来源）。
- **弃字**：只作为合字复合动作的一部分，弃估值最低的。
- **奇遇**：沿用 `ChooseBestEvent`。
- **安全层**：永不撤退（测能爬多深）。

### 4.3 跨段携带对齐生产

照 `GameRoot.WriteCarriedSnapshot` 口径：字库、部件池、`CarriedHp`（含胜利回血）、`MaxHpBonus`、`LibraryExpanded` / `PoolExpanded`、开局效果。**不带木灵和护盾**（生产不带）。

## 5. 输出

读数表保留现有列，新增：
- 每局拆字 / 合字 / 嫁接 / **替换**次数；
- 两面各自出字占比；
- 每张字被打出次数 Top 10 / Bottom 10（给 F2 / F3 找空转与过强）；
- 卡等级 Lv1 / Lv5 / Lv8 三列一次跑完；
- 慢档额外一列「与快档的卒层差」；
- 每档实测耗时。

命令行：`dotnet run -c Release -- [--slow] [--legacy-bot] [--profile <名>] [--seeds N]`。

## 6. 并发与确定性

- 种子之间独立，按 CPU 核数并发（`Parallel.For` 或等价）。每个种子的局内状态、RNG、缓存互不共享（`CardAppraiser` 缓存可共享但须线程安全且结果与顺序无关）。
- **同一种子单线程与并发跑，卒层逐位相同**。

## 7. 验证与完成标准

**测试**：新建 `tools/balance.tests`（NUnit，可 TDD，不进 Unity 程序集）：
- 候选生成：面、落点、拆、合、嫁接、替换都列全，不合法的不列。
- 搜索：在造好的小局面里找到已知最优序列 —— 「先破甲再打伤害」「先合再出」「把后排花替换成林」。
- 打分：赢 / 死 / 血线 W 切换边界；蓄能项。
- 不偷看：换本体 RNG 状态后搜索结果不变。
- 确定性：同一种子单线程与并发卒层相同。
- 估值缓存：同输入同结果；顺序无关。

**完成标准**：
1. **僵局判死**：全部画像 ≤ 5 / 300。
2. **不比旧机器人笨**：每个画像、每个卡等级的均卒层 ≥ `--legacy-bot` 读数；木混·木土须回到护盾改动前（Lv5 ≥ 24.9）附近或更高。不满足视为搜索或打分有 bug，先查再合。
3. **会用新动作**：木系画像每局有嫁接或替换；含字形特性的画像（火、土）每局有拆合。
4. **变异检查**：把一张常用字某条 Lv5 特性数值临时置 0，该字出字次数与画像卒层都可见下降（证明机器人「看得见」特性）。
5. **速度**：快档整轮 ≤ 5 分钟、慢档 ≤ 30 分钟（8 核机实测），报告实测值；超了先降 K / 叶子上限。
6. **恒等**：trace 两档 sha 不变；Core 若有改动 coretests 全绿。

## 8. 不做的

- 不调任何数值（F3），不改机制（F2），不改 trace 机器人。
- 不追求「最优玩家」：剪枝搜索 + 固定常数，够用即可，慢档与快档的差就是对「剪枝让机器人变笨多少」的度量。
- 合并时只报新读数，作为 F2 / F3 的起点；护盾改动的 7 条 Plan F 观察项在新读数下复核，结论交 F2。
