# 子项目 A:状态操作族 — 设计

**日期:** 2026-08-06
**范围:** 详表 §7.2 的 P1 `Dispel`/`Immunity`/`Execute` 与 P2 `Cleanse`/`Revive`,共 14 字
**目标:** 字表可用字数 109 → 123;并给引擎补上**敌方施加给玩家的减益**这一整类缺失

---

## 一 · 背景:一半的机制没有靶子

探索期确认的事实,它决定了这个子项目的形状:

| 机制 | 靶子 | 状况 |
|---|---|---|
| 驱散(清敌方增益) | 敌方 `AttackBuff`(标点小妖加攻 / 焦痕自燃) | ✅ 有 |
| 斩杀(残血加伤/处决) | 敌人血量 | ✅ 有 |
| 复活(救阵亡召唤物) | `_summons` 里的死尸(**从不移除**) | ✅ 有 |
| **净化(清玩家减益)** | **无** | ❌ |
| **岿「免疫位移与控制」** | **无** | ❌ |

玩家侧的 `_playerStatuses` 至今只装过 `DamageReduction` 与 `HealOverTime`,**两个都是增益**。
引擎里不存在任何敌方施加给玩家的减益,所以「浴 · 清除全部异常」会清出个寂寞;
「岿 · 免疫位移与控制」里位移机制不存在,冻结/减速则是玩家打敌人的方向。

2026-08-06 拍板:**本子项目顺带补上玩家侧减益**,让净化与免疫成立,
同时给深层无尽一个「敌人也会上状态」的对称性。

另有两条既有事实:

- `StatusBag.RemoveAll(StatusPolarity)` 在子项目 0 就建好了,**至今没有调用方** —— 它正是为驱散/净化预留的。
- 详表 §7.2 把 `烬` 列进 Execute 组,但 `烬` 自己那行已标 ✅ —— 它早就用 `DoubleVsBurning`
  (烧残补刀)落地了,不属于本子项目。故 Execute 实为 3 字而非 4 字。

## 二 · 敌人侧:两种玩家减益

### 2.1 `Seal`(封字)—— 既有效果状态化,零新内容

Boss「倾覆」(`BossSkill.Topple`)现在写的是 `_apPenaltyNextTurn = 1`,一个裸字段。
改成挂一条状态到 `_playerStatuses`:

```csharp
StatusKind.Seal          // Magnitude = AP 扣减量
Polarity = Debuff
```

`StartTurn()` 里 `Ap = Math.Max(1, _config.ApPerTurn - _apPenaltyNextTurn)` 改为读
`_playerStatuses.TotalMagnitude(StatusKind.Seal)`,`_apPenaltyNextTurn` 字段删除。

行为完全不变,但它现在**可被净化、可被免疫**,并且**跟着存档走**。

⚠ **`TurnsLeft` 必须填 2,不能填 1。** `EndTurn` 的顺序是
「…敌方行动 → 状态回合递减 → 玩家阵亡早退 → 判胜 → 缺笔妖补全 → `StartTurn()`」。
倾覆在敌方段挂的 Seal 若 `TurnsLeft = 1`,同一个 `EndTurn` 的递减就会把它减到 0 并移除,
`StartTurn` 读到 0 —— 效果凭空消失。填 2 才等价于现状(只影响下一个玩家回合)。
这条要有专门测试。

**顺带修掉一个既有 bug**:`_apPenaltyNextTurn` 从来没进过 `BattleSnapshot`,
倾覆之后存档续爬会白丢 AP 惩罚。状态化后它跟着 `PlayerStatuses` 一起存,自动修好。

### 2.2 玩家灼烧 —— 复用 `StatusKind.Burn`,不新增枚举

层数挂在 `_playerStatuses` 上,`EndTurn` 开头结算:`层数 × _burnPerStack` 掉血,然后 −1 层。

**不走生克** —— 玩家没有五行属性,敌人侧那条 `KeMultiplier(Fire, enemy.Element)` 不适用。

`TurnsLeft = -1`(段内持久,靠结算段自减 Magnitude),与敌人侧灼烧同口径,
所以 `TickTurns` 不会误减它。

### 2.3 新字怪「灯花」与新能力 `Sear`

```
{"id": "灯花", "element": "Fire", "maxHp": 12, "attack": 3, "ability": "Sear"}
```

`EnemyAbility.Sear`:每次攻击给玩家挂 1 层灼烧。

命名取自古人夜读时灯芯爆出的火星子,与既有字怪「错字鬼 / 缺笔妖 / 标点小妖 / 叠字怪 /
夯土妖 / 通假字 / 生僻字 / 墨渍 / 焦痕」这套「书写病症」的规律一致,火系也站得住。

**数值上是温和的持续压力,不滚雪球**:每回合挂 1 层、结算 −1 层,净 0,稳定在 1 层 = 2 伤/回合。
(子项目 C 的烓因为「每回合挂 3、只减 1」净 +2 而失控,那次教训这里先算过了。)

**形象不用现在做** —— `MobAssets.PrefixFor` 对未知敌人返回 `null`,`MobView` 为 null,
自动回落圆形字头像。图鉴条目与形象后补。

## 三 · 五种机制的口径

**驱散 / 净化 / 免疫 / 复活是四个新 `EffectKind`,不是修饰字段。** 因为 `灭`/`浴`/`塞`/`岿`/`杜`/`活`
这六个字**没有伤害效果可挂** —— 做成修饰字段就没有宿主。斩杀是唯一的例外:它本质上就是
伤害的修饰(「这一刀对残血目标更重」),所以它留作 `EffectDef` 的字段。

| 机制 | 表达 | 结算 |
|---|---|---|
| 驱散 | `EffectKind.Dispel`,`Value` = 条数(−1 = 全部);复用既有 `TargetAll` 定范围 | 对**敌人** `Statuses` 移除 Buff 极性条目 |
| 净化 | `EffectKind.Cleanse`(`Value` 不用) | 对**玩家** `_playerStatuses.RemoveAll(StatusPolarity.Debuff)` |
| 免疫 | `EffectKind.Immunity`,`Value` = 次数 | 新 `StatusKind.Immunity`,Magnitude = 剩余次数 |
| 复活 | `EffectKind.Revive`,`Value` = 复活几只 | 复活阵亡召唤物 |
| 斩杀 | `EffectDef` 新字段 `int ExecuteBelowPercent` + `bool ExecuteKills` | **打之前**判血 |

一个字的效果是一个 `EffectDef` 列表,所以组合天然成立:
削 = `[DamageSingle 9, Dispel 1]`,岿 = `[Immunity 1, Cleanse]`,澡 = `[HealSelf 12, Cleanse]`。

**管线侧的 token 映射**(`extract_values.py` 的通用正则是 `` `(\w+) (\d+)` ``,认不出负数):
详表里 `` `Dispel N` `` → `{"kind":"Dispel","value":N}`;`` `DispelAll` `` 作为**无数值布尔标记**
→ `{"kind":"Dispel","value":-1}`。无数值标记在子项目 C 已有先例(`OnHitBurnAll`)。

### 3.1 驱散

`Value = -1` → `RemoveAll(StatusPolarity.Buff)`;`> 0` → 从头移除至多 N 条 Buff。
`TargetAll = true`(淡)则对全部存活敌人各做一次,否则只对 `targetIndex`。

现存唯一靶子是敌方 `AttackBuff`(标点小妖给同伴加攻、焦痕受击自燃)。两者都是
`TurnsLeft = -1` 的永久增益且本场累计,所以驱散是真有价值的解法——尤其对焦痕
(越磨越烫)与多怪场的标点小妖。

驱散**只打敌人**。玩家自己的 `DamageReduction` / `HealOverTime` 也是 Buff 极性,
但它们挂在 `_playerStatuses` 上,不在驱散的作用域里。这条要有测试钉死。

### 3.2 净化

`EffectKind.Cleanse` → `_playerStatuses.RemoveAll(StatusPolarity.Debuff)`,清掉 Seal 与玩家灼烧。
不碰 Buff 极性的 `DamageReduction` / `HealOverTime`。

### 3.3 免疫

新 `StatusKind.Immunity`,`Polarity = Buff`,`Magnitude` = 剩余次数,`TurnsLeft = -1`(段内持久)。

**消耗点在 `DamagePlayerDirect` 的最开头,先于护盾**:若 `Magnitude > 0`,
`Magnitude -= 1`(归零即移除),伤害**完全不进**(不是减免),发一条事件供表现层表达,
直接返回。

「先于护盾」是刻意的:免疫是稀缺的一次性资源,让它去挡一记小伤而把护盾留着更亏。
玩家的预期是「免疫牌打出去,下一记不管多重都不疼」。

`SourceId` 用字 ID(同字不叠只刷新)——多次出同一张免疫牌不应无限叠层数。
不同字之间可叠(塞 + 杜 = 3 次),因为它们是不同来源。

因此袋子里可能同时有多条 `Immunity`。**剩余次数取 `TotalMagnitude(StatusKind.Immunity)`;
消耗时从第一条非零的扣 1,扣到 0 就移除那一条。**

### 3.4 斩杀

**打之前判血**,而不是打之后。理由:玩家看着血条就能决定出哪张;
打之后判定虽然更像「补刀」,但结果不可预期。

- `ExecuteKills = true`:目标 `Hp * 100 < MaxHp * ExecuteBelowPercent` 且**非 Boss** → 直接置 0 血,
  走正常的 `ResolveDefeat`。是 Boss 则退化成普通伤害。
- `ExecuteKills = false`:同样的阈值判定,命中则该次伤害 `× 2`。**这一支对 Boss 照常生效** ——
  免疫的只是「直接击杀」,不是「残血加伤」。

Boss 免疫处决是必要的——Boss 是一条总血池,25% 也是很大一截,一刀没掉太破坏节奏。
`Hp * 100 < MaxHp * ExecuteBelowPercent` 里的 `MaxHp` 是 `EnemyState.MaxHp`,
即 Boss 的**当前阶段上限**,不是 `Def.MaxHp`。

`DamageAll` 版本(剿)对**每个目标分别判定**,不是「全场统一按第一个目标算」。

### 3.5 复活

`_summons` 里的死尸**从不被移除**(引擎从来没有清理逻辑,表现层只是不画它们),
所以复活直接找第一个 `!Alive` 的槽位:

```
Hp = (MaxHp + 1) / 2      // 半血,向上取整
ActionMeter = 0           // 重新攒节拍,不继承死前的余额
Shield = 0                // 盾不跟着复活
Passive 保持原样           // 它是这只召唤物的身份
```

没有阵亡召唤物时**空放**(消耗 AP 但无效果),与「无敌人时出 AOE」同口径。
不做 `Cast` 前置拒绝——那需要一条新的 `BattleError` 与 UI 提示,不值当。

## 四 · 十四字

数值即最终值。已逐字核过相生「他生我」口径(配方原料需含**生本字属性**的那一系),
**无一吃 ×3**,故直接填最终值。

### 驱散 5 字

| 字 | 稀 | 系 | 配方 | 效果 |
|---|---|---|---|---|
| 淡 | 🟡金 | Water | 氵+炎 | `DamageAll 20` + 全体各驱散 1 条 |
| 湮 | 🟣紫 | Water | 氵+土 | `DamageSingle 20` + 驱散全部 |
| 灭 | 🟢绿 | Fire | 一+火 | 驱散单体全部增益(无伤害) |
| 削 | 🟢绿 | Metal | 刂+肖 | `DamageSingle 9` + 驱散 1 条 |
| 刮 | 🟢绿 | Metal | 刂+舌 | `DamageSingle 6` + 驱散全部 |

**削 / 刮 的撞车靠机制拆开**:详表 §7.4 把这两字列进「建议暂缓入池」正因为降级后
完全相同(都是 `DamageSingle 9`)。现在削 = 伤 9 + 驱散 1 条,刮 = 伤 6 + 驱散全部——
刮得干净,打得轻。撞车前提消除。

| 字 | 稀 | 系 | 配方 | 效果 |

| 杜 | 🟣紫 | Wood | 木+土 | 免疫 2 次伤害 |

| 塞 | 🟢绿 | Earth | 宀+土 | 免疫 1 次伤害 |

**岿 不需要新字段**。详表原写的「免疫位移与控制」没有靶子,改成「免疫 1 次伤害 + 立即净化」——
正合「岿然不动」:稳如山,顺手把身上杂七杂八抖掉。蓝档 = 绿档(塞)+ 绿档(浴)的合体,

## 五 · 新部件 10 个

`则 廉 肖 舌 巢 谷 归 宀 一 喿`。全部配方经查**无一与既有字撞车**。

两处走 `export_chars.py` 的 `MANUAL_RECIPES` 人工兜底(该表在子项目 C 为「荆」建立):

- **塞 = 宀+土**,而不是 IDS 的 `⿱𡨄土`。`𡨄`(U+21A04)是增补平面,
  `_blocked_smp_part` 会因此把 塞 整个降级成不可拆的叶子(只能靠掉落获得)。
  换成常见部首 `宀` 直接绕开。
- **湮 = 氵+土**,而不是 `⿰氵垔`。`垔` 的核心就是土,义通(水土掩埋),且**零新部件**。

只剩 `喿`(澡 = 氵+喿)一个生僻部件:`氵+木` 已被 `沐` 占用,引擎又不支持三部件配方
(全表 188 条无一例),没有干净替代。它至少是 BMP,渲染得出来。

## 七 · 表现层

**玩家侧状态条**现在只画护盾,要加:`封字`(AP 扣减)、`灼烧{N}`、`免疫{N}`。

**免疫触发**要有反馈——`DamagePlayerDirect` 里免疫吃掉一记时发一条事件,
表现层播一次挡格表达(复用既有护盾吸伤的飘字样式即可,不做新动效)。

**驱散**不做新动效:敌人 chip 的 `攻 {N}` 本就读实时攻击力,增益被清掉数字自然回落。

**新字怪「灯花」**无形象,自动回落圆形字头像;图鉴条目照既有格式补一条文案。

⚠ UI 文案禁用 emoji(字体子集补不出来 → 空框),一律中文短词。
