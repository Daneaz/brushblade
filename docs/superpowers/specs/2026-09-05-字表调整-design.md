## 1 · 移除 17 字

劈 战 刺 铠 · 杖 松 柏 蕉 · 沝 淡 沏 · 碾 砸 · 烧 焦 灼 熣

处理方式同 2026-08-14 / 2026-08-25 两批:详表对应行标 `⚠ **2026-09-05 用户裁定移出字表**`
并保留原有数值记录,`extract_values` 不再抽取(标记由 ✅ 改 ⚠),chars.json 随之不产出。

### 1.1 连带消失的部件

部件条目由 `export_chars.build_chars` 从配方闭包反推,不再被引用的自动消失:

| 部件 | 原唯一用途 | 处理 |
|---|---|---|
| 戈 | 战 = 占 + 戈 | 自动消失;`ComponentKin` 金组同步删 |
| 刀 | 劈 = 辟 + 刀;切 = 七 + 刀 | 自动消失;`ComponentKin` 金组同步删 |
| 切 | 沏 = 氵 + 切 | `COMPONENT_RECIPES` / `COMPOUND_ATTR` 两处均删 |
| 崔 | 熣 = 火 + 崔 | `COMPONENT_RECIPES` 删 |

⚠ `ComponentKinTests.RealConfig_AllMembersAreLeavesInTheRealCharTable` 要求清单成员在真实
字表里**存在**且是叶子部件 —— 戈/刀 不从清单里删掉,这条守卫会红。这是本次唯一会自己
报警的连带改动,其余全靠人工对账。

`filter_chars.ATTR_MAP` 的 刀/戈 → 金 **保留不动**:那是管线侧的部件属性表(候选字筛选用),
与游戏内的等价清单是两回事,删了会影响 `out/candidates.json` 的历史可比性。

### 1.2 水系叠字链改 `淼 = 水 + 冰`

沝(🟡金·水·纯二叠)随本批移出,链中断。用户拍板由 **冰**(🟡金·水,冫 + 水)顶替中间环:

```
水 → 冰(冫+水) → 淼(水+冰) → 㵘(水+淼)
```

- `export_chars.STACK_RECIPES` 删 `沝` 条目、`淼` 改为 `["水", "冰"]`;`㵘` 不动。
- 淼 的五行部件展开仍是 `水 + 冫 + 水` = **3 个纯同系**,§1.1 判据下档位不变(🟠橙)。
- 代价:五系二叠字里水系不再有卡(林/炎/圭/鍂 仍在金档),叠字链的对称性破一个口。
  `淼 = 水 + 冰` 也不再满足「部件在前、低阶字在后」之外的「同系纯叠」形状 —— 冰 本身
  是 冫+水,语义上仍是「水上加水」,详表 §1.5 补一条例外说明。

## 2 · 新增 3 字

### 2.1 藻 · 🟠橙 · 木

| 项 | 值 | 依据 |
|---|---|---|
| 配方 | 艹 + 澡 | IDS 一级拆解,澡 是现有可出牌字(同 蕉 = 艹 + 焦 的形状) |
| 档位 | 🟠橙 | 五行部件展开 `艹 + 氵 + 木` = 3 个 → §1.1「3 个五行部件 → 橙」 |
| 效果 | `Summon 3`(260 血 / 攻 50)+ `Regen 60` | 橙档召唤锚点 3 × 260/100;第二个五行部件是 氵 → 治疗型系数 血 ×1.0 / 攻 ×0.5 |
| 拼音 / 释义 | zǎo / 水中丛生的绿色植物 | |

「治疗型」在 §3 的定位体系里配的是 `HealAlly`(给全队回血)。本字**由用户指定改为自愈** ——
召唤物每回合给自己回血,不外溢。这是继 蕉(艹+焦 该是灼烧型却做控制型)、杖(中性该是
平衡型却做治疗型)之后的第三个「第二五行部件定型」特例,同样由用户拍板。

### 2.2 箭 · 🟣紫 · 木

| 项 | 值 | 依据 |
|---|---|---|
| 配方 | 竹 + 前 | IDS 一级拆解;竹 由此进入字表(叶子部件,element Wood),前 是新的中性部件 |
| 档位 | 🟣紫 | 五行部件展开 `竹(木) + 刂(金)` = 2 个混系 → §1.1「混 2 → 紫」 |
| 效果 | `DamageSingle 200` | 紫档单攻锚点 200,无副效果故取满 |
| 拼音 / 释义 | jiàn / 弓弩发射的尖头长杆 | |

### 2.3 葬 · 🔵蓝 · 木

| 项 | 值 | 依据 |
|---|---|---|
| 配方 | **艹 + 死**(手写) | IDS 是 `艹 + 死 + 廾` 三部件,而全表 86 条配方**全是两部件**(一步合成 Mode A)。取 艹 + 死,草覆其尸,义形都通 |
| 档位 | 🔵蓝 | 只有 1 个五行部件(艹),落白/绿/蓝三档;词组「埋葬 / 葬送」的搭档字都不在表内 = 0 词,按 §1.2 该落白档 —— **用户指定上调蓝档**,记为语义特例 |
| 效果 | `DamageAll 70` | 蓝档全体锚点 70 |
| 拼音 / 释义 | zàng / 掩埋亡者 | |

⚠ 箭 / 葬 都是直伤,推翻 2026-08-25 的「木系转纯召唤」(棒 / 棍 当时正因此移出)。
第 5 章 §5.2 的木系描述需同步。

### 2.4 `ComponentKin` 木组加 竹

`{木, 艹}` → `{木, 艹, 竹}`。`filter_chars.ATTR_MAP` 早已有 `"竹": "木"`,无需改。
竹 靠 箭 的配方进入 chars.json;它自己不在 `COMPONENT_RECIPES` 里,故是叶子部件,
满足 `ComponentKinTests` 的守卫。

## 3 · 木系档位重排

木系白档在移除 柏 / 杖 后归零,而 `Meta.StartingCollection` 的口径是「五系 × 白/绿/蓝各一张」。
用户裁定**下调两张**填洞,而不是改口径:

| 字 | 档位 | 效果 | 依据 |
|---|---|---|---|
| 枪 | 🟢绿 → ⚪**白** | `Summon 1`(**24** 血 / 攻 **32**)+ `Skewer` + `ShapePercent 70` | 白档召唤锚点 1 × 40/20 × 攻击型系数 0.6/1.6;形状不变 |
| 藤 | 🔵蓝 → 🟢**绿** | `Summon 1`(**60** 血 / 攻 **30**)+ `OnHitFreeze 10` + `OnHitFreezeTurns 1` | 绿档召唤锚点 1 × 60/30 × 平衡型 1.0/1.0(艹 + 滕,滕 中性) |

- 藤 的冻结概率 10% / 1 回合**不随降档改动** —— 它在蓝档时就是锚点全额之外白送的边角,
  按 §1.4.1 的价目表本就没计价;降档后概率照旧,只有主数值跟着锚点走。
- ⚠ 枪 降白后与金系白档的 锥(24 血 / 攻 32)**主数值完全相同**,区别只在攻击形状
  (Skewer 贯穿 vs Volley 连发 2)与所属五行。这是本次自觉引入的一处同质,记录在案:
  白档攻击型召唤在两系各一张、形状不同,视为可接受;若日后判定为同质对,优先改 枪。

## 4 · 引擎改动:`SummonPassive.Regen`

本次唯一的代码新增,与 2026-08-25 加 `OnSummonFreeze` 同型。

1. **`Core/SummonPassive.cs`** —— `public int Regen { get; set; }`(每回合自愈点数,0 = 无),
   同步进 `Clone()`。它同时是存档 POCO,字段加进去即随 `BattleSnapshot` 往返。
2. **`Core/BattleEngine.cs`** —— 在**召唤物的回合末结算**处给自己回血,上限是自身
   `MaxHp`,不外溢给玩家或其它召唤物。落点与 `HealAlly` 那段相邻但独立:
   `HealAlly` 是「给玩家 + 全部存活召唤物」,`Regen` 只作用于持有者本身。
3. **`Data`** —— `passive` 对象的 `regen` 字段;`extract_values.SUMMON_PASSIVE` 加
   `"Regen": "regen"` 映射。⚠ 这张 token 表认不得的标记会**静默丢弃**,新字段务必核对。
4. **不吃卡等级**:回归 2026-08-05 的「被动数值是节奏、不随等级变」缺省。
   (吃等级的只有 藤 的冻结概率与 蕉 的减速两项,均为 2026-08-25 的显式例外,蕉 本次移出。)

**测试(先写后实现)**:
- `Regen_HealsOnlyItself_NotPlayerOrOtherSummons`
- `Regen_DoesNotExceedMaxHp`
- `Regen_SurvivesSnapshotRoundTrip`
- `Regen_ZeroIsNoOp`(缺省不改变任何既有行为)
