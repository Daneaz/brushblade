# 字卡详情说明区改版与木灵统一命名（spec B）

> 2026-10-15，来源：用户试玩反馈第 3、4、5、6、11 条。
> 设计稿（已拍板 · 待实现）：`docs/design/drafts/abilitytext/`（README 列定稿要点，`sheet-data.js` 为样例数据）。
> 机制与数值来自 spec A `2026-10-15-字卡两面对齐与数值归一-design.md`；**spec A 先合并**，本 spec 的版面才有完整数据可画。
> 标 **〔代拍〕** 的是用户授权「先替我做决定、明早对齐」后由 Claude 定的。

## 1. 版面（按拍板稿实现，第 3、4、11 条）

改动只在 `CharPreview` 的「技能说明区」，外壳（头、等级条、右栏、脚）不动。

1. **取色 A 案**：on 态正文 `text-quiet`；词条加粗、取本系 `<el>-fg`；数字 `text-main` 加粗；spent 全行 `text-dim`；off 不变。
   不新增 token，`tokens.json` 里 `text-quiet`、`<el>-fg` 的 usage 各补一句（并重跑 `build_ds_preview.py`）。
   `GlossaryText` 的高亮色改为按系传入。
2. **全平铺**：两面是同一张网格的两列，每一级（Lv1 / 3 / 4 / 5 / 6 / 8）两面各一行，同级左右并排、行高取两边较大值；两面效果相同时各写一遍。
   删除「两面」条：`SharedStrip`、`CompactRow` 及其调用；`FaceHeight` 改为逐级取大。
   某面缺该级（spec A 合并后不应出现）画「待补」斜纹占位，留作防御。
3. **数值格（每面第一行）**：攻击面只列「攻击」；五行面按系——
   金 反击 · 格挡次数 · 战意｜水 治疗（「涓」另列回合，「苏」列复活生命 %）｜火 慑 · 回合 · 灼｜木 木灵生命 · 木灵攻击｜土 护盾 · 护甲 · 回合。
   数值格不再出现 Lv1 特性格（删除只有图标的「本命」格）。
4. **Lv1 行**：两面都有。攻击面写本体关键词效果；五行面写本面 Lv1（木系写本命：本命 chip + 本命名 +「本命 · 被动」+ 当前等级效果句，左缘 2pt 朱砂）。
   花、藤、箭、柘的本命过去因无图标被整格跳过——Lv1 行不依赖图标，必须出现；无图标时不画 chip。
5. **名 + 图标**：每行行头在 Lv 标与名之间放 13pt 图标 chip（= 战场状态 / 本命 chip 的方形缩小版，同图标同底色）；无图标的行不画。
   `GlossaryBubble` 每条词条也带同一枚 chip，宽 248 → 262pt。点击粒度不变（整行 / 整格）。
6. **战斗版**（`SheetBattle`）：只列已解锁的级，未解锁的每面收成一行，与现状同。
7. 两档宽已由 designer 验算（一面字宽 基准 246.8pt / 16:9 190.2pt）；纵向超出走现有 ScrollList。

## 2. 木灵统一命名（第 5、6 条）

- 玩家可见文案里的召唤单位统一叫「**木灵**」：「召唤物」「藤灵」「小藻」「箭灵」「X 灵」等一律改为「木灵」；
  **「幼苗 / 苗」改为「小木灵」**（用户拍板）。
- `term.spirit.desc` =「木系召唤的单位」；`term.spirit.alias` 保留「召唤物」（兜底高亮）。
- 原「幼苗」词条改名「小木灵」，仍是独立词条（属性为本体 20% 的小木灵）；词表最长匹配保证「小木灵」不被拆成「木灵」。
- 敌人技能里的「召唤物」若指敌方召唤单位，〔代拍〕改为「召唤单位」，不叫木灵（木灵专指我方木系召唤）。
- 范围：`strings.zh-CN.json`、特性 / 效果名（chars.json 经管线）、设计稿数据不回改（稿已拍板）。
- Core 枚举名 `Summon*` 不改（非玩家可见）。
