# 设计:角色页 —— 统计 + 等级奖励(每级宝箱 / 里程碑)

> 2026-10-02 · brainstorming 产出 · 数值均首版基准可调
> 设计稿:画布「字·斗 角色页」https://claude.ai/artifact/Qx2iRapRifnQfeYzrLt7Fw(5 张:主界面 / 角色页 / 领取里程碑 / 升级弹窗 / 奖励表)
> 取代:`docs/design/ui/levelup/LevelChest.dc.html` 的「等级区间 → 宝箱」草案(本 spec 整体升一档、去掉素纸匣)

## 1. 目标

1. 新增**角色页**:执笔人属性 + 一组跨局累计的**统计** + **等级里程碑**领取。
2. 角色升级给奖励,两轨叠加:
   - **每级宝箱**:每升一级自动发一只,配升级弹窗。
   - **等级里程碑**:每 5 级一档(Lv.50 后每 10 级),在角色页**手动领**,给墨锭 + 字卡 3 选 1。
3. 主界面左栏角色面板整块可点进角色页;底部「卡池 N 字」摘要换成「出手最多 Top10」。

非目标:不改等级曲线、不改属性曲线、不改宝箱内容与保底规则、不做称号/外观。

## 2. 数值

### 2.1 每级宝箱(自动发,确定性,不掷随机)

| 升到 | 宝箱 |
|---|---|
| Lv.2–5 | 竹简匣 |
| Lv.6–10 | 青瓷匣 |
| Lv.11–20 | 紫檀匣 |
| Lv.21–30 | 鎏金匣 |
| Lv.31–40 | 朱漆匣 |
| Lv.41+ | 赤霄匣 |

升 n 级就发 n 只(每级按**它自己**那一级查表)。发的宝箱是普通宝箱:进箱位、计时、开箱时照常推进保底计数。

### 2.2 等级里程碑(角色页手动领)

| 等级 | 墨锭 | 字卡 3 选 1 |
|---|---|---|
| 5 | 300 | 蓝 |
| 10 | 500 | 紫 |
| 15 | 800 | 紫 |
| 20 | 1,200 | 金 |
| 25 | 1,500 | 金 |
| 30 | 2,000 | 金 |
| 35 | 2,500 | 橙 |
| 40 | 3,000 | 橙 |
| 45 | 3,500 | 橙 |
| 50 | 5,000 | 红 |
| 60、70、80… | 3,000 | 橙 |

- 不给宝箱(用户 2026-10-02 拍板移除)。逢 5 的等级两轨都拿。
- 3 选 1 **不走开箱、不推进保底计数**。
- 候选可以是已拥有的字:选中即 +1 张重复卡(升级材料)。
- 领取没有截止;等级早已越过也能补领。

## 3. 数据模型(`MetaState` 新增,项目未上线不写迁移)

```csharp
public int LevelRewardGranted { get; set; } = 1;                 // 每级宝箱已发到第几级(1 = 一只都没发)
public List<int> ClaimedMilestones { get; set; } = new();        // 已领里程碑的等级
public Dictionary<int, List<string>> MilestoneOffers { get; set; } = new(); // 已生成的 3 选 1 候选(等级 → 字 id)
public StatsState Stats { get; set; } = new();
```

```csharp
public sealed class StatsState
{
    // 宝箱(ChestRules.TryOpen 里累加)
    public Dictionary<ChestTier, int> ChestsOpened { get; set; } = new();
    public Dictionary<CardRarity, int> CardsFromChests { get; set; } = new(); // 按张数(捆 × 每捆张数)
    // 登塔
    public int Climbs { get; set; }          // 开新塔次数,续爬不算
    public int FloorsCleared { get; set; }
    public int BossesDefeated { get; set; }
    public int Deaths { get; set; }          // 弃塔不算
    // 战斗 / 拆合(战斗结束时由本场计数折入)
    public Dictionary<string, int> CardPlays { get; set; } = new(); // 字 id → 出手次数
    public int Composes { get; set; }
    public int Dismantles { get; set; }
    public int MaxHit { get; set; }
    // 经济
    public int InkEarned { get; set; }
    public int InkSpent { get; set; }
    public int AdRewards { get; set; }
}
```

**保底进度不另记**:角色页直接读 `GoldPity / OrangePity / RedPity` 与 `ChestRules.PityRules` 的阈值和最低档,屏上数字与真实保底同源。

新旧存档:新字段缺省值即「从 0 开始计」,不追溯。`LevelRewardGranted` 缺省 1 意味着**老号首次进游戏会补发**从 Lv.2 到当前等级的全部宝箱——未上线,接受(见 §5.1 的补发上限)。

## 4. 统计的收集(方案 A)

| 类别 | 在哪累加 | 层 |
|---|---|---|
| 开箱各档 / 开出各稀有度张数 | `ChestRules.TryOpen` 成功分支 | Core |
| 登塔次数 / 清层 / Boss / 阵亡 | 新 `StatsRules.RecordClimbStart / RecordFloorCleared(isBoss) / RecordDeath`,由 `GameRoot.StartTower`(新开)、两处 `CharacterXp +=` 经验入账点、`SettleTower(died: true)` 调用 | Core 规则 + Presentation 接线 |
| 出手 / 合成 / 拆解 / 最高单次伤害 | `BattleEngine` 新增只读 `BattleTally`(本场计数):`Cast` 成功 +1 该字、`TryCompose`/`TryDismantle` 成功各 +1、`DamageEnemy` 的最终落地伤害取 max。战斗结束(胜或负)时 Presentation 调 `StatsRules.FoldBattle(meta, battle.Tally)` | Core 计数 + Presentation 折入 |
| 墨锭获得 / 花费 | 新 `MetaRules.GainInk(meta, n)` / `SpendInk(meta, n)`,现有 10 处 `meta.Ink += / -=` 全部改走它们 | Core |
| 看广告领奖 | `AdGate.Watch` 的 `Rewarded` 分支是唯一出口;加静态钩子 `AdGate.OnRewarded`,由 `GameRoot` 挂上 `StatsRules.RecordAdReward(_meta)` + 存档 | Presentation |

- `BattleEngine` 不引用 `MetaState`(保持分层)。中途杀进程丢的只是那一场未结束的计数,接受。
- 最高单次伤害:一次 `DamageEnemy` 调用落地的数值(含召唤物、溅射各算各的),不记来源字与层数。
- 「出手」= 一次 `Cast` 成功,与 AP 花费无关。

## 5. 等级奖励的发放

### 5.1 每级宝箱

```
GrantLevelChests(meta, cardPool, time) → List<(int level, ChestTier tier, ChestAward award)>
  L = CharacterLevel(meta.CharacterXp)
  for lv = LevelRewardGranted+1 .. L:
      award = ChestRules.AwardOrHold(meta, TierForLevel(lv), cardPool, time)
      if award == Lost: break            // 箱位与暂存都满:这一级及之后**欠着**,不推进账目
      LevelRewardGranted = lv
```

- **不会丢箱**:`PendingLimit = 1`,连升多级时箱位很容易满。满了就停在原处,账目不前进;下次触发点再补。和战后掉箱的「满了就丢」**刻意不同**——升级奖励是确定的事,不能因为箱位满就没了。
- 触发点:段末安全层(`ShowSafeLayer`)、登塔结算(`SettleTower`)、回主界面(`ShowMap`,补发欠账)。
- 角色页显示「待发 N 只 · 箱位已满」,开箱腾位后回主界面即补发。
- 补发上限:单次调用最多发到箱位 + 暂存装满为止,天然有界,无需另设上限。

### 5.2 升级弹窗

- 在安全层 / 登塔结算页之上弹出,一次说清这一段升了几级:属性 旧 → 新(+差)、本次发的宝箱。连升多级时同档宝箱合并成一行「×N」(沿用 `levelup/MultiLevel.dc.html` 的版式)。
- 本次跨过里程碑等级 → 弹窗底部加一条提示「Lv.X 里程碑已解锁 · 回主界面后在角色页领取」。**不放跳转钮**(局内进不了角色页)。
- 有宝箱欠着 → 弹窗写「箱位已满 · 开箱腾位后补发」。
- 属性封顶(Lv.50+)沿用 `levelup/Capped.dc.html` 的读法。
- 回主界面补发欠账时不再弹窗,左栏红点 + 箱位变化足够。

### 5.3 里程碑领取

```
MilestonesUpTo(level)          → 已达等级的全部里程碑(5,10,…,50,60,70…)
IsClaimable(meta, lv)          = lv ≤ CharacterLevel && lv ∉ ClaimedMilestones
GetOrCreateOffer(meta, lv, pool, random)
    已有 MilestoneOffers[lv] → 原样返回
    否则从「该稀有度的可掉落字」里不重复抽 3 张(不足 3 张就全给),存档后返回
TryClaim(meta, lv, pickedId)
    校验 IsClaimable 且 pickedId ∈ Offer;GainInk(墨锭);AcquireCard(pickedId);
    ClaimedMilestones += lv;移除 MilestoneOffers[lv]
```

- 候选池 = 与开箱同一份可掉落池(已过滤没配方的字,见记忆「没配方的字拿不到」),按稀有度筛。
- 候选在**第一次打开领取弹窗时**生成并立刻存档:关掉重进不变,防刷。随机走 Core 的 `GameRandom`,种子由 Presentation 传入(候选落档后种子来源无所谓)。
- `HasClaimableMilestone(meta)` 驱动主界面左栏红点。

## 6. UI(Presentation,离线编译必过)

以画布为准,尺寸单位为稿面 pt(×2.093 → Unity 逻辑单位)。

### 6.1 主界面左栏(`MapView.BuildHeroPanel`)

- 整块面板挂 `Button`,点哪都进角色页;右上角一枚 chevron 图标 + 红点(有里程碑可领)。
- `BuildPoolMini` 替换为 Top10:5 列 × 2 行小字牌(26×32,0.8 比例,五行淡底 + 稀有度 1.5pt 框),左上角名次圆标、牌下次数。数据为空时一行占位文案。
- **兜底(用户已认可)**:1600×900 实测挤不下 → 降为 1 行 5 张,完整 10 张只在角色页。

### 6.2 角色页(新 `CharacterView`,`GameRoot.ShowCharacter`)

- 顶栏:返回 · 标题「执 笔 人」· 等级/段位/最高层 · 墨锭。
- 左栏 200:头像、名、等级、经验条(距下一级)、六项属性 + 下一级增量(封顶项写「—」)、底部一句封顶说明。属性读 `MetaRules.BuildBattleConfig`,下一级增量用同一套函数算 L+1 减 L。
- 右上 里程碑轨道:显示 Lv.5–50 十档,三态 —— 已领(压浅 + 勾)/ 可领(赭金底压 `gold-text`、全条最亮,按钮「领 取」)/ 未达(写「差 N 级」)。Lv.50 之后只在标题行写规则;等级过了 50 时轨道换成「当前所在的十档窗口」(实现时取包含最近可领项的 10 档)。
- 右下 统计:页签 宝箱 / 登塔 / 战斗 / 经济。
  - 宝箱:七档开箱数、七档开出张数、金/橙/红三条保底进度(`x / 阈值` + 「再开 N 只 xx 匣及以上必出」)。
  - 登塔:登塔次数、累计清层、最高层(`BestDepth`)、击败 Boss、阵亡。
  - 战斗:出手 Top10(带次数)、合成、拆解、最高单次伤害。
  - 经济:累计获得/花费墨锭、看广告领奖次数。
- 领取按钮**不用朱砂**(一屏可能多个可领,朱砂一屏只许一个主钮)。

### 6.3 领取里程碑弹窗

- 标题「里 程 碑」+ Lv、墨锭行、「X 字 · 3 选 1」三张 0.8 竖版候选牌(新字 / 已有 · 重复卡 +1 角标)、选中环、「收下」朱砂主钮(未选时禁用)、×关闭(候选保留)。

### 6.4 新增素材

- 图标两枚:`chevron`(左栏右上角)、`check`(已领)。走 `tools/icons/build_icons.py` 三处同改(ICONS / EXPECTED / `Icons.Glyphs` 兜底字)。设计系统只允许 `· × — → − ≥ ±` 这几个符号,`›` 与 `✓` 不在字体里。
- 所有新文案进字符串表;改完重跑 `python3 tools/fonts/subset_fonts.py`。

## 7. 测试(Core 先测后实现)

- `TierForLevel`:2/5/6/10/11/20/21/30/31/40/41/99 的边界。
- `GrantLevelChests`:升 1 级发 1 只;连升 3 级发 3 只、各按自己那级查表;箱位 + 暂存满时停在原处、`LevelRewardGranted` 不前进、腾位后再调用补齐;重复调用幂等。
- 里程碑:`MilestonesUpTo` 在 4/5/49/50/59/60/75 的输出;`IsClaimable`;`GetOrCreateOffer` 二次调用返回同一组、不消耗随机;候选全属该稀有度、不重复、池不足 3 张时全给;`TryClaim` 成功加墨锭/加卡/记账/清候选,非法 pick、未达等级、已领均拒且不改状态;**领取不改 `GoldPity/OrangePity/RedPity`**。
- 统计:`TryOpen` 后各档与各稀有度计数正确(按张数);`FoldBattle` 合并出手字典、累加合成拆解、`MaxHit` 取 max;`GainInk/SpendInk` 同步更新 `InkEarned/InkSpent`。
- `BattleTally`:Cast 成功计数、失败不计;合成/拆解成功才计;最高伤害取落地值。
- 存档往返:新字段序列化/反序列化(走 `SaveSerializer`,不直接引用 Newtonsoft);`Dictionary<int, …>` 与枚举键能往返。
- **墨锭对账测试**(pytest,放 `tools/monetization/tests/`):扫 Core/Presentation 源码,`MetaRules.GainInk/SpendInk` 之外出现 `.Ink +=` / `.Ink -=` / `.Ink =` 赋值即红 —— 防以后新加的花钱点漏记。
- 断言只用 Unity NUnit 支持的 API(禁 `Is.AnyOf`、`Does.Not.Contain(非 string)`)。
