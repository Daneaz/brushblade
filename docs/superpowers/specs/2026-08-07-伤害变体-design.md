## 二 · 命中判定

### 2.1 判定点

插在 `DamagePlayerDirect` 与 `DamageSummon` 的**最开头**,一个辅助方法两处调用:

```
命中率 = 100 − 攻击者的致盲% − 目标的闪避%
_random.Next(100) < 命中率 → 命中
```

`GameRandom` 已在 `BattleEngine` 里(`_random`),`RandomState` 也已进 `BattleSnapshot`,
可重现性不受影响。

### 2.2 只判敌人打过来的那一侧

**玩家出字必中,不做 miss。** 详表里没有任何让玩家落空的机制,做了就是 YAGNI;
而且「我出的牌可能白出」在这个游戏里手感很差 —— 出字要消耗 AP 与字库,落空是双重惩罚。

因此 `DamageEnemy` 不加任何命中判定。

### 2.3 完整流水线

`DamagePlayerDirect` 现在是:

```
命中判定(打空 → 什么都不发生,直接 return)
  → 免疫(完全挡下)
  → 护盾吸收 + 掉血
  → 反弹(镜)
```

`DamageSummon` 是:

```
命中判定(含该召唤物的闪避)
  → 护盾吸收 + 掉血
  → 反伤(荆)
```

### 2.4 一个刻意的裁定:掀盾与秒杀打不空

致盲让「伤害」落空,但**不让「掀盾」和「秒杀」落空** —— 倾覆的掀盾(`_shieldNormal = 0`)
与吞噬的必杀(`victim.Hp = 0`)都不经这两个方法,所以不受命中判定影响。

这与既有的两条口径一致:免疫也挡不住掀盾;吞噬也不触发反伤。

## 三 · 五种机制的口径

| 机制 | 表达 | 结算 |
|---|---|---|
| 致盲 | `EffectKind.Blind`,`Value` = 降低的命中百分比;复用 `TargetAll` 定范围、`Turns` 定回合 | 新 `StatusKind.Blind` 挂**敌人** |
| 闪避 | `SummonPassive.Dodge`(百分比) | 子项目 C 建好的被动对象加一个字段,零新结构 |
| 多段 | `EffectDef.HitCount` | 同一个 `DamageEnemy` 调 N 次,每段独立 |
| 反弹 | `EffectKind.Reflect`,`Value` = 百分比,`Turns` 定回合 | 新 `StatusKind.Reflect` 挂**玩家** |
| 沉默 | `EffectKind.Silence`(`Value` 不用),`Turns` 定回合 | 新 `StatusKind.Silence` 挂**敌人** |

### 3.1 多段(剁)

`HitCount` 段,每段调一次 `DamageEnemy`,**每段完全独立**:各自过生克、破甲、穿甲,
也各自过斩杀的「打之前判血」。

所以「第一段把敌人打进 25%、第二段触发处决」是**真会发生的涌现**,不是 bug。

每段前重查 `Alive`,目标死了就停(不浪费后续段数,也不对尸体发事件)。

`HitCount` 默认 1,既有字全部不受影响。

### 3.2 反弹(镜)

`StatusKind.Reflect`,`Polarity = Buff`,`Magnitude` = 反弹百分比,`SourceId` 用字 ID(同字刷新)。

**按「打过来的总伤害」反弹,不是按实际掉血** —— 护盾吸掉的那部分也照样照回去。
「镜」是把东西原样反射,不管你挡没挡住。这与召唤物 `荆` 的反伤同口径(荆 被打死的那一击
也照样扎)。

**免疫完全挡下时不反弹** —— 压根没吃到那记伤害。命中判定打空时同理。

反弹伤害**不走生克**(与 `荆` 同口径,`attacker` 传 `Element.Heart`),
且会引爆与反伤同样的连锁(分裂、焦痕、Boss 换阶、敌人死亡)——
子项目 C 为反伤补的「敌方段后判胜」与「行动配额上界用循环前快照」两条兜底,这里直接受益。

### 3.3 沉默(锁)

`StatusKind.Silence`,`Polarity = Debuff`,`Turns` 回合。带 Silence 的敌人:

- **Boss**:`ResolveBossTurn` 直接返回 false(不蓄力、不放大招);若正在蓄力,
  **取消蓄力并清零 `ChargeCounter`**(锁住的是"正在攒的那一下",解锁后从头攒)
- **字怪能力**:`Regrow`(不补全)、`Split`(不分裂)、`Buff`(不加攻)、
  `Scorch`(不自燃)、`Sear`(不挂灼烧)全部哑火

**`Disguise` 与 `Obscure` 不受影响** —— 那两个是信息隐藏,不是主动机制;
锁住它们等于「锁一下就看穿了」,与「锁」的语义不符。

### 3.4 致盲(熣 / 烟)与闪避(柳)

致盲挂敌人:`StatusKind.Blind`,`Magnitude` = 命中降低百分比,`Turns` 回合,
`SourceId` 用字 ID(同字刷新)。不同来源可叠。

闪避挂召唤物:`SummonPassive.Dodge`。

**钳制的是最终命中率,不是单项**:`命中率 = Clamp(100 − 致盲合计 − 闪避, 0, 100)`。
钳位是**防御性**的,不是修正现有比较式的行为——按 `_random.Next(100) < 命中率` 这条
既有比较式,`Next(100)` 只吐 `[0, 99]`,负的命中率本就恒为 false = 必空,不钳也是同样
结果。钳到 `[0, 100]` 是为了防日后有人把比较式改成 `<=`,或换成 `_random.Next(命中率)`
这类写法时,负数传进去直接出错或产生意外行为。

## 四 · 六字

数值即最终值。已逐字核过相生「他生我」口径,**无一吃 ×3**。

| 字 | 稀 | 系 | 配方 | 效果 |
|---|---|---|---|---|
| 熣 | 🟣紫 | Fire | 火+崔 | `DamageSingle 16` + `Blind 50`(单体,2 回合) |
| 剁 | 🟣紫 | Metal | 朵+刂 | `DamageSingle 10` ×2 段 |
| 镜 | 🔵蓝 | Metal | 钅+竟 | `Reflect 50`(2 回合) |
| 锁 | 🔵蓝 | Metal | 钅+贝 | `Silence`(1 回合) |
| 烟 | 🟢绿 | Fire | 火+因 | `Blind 30`(全体,1 回合,纯功能牌) |
| 柳 | 🟢绿 | Wood | 木+卯 | `Summon 1`(8 血/攻 3)+ `Dodge 50` |

### 三处偏离详表原值,都是为了不让新字压死旧字

- **熣 21 → 16**。详表把它定成「灿(18)的升阶」,那是在它降级成纯单攻的前提下。
  现在带了致盲,再拿 21 就把同档的 灿 压死了 —— 与 2026-08-06 拍板的 `铡 20 → 16` 同一条理。
- **烟 的致盲 50% → 30%**。按期望免伤算:`藤` 🔵蓝「单体冻结 1 回合」= 1.0 个敌人回合;
  烟 若是全体 50%/1 回合,场上 2 怪就已经 1.0、3 怪 1.5,一张**绿卡**盖过蓝卡。
  降到 30% 后 3 怪是 0.9,压在藤下面。
- **柳 12 血/攻 4 → 8 血/攻 3**。50% 闪避把期望有效血翻倍,拿原值会让同为绿档的
  `松`(12 血/攻 3)彻底没有出场理由。改成 8/3 后三张绿档单召各有身份:
  松 12 血稳,杨 8 血/攻 5 能打,柳 期望 16 血但方差大(一半概率一击即碎)。

## 五 · 新部件 6 个

`朵 竟 崔 因 卯 贝`。六个配方经查**无一与既有字撞车**。

**`锁 = 钅+贝`,而不是 IDS 的 `⿰钅𭕆`。** `𭕆`(U+2D546)是增补平面,
`_blocked_smp_part` 会把 锁 整个降级成不可拆的叶子(只能靠掉落获得)。
这是第三次走 `MANUAL_RECIPES` 兜底(荆 的 `茾`、塞 的 `𡨄`,现在 锁 的 `𭕆`)。
用 `贝` 义也通 —— 锁住财物。

## 七 · 存档

新增 `StatusKind.Blind` / `Reflect` / `Silence` 与 `EffectKind.Blind` / `Reflect` / `Silence`,
一律**追加在枚举末尾** —— 老存档里已持久化的序数不位移。

`SummonPassive.Dodge` 是纯新增字段,老存档读到默认 0 = 不闪避,与既有召唤物行为一致。

`EffectDef.HitCount` 同理,默认 1。

三个新 `StatusKind` 都不进跨战斗携带态(`RunEngine` 的过滤器只放 `DamageReduction`),
与免疫/封字/玩家灼烧同待遇 —— 战内持久,战斗结束即丢。

## 八 · 表现层

- **打空**要有表达:发一条事件,表现层播「空」的飘字(复用免疫「免」那套 Lunge + 屏幕中下飘字)。
  没有反馈的话玩家只会觉得「这回合敌人怎么没动」。
- **敌人 chip** 加 `致盲 −N%` 与 `沉默`;**玩家状态条**加 `反弹 N%`。
- **召唤物**的闪避走子项目 C 建好的 `SummonPassiveTag`,加一个 `闪避N` 分支。
- 剁 的两段要**分两拍播**(复用既有 DOT 的串行节奏),一拍打完两段玩家看不出是两段。

## 九 · 测试

1. 命中判定用**固定种子断言具体的命中/落空序列**,不是「大概一半」
2. 致盲让敌人打空时:玩家血、护盾、免疫层数都不动,反弹也不触发
3. 掀盾(倾覆)与秒杀(吞噬)**不受致盲影响**
4. 致盲多来源合计钳到 100,不出现负命中率
5. 剁 的两段各自独立:一段吃破甲、一段不吃时数值对得上
6. 剁 第一段把敌人打进斩杀阈值后,第二段触发处决
7. 剁 的目标中途死亡时剩余段数停手,不对尸体发事件
8. 镜 按**总伤害**反弹(护盾吸掉的部分也反)
9. 镜 在免疫挡下时**不**反弹;在命中判定打空时也不反弹
10. 镜 的反弹打死最后一只敌人时判胜生效(复用子项目 C 的兜底)
11. 锁 住的 Boss 蓄力被取消且 `ChargeCounter` 清零
12. 锁 住的五种字怪能力全部哑火;通假/生僻**不受影响**
13. 柳 的闪避跨战斗保留(走 `SummonPassive` 的存档路径)
14. `HitCount` 默认 1 时既有伤害字行为逐位不变

其他:`ConfigLoader` 解析新字段;`CharTableTests` 补真实配置守卫;
改完 Presentation 必过离线编译;新增字与部件后重跑字体子集。

⚠ **管线侧有一处会静默吃掉数值**:`extract_values.py` 现在的 `turns` / `targetAll` 解析
是**写死给 `HealOverTime` 的**——

```python
for effect in effects:
    if effect["kind"] == "HealOverTime":
        if turns: effect["turns"] = int(turns.group(1))
        if "targetAll" in config: effect["targetAll"] = True
```

`Blind` / `Reflect` / `Silence` 三个新 Kind 都要 `turns`,`Blind` 还要 `targetAll`。
不扩这段,详表里写的 `(turns 2)` 会被**静默丢弃**,生成出来的效果 `turns = 0` ——
挂上去当场就到期。管线测试要有一条钉住这个。

## 十 · 不做的事

- **不给玩家出字加命中判定** —— 只判敌人打过来的那一侧
- **不做 `钩`** —— 模型缺口,移出字表
- 不给致盲/沉默做新动效 —— 复用既有飘字与 chip
- 不动既有字怪的数值与能力(沉默只是让它们哑火,不改数值)
- 不把新状态加进跨战斗携带态
