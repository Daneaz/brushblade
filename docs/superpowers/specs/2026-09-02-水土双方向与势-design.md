# 水土双方向与「势 / 水势」— 设计

> 2026-09-02 · 拍板人:用户 · 分支 `worktree-earth-water-dual-direction`(自 main 分叉)
> 起因:试玩发现治疗与护盾价值极低,土系几乎不带、水系只带冰/冷这类控制字,五行严重失衡。

---

## 1. 问题诊断(本次改动的依据)

调研结论,按证据强度排列:

1. **输出有 7 条乘性放大轴,防御一条都没有。** ATK 成长(100→150)、暴击、战意、破甲/穿透、炽、相克 ×1.5、相生 ×3 全部只放大伤害;护盾/治疗只吃卡等级 ×1.4。`BattleEngine.cs:2156`(Shield)与 `:2176`(HealSelf)只过 `WuxingResolver.ResolveEffect`,一次 `ScaleByAttack` 都没有。**输出可堆到基础值 ~7 倍,防御只能到 1.4 倍。**
2. **威胁量无上限线性增长,防御量是死数字。** `Endless.ScaleFor` = `1 + 0.1×(depth−1)` 无封顶;第 50 层敌人一击 354,而 `垚` 护盾 240(卡5级 336)挡不住一击。
3. **相生 ×3 只有 4/74 张字吃得到**(焚/蒸/沏/刲),土 0/13、木 0/14 —— 全表最大的乘区对土/木完全不可达。
4. **每 AP 价值实测**(depth 20,10 级,卡 5 级,3 只小怪):森(木/橙) 1092 吸伤 + 420 伤害/回合 ≫ 焱(火/橙) ~1230 ≫ 鑫(金/橙) 733 > 淋(水/橙) ~640 > **垚(土/橙) ~500**。
5. **治疗被三件事同时架空**:上限截断(满血溢出全废)、奇遇免费回血(篝火 +200 / 书院 +150 / 废稿堆 +80,零代价)、字库只有 6 格(每格机会成本 = 一张 700+ 伤害的字)。
6. **木系吃掉了土系的饭碗**:19 个召唤字里木 12、土 3。`荆`(330HP ×2,反伤 50 + 嘲讽)是全表最好的防御,因为它同时提供进攻价值。
7. **死轴**:`CharDef.AttackEffects` 全表 0 处配置;设计稿 10.2 的「水势」未实装;破甲/穿透 6 张字只对 3/21 只敌人有意义。

## 3. 机制设计

### 3.1 势 / 水势

**载体**:`StatusKind` **末尾追加** `Momentum`(势,序号 **21**)、`WaterPower`(水势,**22**)。当前末尾是 `DodgeBuff = 20`。

⚠ 追加在末尾是硬约束:`StatusEffect` 随 `EndlessSaveState.CarriedStatuses` / `BattleSnapshot.PlayerStatuses` 进 JSON,而 `SaveSerializer` 没注册 `StringEnumConverter`,Newtonsoft 默认把枚举序列化成**整数**。中间插值会让旧存档静默错位。新序号由 `CritStatTests.StatusKindOrdinals_AreLockedForSaveCompatibility` 锁住。

两条状态都挂在 `_playerStatuses` 上 —— 它本来就进快照,**不新增快照的状态容器**。

| | 势 (Momentum) | 水势 (WaterPower) |
|---|---|---|
| 累积来源 | 获得护盾的**量** | 治疗的**名义值** |
| 阈值 | `MaxHp / 10` | `MaxHp / 10` |
| 上限 | 10 层 | 10 层 |
| 被动 | 每层 **+5% 伤害** | 每层 **+10% 治疗** |
| `Magnitude` | 层数 | 层数 |
| `TurnsLeft` | −1(持久) | −1(持久) |
| `Polarity` | Buff | Buff |
| `SourceId` | `"势"`(单一来源,`Apply` 走覆盖刷新) | `"水势"` |

**治疗按名义值累积**是关键的一条:满血时治疗溢出照样攒水势,"满血奶自己一分不亏"这条痛点由此消掉。护盾同理按获得量而非实际吸伤量算。

**势定 +5%/层(满 +50%)** 而不是 +8%,是为了与**战意的 5 层 × 10% = +50%** 同顶 —— 两条乘性轴不该一高一低,否则堆盾会直接压过战意。

势进 `EffectiveAttack` 的**百分比乘区**,与战意相加:

```csharp
int percent = 100
    + _playerStatuses.TotalMagnitude(StatusKind.Morale) * MoralePercentPerStack   // 战意 ×10
    + _playerStatuses.TotalMagnitude(StatusKind.Momentum) * MomentumPercentPerStack; // 势 ×5
```

「先加后乘」的既有顺序不动(`Empower`/`AttackBuff` 是加点,战意与势是乘比例)。

**势是全局增幅,不限土系伤害。** 依据是第 10 章 10.3.6:「土不成流派,定位为防御/护盾工具字家族,**任何流派可用来补短板**」。火/金流派带一张护盾字白拿增幅是设计定位内的,不是漏洞。

**余数**:新增私有字段 `_shieldAccum` / `_healAccum`(int),累到阈值就换一层、扣掉阈值。到达上限 10 层后**余数也不再累积**(否则降层后会瞬间跳回满层)。

### 3.2 引爆

新增两个 `EffectKind`(不进存档,可自由追加):

| Kind | 行为 |
|---|---|
| `SpendMomentum` | 清空全部势,对**全体敌人**造成 `层数 × Value` 伤害 |
| `SpendWaterPower` | 清空全部水势,对**全体敌人**造成 `层数 × Value` 伤害 |

两者都过 `ScaleByAttack` 与相克,不过折价。层数为 0 时**不消耗 AP 也不发事件**——由 `NeedsTarget` 之外的一条前置守卫挡住,避免玩家空放。

`Value`(每层伤害)写在字上,按载体档位缩放:

| 载体 | 系 | 档 | 每层 | 满层(10) |
|---|---|---|---|---|
| `崩` | 土 | 绿 | 30 | 300 全体 |
| `㙓` | 土 | 红 | 60 | 600 全体 |
| `淼` | 水 | 橙 | 50 | 500 全体 |
| `㵘` | 水 | 红 | 80 | 800 全体 |

**每系两张载体(中档 + 红档)**是刻意的:引爆是这套机制的高光时刻,只挂在红档五系四叠字上会让大部分玩家一局都摸不到。`崩` 在绿档就能拿到,前期即可体验。

水势的变现口放在 `淼`(纯治疗字、攒水势的主力)而不是 `淡`(驱散字),让"攒"与"泄"落在同一张字上,语义自洽。

### 3.3 跨战斗延续

势/水势**跨战斗延续**,与护盾同步(护盾 `_shieldNormal` 本来就整场爬塔延续)。

改动点 `RunEngine.cs:539`,携带态白名单从

```csharp
.Where(s => s.Kind == StatusKind.DefenseBuff)
```

扩为 `DefenseBuff | Momentum | WaterPower`。

余数一并跨战斗:`RunEngine` 新增 `_carriedShieldAccum` / `_carriedHealAccum`,进 `RunSnapshot`,由构造函数注入 `BattleEngine`。

⚠ **漏补快照字段是静默的**(断点续爬丢半层,没有任何现有测试会红)。单独写一条测试钉住:攒到半层 → `Capture()` → `Restore()` → 余数不变。

### 3.4 方向选择器(Presentation)

在现有状态机上**加一态**,不写第二套:

```
选中字 ──def.AttackEffects.Count > 0?──→ _directionPicking
                                            │
                                ┌───────────┴───────────┐
                             [攻击]                [治疗/加盾]
                                │                       │
                        _targeting              _allyTargeting
                     (attackMode=true)        (attackMode=false)
                                │                       │
              已有 Targeting.ExpandTargets      已有 CanHealSlot
                  整片高亮(AOE/横扫/连发)         友方落点高亮
```

- AOE 整片渲染、友方落点高亮**都是现成的**(`OnDragHover` + `Targeting.ExpandTargets`;`TryGetAllySlotAt` + `CanHealSlot`)
- **拖放路径一个字不改** —— 拖到敌人本来就是 `attackMode: true`(`BattleView.cs:2476`),它天然等于"选了攻击方向"
- `AttackEffects` 为空的字(火/金/木全部)**不进方向选择器**,行为与今天完全一致
- 取消:`CancelSelection()` 复用,`_directionPicking` 一并清

新增两条字符串表 key:`battle.direction.attack` / `battle.direction.support`。

### 3.5 护盾/治疗接上攻击成长

新增 `ScaleByBaseAttack`,四处套用:`Shield`、`HealSelf`、`HealAll`、`HealOverTime`。

```csharp
private int ScaleByBaseAttack(int value) =>
    value * _config.PlayerAttack / BattleConfig.AttackBaseline;
```

⚠ **读的是 `_config.PlayerAttack`(纯角色等级成长),不是 `EffectiveAttack`(含局内 buff)。**

这不是图省事 —— 用 `EffectiveAttack` 会造出一个**正反馈环**:势进 `EffectiveAttack` 的百分比乘区 → 护盾吃 `EffectiveAttack` → 堆盾涨势 → 势放大护盾 → 涨更多势。10 层上限能兜住不爆炸,但"战意(连续出字的节奏奖励)放大护盾"、"势放大自己的来源"两条语义都荒谬。

用户拍板时看的预览是「26 级 ATK=150,垚 攻击面 320→480、护盾面 340→510」—— 说的正是**等级成长**这一层,不是局内增益。`ScaleByBaseAttack` 精确对应它。

**基准值下逐字节恒等**:`v * 100 / 100 == v`,这是 E-b1 立下的硬线。1 级角色(`PlayerAttack = AttackBaseline = 100`)的战斗结果一分不差,既有断言全绿。

### 3.6 取消相生

`WuxingResolver.ShengMultiplier` **删除**,`KeMultiplier`(相克 ×1.5 / ×0.5)**保留**。`ResolveEffect` 两个重载去掉 `recipeElements` 参数。

全表只有 4 张字吃相生,把基础值直接写成 ×3 后的实战值,**战斗结果一分不差**:

| 字 | 系/档 | 现基础值 | 写死为 | 实战值 |
|---|---|---|---|---|
| 焚 | 火/橙 | `DamageAll 40` | **120** | 不变 |
| 蒸 | 火/紫 | `DamageSingle 45` | **135** | 不变 |
| 刲 | 金/橙 | `DamageSingle 150` | **450** | 不变 |
| 沏 | 水/紫 | `DamageSingle 70` | **180** | 210 → 180(在水系重配范围内,见 §4.2) |

于是取消相生是**纯模型简化**:少一条规则、少一个乘区、配置值 = 实战值(读表不用再心算)。

连带改动:`docs/design/wuxing-reference.md`(规则唯一来源)、`WuxingResolverTests`、`CLAUDE.md` 里那条「相生 ×3 去重不叠乘」的描述。

## 4. 数值

### 4.1 锚点表

不逐字拍脑袋,每张字的两面都从表里取值:

| 档 | 单体 | 全体 | 护盾/治疗 |
|---|---|---|---|
| 白 | 45 | 30 | 45 |
| 绿 | 70 | 50 | 70 |
| 蓝 | 110 | 60 | 110 |
| 紫 | 150 | 80 | 150 |
| 金 | 340 | 150 | 340 |
| 橙 | 430 | 190 | 430 |
| 红 | 540 | 250 | 540 |

**折价规则**:带附加特性的面 × **0.7**(冻结/减速/破甲/驱散/斩杀/净化/复活/免疫都算)。引爆(`SpendMomentum`/`SpendWaterPower`)**不算附加** —— 它消耗资源,不是白拿。

**两面各自独立算折价**:一面带附加要折、另一面没有就取满值。`冰` 攻击面带冻结折到 238、治疗面无附加取满 340,是正常的不对称,不是配错。

**不为了凑折价硬造特性。** 原字没有的特性一律不加 —— 初稿曾给 `冰` 的治疗面加"净化"、给 `沐` 的攻击面加"流血",两者语义都站不住,已改回满值。

**护盾/治疗 = 单体满值(1:1)**。理由:护盾跨层累积不浪费、治疗溢出攒水势不浪费,但两者不吃暴击/战意/破甲/相克 —— 稳定性溢价与乘区折价对冲。1:1 也让玩家一眼看懂("要么打 340,要么给 340 盾")。

**全体锚点按"不削弱任何现有字"定**,不是单体 ÷ 3。现有 AOE 分布(海 50 / 崩 50 / 爆 50 / 烈 70 / 焱 120 / 淡 180 / 㵘 200 / 㙓 240)远高于单体的三分之一;按 ÷3 配会把 `海`/`崩` 从 50 削到 23。

单体锚点与现有火/金一致(炎 340 / 鑫 430 / U+E626 540),不是新造的量级。

**召唤字例外**:碉/堡/塔 的攻击面保留现有召唤数值不动 —— 召唤的数值体系是另一套(血/攻/被动),不适用伤害锚点。

**测试纪律**(踩过的坑):
