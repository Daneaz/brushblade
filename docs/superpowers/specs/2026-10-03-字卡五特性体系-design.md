## Context

**问题**：字卡等级只放大数值，不解锁能力。现在的"特性"只是效果列表里的附加项，没有成长感。

**目标**：
- 每张字有 5 个特性，随等级解锁，与字义相关。稀有度越高，特性越强、越独占。
- 每张字有两面：**攻击面**和**本系特色面**。在合适的场景下，两面都值得用。
- 与现有技能树分工明确，不重复。

**v6 改动**：

| # | 改动 | 原因 |
|---|---|---|
| 1 | 火、金改为「攻击面 = 输出，特色面 = 生存」，取消 v5 的铺垫 / 兑现拆法 | 铺垫 / 兑现要两张牌、2 AP 才能打出一次完整效果。每回合只有 3 AP、只掉 1 张字，火、金字本来就少，这样拆会让它们再弱一档 |
| 2 | 新增**自足原则**（R8）：每一面单独打出都完整生效 | 同上 |
| 3 | 与技能树对齐：同一机制只归一处，特性不与技能节点重名，资源沿用现有设定 | 用户要求对比现有技能 |
| 4 | 金系关键词改回「**战意**」；水的**泉**、土的**厚**保留 | 技能节点锋芒、断金、涌泉、积土依赖这些资源 |
| 5 | 红字不再改规则、不跨场景、不叠生存 | 红字靠起手保底每局都会出现，𣛧 已能带人上 50 层 |
| 6 | 仿真以「五系随机」画像为准，跑多批种子 | 字卡随机抽取，不固定某一系 |

## 0. 术语

| 词 | 含义 |
|---|---|
| 场 | 一场战斗，即一关 |
| 段 | 5 关，第 5 关是 Boss |
| 场景 | 10 关一个主题，例如「字林」= 第 1~10 关 |
| 本塔 | 一次爬塔，直到死亡或放弃 |
| 回合 | 玩家身上的效果按玩家回合计；敌人身上的效果按该敌人的行动次数计 |
| 击 | 一次出字对同一个目标结算的次数 |

## 1. 等级阶梯

| 等级 | 解锁 | 作用于 |
|---|---|---|
| Lv1 | ① 基础特性（本系关键词） | 两面各有对应写法 |
| Lv3 | ① 强化 | 两面 |
| Lv4 | ② 被动：修饰本字 | 两面 |
| Lv5 | ③ 主动 | **副面** |
| Lv6 | ④ 被动 | 某一面（每张字自定） |
| Lv8 | ⑤ 主动：招牌 | **主面** |
| Lv2/7/9/10 | 只涨数值 | — |

- 数值每级 +6%：Lv8 为 ×1.42，Lv10 为 ×1.54。
- 层数、回合、次数、击数不随等级涨，只在 Lv3 提升。

## 2. 两面

### 2.1 定义：攻击面负责输出，特色面负责生存

| 系 | 攻击面（输出） | 特色面（生存，本系的方式） |
|---|---|---|
| 火 | **焚**：伤害 + 灼 | **燃**：上灼，同时削弱敌人攻击。思路是"让敌人打不痛" |
| 金 | **斩**：伤害 + 战意 | **铠**：战意 + 格挡。思路是"挡下来再打回去" |
| 水 | **涛**：伤害 + 冻结 / 减速 | **润**：治疗 |
| 土 | **震**：伤害 + 破甲 | **固**：护盾 + 护甲 |
| 木 | **刺**：伤害 + 种 | **生**：召唤木灵 |

- **主面与副面**：每张字有一个主面，按 100% 结算；另一面为副面，按 60% 结算（比例由仿真定标）。
- **翻面**：卡面默认显示主面，点一下翻面；拖出时使用当前朝上的那一面。
- **两面各得其一**：Lv8 给主面，Lv5 给副面。

### 2.2 特色面可以作用于木灵

| 系 | 拖到木灵身上的效果 |
|---|---|
| 水·润 | 治疗木灵，并把它改为水属性（本场） |
| 土·固 | 给木灵护盾，并让它获得嘲讽（本场） |
| 金·铠 | 木灵获得格挡和战意 |
| 木·生 | 拖到已有木灵上为**嫁接**：回满生命，并获得本字的本命（本场） |
| 火·燃 | 只能对敌人使用 |

这一设计对应原双面字要解决的三个问题：
- 木字防卡手：召唤位满了可以嫁接，或改用攻击面。
- 克制补位：可以把木灵改成克制敌人的属性。
- 水、土不只是奶和盾：每张都有攻击面。

### 2.3 被动的落点

不需要在玩家身上另设载体，被动只有两种：
1. **修饰本字**：例如「本字克制时 +15%」。
2. **附在本字的产出上**：产出指护盾、格挡、木灵、灼等状态。受击触发、减益触发都由产出承载，产出消失，被动也随之消失。

## 4. 五系 Lv1 / Lv3

| 系 | 攻击面 Lv1 | 特色面 Lv1 | Lv3 |
|---|---|---|---|
| 火 | 焚：伤害 + 灼 N | 燃：灼 N，目标攻击 −15%，2 回合 | 灼 N+1；燃改为持续 3 回合 |
| 金 | 斩：伤害 + 战意 N | 铠：战意 N，格挡 1 次（反击本体 30%） | 战意 N+1；格挡 2 次 |
| 水 | 涛：伤害 + 冻结或减速 1 回合 | 润：治疗，并附润泽 2 回合 | 两面都 +1 回合 |
| 土 | 震：伤害 + 破甲 2 回合 | 固：护盾 + 护甲 2 回合 | 都改为 4 回合 |
| 木 | 刺：伤害 + 种 2 回合 | 生：召唤木灵（带本命） | 种改为 3 回合；本命强化 |

- **各档 N**：
  - 灼：白 / 绿 / 蓝 1，紫 2，金 / 橙 3，红 4。
  - 战意：白 / 绿 / 蓝 1，紫 / 金 2，橙 / 红 3。
- **释放泉 / 厚的字**：溃、㵘 的攻击面释放泉；崩、㙓 的攻击面释放厚。
- **灼伤害公式**：每层每回合 20 × 火力 × 攻击% × 生克倍率。
  - 火力 = 给这个目标上过灼的火字中，最高的那个等级系数。
  - 算例：叠满 10 层时，一回合 200 伤害；全部烧完共 1100。

## 5. 存续与防叠加

### 5.1 谁能跨场

| 稀有度 | 可用的存续 |
|---|---|
| 白 ~ 紫 | 回合、本场 |
| 金 | 跨场（1~3 场） |
| 橙 | 跨段 |
| 红 | 回合、本场（见 §7） |

木灵本身跨场保留，直到阵亡。

### 5.2 防无限叠加六律

1. **同类取最强**：同类效果不叠加，只保留最强的一份。同类包括：护盾附加效果、反伤、减伤、增攻，以及开局类的跨场效果。
2. **硬上限**：
   - 护盾 ≤ 最大生命
   - 战意 ≤ 5
   - 灼 ≤ 10 层
   - 泉、厚各 ≤ 10 层
   - 战后护盾保留比例按技能树（基础 50%，点了固本 75%）
3. **反伤封顶**：反伤合计不超过本次受到伤害的 60%。荆棘、反震、格挡反击都算反伤。反伤不暴击，也不能转成护盾。
4. **减伤封顶**：护甲以外的减伤合计 ≤ 60%。
5. **跨场只存不长**：跨场效果数值固定，不会越滚越大。唯一的例外是木灵的成长，最多 3 次。
6. **按场数计**：所有跨场效果都写明场数。Boss 的「倾覆」会清空护盾。

## 6. 与技能树的分工

### 6.1 原则

1. **技能树管角色层**：全系通用的连续数值，以及资源规则（上限、释放、保留比例）。**字卡管单张字**：离散量、触发条件、字义特色。
2. **同一机制只归一处**：技能树已有的产出，字卡不再做。触发点可以共用，但产出必须不同。
3. **同轴加成相加，不相乘**：字卡上「本字 +X%」与技能树的同类加成放在同一个乘区。暴击率总和设上限（数值待定标）。
4. **字卡特性名不与技能节点重名。**
5. **资源统一**：火灼、金战意、水泉、土厚都沿用现有设定。技能树强化资源，字卡产生和使用资源。

### 6.2 已处理的重叠

| 技能节点 | v5 中撞上的字卡内容 | v6 的处理 |
|---|---|---|
| 火 L3 余烬（敌人死亡时，灼转给随机敌人） | 火池·余火；焚·余烬 | 两条都删除，改为其他产出 |
| 火 L4 燎原（灼烧扩散到相邻） | 焱·飞迸（灼扩散给另一名敌人） | 删除，改为「炽焰」 |
| 水 L3 溢流（治疗溢出转为伤害） | 㵘·襄陵；水池·回流、淼·浩渺（溢出转护盾） | 「治疗溢出」这个触发点归技能树；字卡改为「治疗时额外给护盾」 |
| 土 L3 固本（战后护盾保留比例） | v5 的「战后护盾 ≤30%」、㙓 的 60% | 删除，战后保留比例以技能树为准 |
| 金 L4 断金（战意满 5 层时爆发） | 𨰻、鑫 修改战意上限 | 删除改上限的内容；断金固定为「≥5 层」触发 |
| 木 L1 深根 / 水 L1 甘霖 / 土 L1 筑垒 | 通用池·灵健、厚实；水池·甘霖 | 删除 |
| 被动树·力、锋 | 通用池·精进；桂·蟾宫 | 保留，按 §6.1 第 3 条相加 |
| 重名：添薪、炎上、燎原、锋芒、归根、锐锋 | 同名或近名的字卡特性 | 字卡一侧改名：续火、火上浇油、星星之火、锋锐、秋实；关键词改回「战意」 |

## 7. 稀有度梯度

| 档 | Lv4 | Lv5（副面） | Lv6 | Lv8（主面） | 专属条数 |
|---|---|---|---|---|---|
| 白 / 绿 | 通用池 | 系池 | 系池 | 专属 | 1 |
| 蓝 | 通用池 | 专属 | 系池 | 专属 | 2 |
| 紫 | 专属 | 专属 | 系池 | 专属 | 3 |
| 金 / 橙 / 红 | 专属 | 专属 | 专属 | 专属 | 4 |

**红字原则**：红字会通过起手保底每局出现，所以：
1. **不改规则**：Lv8 是这张字最强的一次性大招，不改写整场战斗的规则。
2. **不跨场景**：不叠多场持续效果。
3. **不叠生存**：𣛧 的特性给输出和联动，不再给保命。
4. **强在独特，不强在数值**：数值只比橙档略高。

词条池里的数值按档放大：白 1.0、绿 1.2、蓝 1.45、紫 1.75、金 2.1、橙 2.5、红 3.0。表中的 X 由仿真定标。

## 10. 全局规则

- **R1 冻结**：冻结中不能再被冻结，也不能延长；结束后获得霜抗，回合数等于刚结束的冻结回合数。减速不叠加，只刷新。概率定身视为冻结。
- **R1b 冰滞**：Boss 被冻结时一律改为冰滞（见词条表），任何字都不能真正冻结 Boss。冷·冷却对同一 Boss 每场只生效 1 次。
- **R2 斩杀**：对 Boss 一律改为伤害 ×2。
- **R3 结算顺序**：条件按出字前的状态判定。依次结算：伤害 → Lv1/Lv3 → Lv5/Lv8。
- **R4 防循环**：
  - 特性造成的伤害，不再触发受击类、死亡类被动。
  - 自损不算受击。
  - 代价（如 AP −1）不算减益。
- **R5 阈值与复活**：「生命跌破 X%」每个单位每场只触发 1 次；复活不重置。
- **R6 站位**：不设计「本回合未受伤」这类条件。
- **R7 计数**：「本场此前」不含本张，也不含部件出手。
- **R8 自足**：
  - 每一面单独打出都必须完整生效。
  - 特性不得依赖「下一张字」或「本场已打出 N 张某系字」。
  - 同系联动只能是「有则更强」，不能是「没有就没用」。
  - 依赖目标状态（如「目标带灼时 ×2」）是允许的，因为没有这个状态时，本体效果照样生效。

1. **数据**
   - `CharDef` 增加 `MainFace`、两面本体、`Traits`。
   - `TraitDef` 包含：槽位、解锁等级、作用面、形态（主动 / 修饰 / 附着 / 字形）、效果（复用 `EffectDef`）、次数阀。
2. **出字**
   - `Cast` 增加面参数，副面按 60% 结算。
   - 特色面拖到木灵上：复用 `NeedsAllyTarget` / `allySlot`；改属性走 `Unseal` 的路径。
3. **资源**
   - 战意、泉、厚沿用现有实现。
   - 新增格挡状态（含次数和反击）。
   - 燃面的「攻击 −X%」复用现有减攻通道（`Curse` 类）。
4. **事件管线**（`BattleEngine.cs`）
   - 伤害上下文加入来源和触发深度，三处伤害入口都要接上。
   - 状态统一走一个入口，收口约 21 处 `Statuses.Apply`；霜抗、冰滞、杜绝在这个入口拦截。
   - 击杀者由 `ResolveDefeat` / `OnSummonDeath` 带出。
   - 新增挂点：回合开始 / 结束、`Compose`、`Dismantle`、阈值跌破。
   - 附着在产出上的被动随产出一起消亡。
5. **跨场效果**
   - `RunEngine` 维护一张「开局效果」表，记录剩余场数，每场开局结算后减 1。
   - 同类效果只保留最强的一份。
6. **范围**
   - `TargetShape` 改名为 `TargetArea`，各项为：`Single` / `Adjacent`（溅射）/ `Row`（横扫）/ `Column`（贯穿）/ `Scatter`（散射）/ `Chain`（弹射）/ `All`（全体）。
   - 并入 `All` 后，退役 `EffectKind.DamageAll`。
7. **上限**
   - §5.2 的所有上限集中到一个规则类。
   - 战后护盾保留沿用 `ShieldCarryPercent`（技能树固本调整这个值）。
8. **快照**
   - 新增状态全部进入 `BattleSnapshot` / `RunSnapshot`，并配全字段往返测试。
   - `StatusKind` 只能在末尾追加。
   - 拆字印记用计数字典实现，不改 `ForgeState.Pool`。
9. **管线**
   - 特性表按系拆成 5 个文件。
   - `extract_values.py` / `export_chars.py` 输出 `mainFace`、两面本体和 `traits`。
   - 移除旧的附加效果和旧价目。

## 12. UI（先交 designer 出稿）

按 CLAUDE.md 的「UI 设计流程」：由 `designer` 出稿，稿件按层落库到 `docs/design/`，用户确认后才能实现。

| 界面 | 要设计的内容 |
|---|---|
| **字卡详情页（重设计）** | 两面并排，主面突出；每面显示本体数值和挂载的特性；通用特性（Lv1/3/4）；锁定状态和解锁等级；每个特性附一句说明 |
| 词条说明 | 文案中的术语可点开，显示 §3 的说明 |
| 翻面 | 手牌上点一下翻面；拖动时按当前面高亮可落点（敌人 / 自己 / 木灵） |

| 状态 chip | 灼、战意、格挡、泉、厚、润泽、种、霜抗、冰滞、致命、标记、嘲讽、留存护盾、减攻 |

新状态要同时接入三处：`StatusText.Of`、`BattleView` 的 chip、`CharInfo`。新文案进字符串表，并重跑字体子集。

## 13. 仿真口径

- **以「五系随机」画像为准**。单系画像只作基线参考。
- **多跑几批种子**：`tools/balance` 需要新增种子偏移参数，每批 300 个种子，至少跑 3 批，看均值和波动。
- **先修机器人**：
  - 混合卡组里，机器人平均每局只召唤 1.5 次，没有把常驻木灵当作挡刀来用。
  - 红字靠起手保底每局都在，现有画像量不出单张红字的影响。
  - 定标前要先改进机器人的出牌策略，并新增一个「起手指定某张字」的画像。
- **检查项**：
  - 各档 Lv1/Lv5/Lv8 的卒层应呈梯度。
  - 每张字的两面都应在某类遭遇中被选用。
  - 火、金字的出字占比不再明显低于其他系。

## 14. 不在本稿范围（另开一项）

- **𣛧 本体强度评估**：现有数值（生命 938、荆棘、光环）配合召唤物跨场保留和前排拦截，已经能带人上 50 层。是否需要削弱，另行评估。
