# 字卡五特性体系 · 设计（v5）

> 状态：待用户审阅（2026-10-03）。
> 版本：v1→v2 设计评审；v2→v3 用户反馈 8 条；v3→v4 反馈 5 条；v4→v5 反馈 2 条。
> 本稿不继承现有技能树和字卡附加效果。生效后，以下两项作废：`rebalance_2026_09_05.py` 的特性价目，以及 09-05 字表平衡 spec 的「本体特性配额」。

## Context

**问题**：字卡等级只放大数值，不解锁能力。现在的"特性"只是效果列表里的附加效果，没有成长感，也没有独立数据。

**目标**：
- 每张字有 5 个特性，随等级解锁，跟字义相关。稀有度越高，特性越强、越独占。
- 每张字有两面：**攻击面**和**本系特色面**。两面都要有用武之地。

**v5 改动**：
- **两面制**，取代 v4 的三面。召唤只属于木系（§2）。
- **火、金的特色面**要和攻击面分开。做法是「一面铺垫、一面兑现」（§2.2）。
- **文案从简**。每个特性都附一句说明，术语统一收进词条表（§3）。
- 存续层级、防叠加规则、范围改名保留，并适配两面制。

## 0. 术语

| 词 | 含义 |
|---|---|
| 场 | 一场战斗，即一关 |
| 段 | 5 关，第 5 关是 Boss |
| 场景 | 10 关，一个主题，例如「字林」= 第 1~10 关 |
| 本塔 | 一次爬塔，到死亡或放弃为止 |
| 回合 | 玩家身上的效果按玩家回合计；敌人身上的效果按该敌人的行动次数计 |
| 击 | 一次出字对同一个目标结算几下 |

## 1. 等级阶梯

| 等级 | 解锁 | 作用于 |
|---|---|---|
| Lv1 | ① 基础特性（本系关键词） | 两面各有对应写法 |
| Lv3 | ① 强化 | 两面 |
| Lv4 | ② 被动：修饰本字 | 两面 |
| Lv5 | ③ 主动 | **副面** |
| Lv6 | ④ 被动 | 一面，各字自定 |
| Lv8 | ⑤ 主动：招牌 | **主面** |
| Lv2/7/9/10 | 只涨数值 | — |

- 数值每级 +6%：Lv8 = ×1.42，Lv10 = ×1.54。
- 层数、回合、次数、击数不随等级涨，只在 Lv3 提升。

## 2. 两面

### 2.1 定义

| 系 | 攻击面 | 特色面 |
|---|---|---|
| 火 | **焚**：打伤害，**利用**灼 | **燃**：上灼和其他减益，几乎不打伤害 |
| 金 | **斩**：打伤害，**消耗**锐 | **砺**：叠锐，并获得格挡 |
| 水 | **涛**：打伤害，冻结或减速 | **润**：治疗 |
| 土 | **震**：打伤害，破甲 | **固**：护盾和护甲 |
| 木 | **刺**：打伤害，种 | **生**：召唤木灵 |

- 每张字有一个**主面**，按 100% 结算；另一面是**副面**，按 60% 结算（比例由仿真定标）。
- 卡面显示主面，**点一下翻面**，拖出去时用当前朝上的那一面。
- 两面各得其一：Lv8 给主面，Lv5 给副面。满级时，两面都有自己的专属主动。

### 2.2 火、金两面怎么分开

问题出在：火的攻击会顺带上灼，金的攻击会顺带叠锐，所以特色面和攻击面做的是同一件事。

解法是**一面铺垫，一面兑现**：

| 系 | 铺垫面（特色） | 兑现面（攻击） |
|---|---|---|
| 火 | 燃：只上灼、挂减益，不打伤害或只打很少 | 焚：不上灼；目标身上的灼越多，伤害越高 |
| 金 | 砺：只叠锐、加格挡，不打伤害 | 斩：不叠锐；打出时消耗全部锐，每层 +20% 伤害 |

这样就形成节奏选择：本回合先铺（燃 / 砺），下回合兑现（焚 / 斩）；或者手上有现成的灼 / 锐时，直接兑现。

### 2.3 特色面可以作用于木灵

| 系 | 拖到木灵身上 |
|---|---|
| 水·润 | 治疗木灵，并把它的五行改为水（本场） |
| 土·固 | 给木灵护盾，并让它获得嘲讽（本场） |
| 金·砺 | 木灵获得锐，它的攻击会消耗锐 |
| 木·生 | 拖到已有的木灵上 = **嫁接**：回满生命，并获得本字的本命（本场） |
| 火·燃 | 只能对敌人用 |

这一节回应原双面设计的三个目的：
- 木字在场上召唤位满了时可以嫁接，或改用攻击面；
- 遇到没有克制手段的敌人，可以把木灵改成克制它的五行；
- 水、土每张字都带攻击面，不会只能奶或只能盾。

### 2.4 被动的落点

不需要玩家身上的额外载体，被动只有两种：
1. **修饰本字**，例如「本字克制时 +15%」。
2. **附在本字的产出上**，产出包括护盾、格挡、木灵、灼等状态。受击触发、减益触发都由产出承载，产出消失，被动也随之消失。

## 4. 五系 Lv1 / Lv3

| 系 | 攻击面 Lv1 | 特色面 Lv1 | Lv3 |
|---|---|---|---|
| 火 | 焚：目标每层灼使伤害 +10%（最多 +100%） | 燃：上灼 N 层 | 焚每层改为 +15%；燃 N+1 |
| 金 | 斩：消耗全部锐，每层伤害 +20% | 砺：锐 +N，格挡 1 次 | 斩每层改为 +25%；砺锐 N+1、格挡 2 次 |
| 水 | 涛：冻结或减速 1 回合 | 润：治疗，并附润泽 2 回合 | 都 +1 回合 |
| 土 | 震：破甲，持续 2 回合 | 固：护盾，并加护甲 2 回合 | 都改为 4 回合 |
| 木 | 刺：种 2 回合 | 生：召唤木灵（带本命） | 种 3 回合；本命强化 |

**各档的 N**：
- 灼：白 / 绿 / 蓝 1 层，紫 2，金 / 橙 3，红 4。
- 锐：白 / 绿 / 蓝 1 层，紫 / 金 2，橙 / 红 3。

**灼的伤害**：每层每回合 20 × 火力 × 攻击% × 生克倍率。

- 「火力」= 给这个目标上过灼的火字里，最高的那个等级系数。
- 层数上限为 10。这个上限限制的是层数，不是伤害。
- 算例：
  - 灼 1 层：20 伤害。
  - 叠满 10 层，一回合打 200，全部烧完共 1100。

## 5. 存续与防叠加

### 5.1 谁能跨场

| 稀有度 | 可用的存续 |
|---|---|
| 白 ~ 紫 | 回合、本场 |
| 金 | 跨场（1~3 场） |
| 橙 | 跨段 |
| 红 | 跨场景，以及本场改规则 |

此外：
- 木灵本身跨场保留，直到阵亡。
- 护盾战后最多带走最大生命的 30%。

### 5.2 防无限叠加六律

1. **同类取最强**：同类效果（护盾附加、反伤、减伤、增攻、开局类跨场效果）不叠加，只保留最强的一份。
2. **硬上限**：
   - 护盾 ≤ 最大生命
   - 战后带走的护盾 ≤ 30%（红档 㙓 可提到 60%）
   - 锐 ≤ 5（红档 𨰻 可提到 10）
   - 灼 ≤ 10 层（红档 燚 可提到 15）
3. **反伤封顶**：反伤合计 ≤ 本次受到伤害的 60%。反伤不暴击，也不能变成护盾。
4. **减伤封顶**：护甲以外的减伤合计 ≤ 60%。
5. **跨场只存不长**：跨场效果的数值固定，不会越滚越大。木灵每场成长是唯一的例外，且最多成长 3 次。
6. **按场数计**：所有跨场效果都写明场数，没有无限持续的。Boss 的「倾覆」会清空护盾，作为天然克制。

## 6. 全局规则

- **R1 冻结**：冻结中不能再被冻结，也不能延长；结束后获得霜抗，回合数与刚才的冻结相同。减速不叠加，只刷新。概率定身视为冻结。
- **R1b 冰滞**：Boss 被冻结时改为冰滞（见词条表）。只有红档 㵘 能真正冻结 Boss。
- **R2 斩杀**：对 Boss 一律改为伤害 ×2。
- **R3 结算顺序**：条件按出字前的状态判断；先结算伤害，再结算 Lv1/Lv3，最后结算 Lv5/Lv8。
- **R4 防循环**：特性造成的伤害不会再触发受击、死亡类被动。自损不算受击。代价（如 AP −1）不算减益。
- **R5 阈值与复活**：「生命跌破 X%」每个单位每场只触发 1 次；复活不重置这个计数。
- **R6 站位**：不设计「本回合未受伤」这类条件。后排常年被前排挡着，这种条件对它们是白给。
- **R7 计数**：「本场此前」不含本张，也不含部件出手。

## 9. 引擎与数据改造

1. **数据**
   - `CharDef` 增加 `MainFace`、两面本体、`Traits`。
   - `TraitDef` 包含：槽位、解锁等级、作用面、形态（主动 / 修饰 / 附着 / 字形）、效果（复用 `EffectDef`）、次数阀。
2. **出字**
   - `Cast` 带上面参数。副面按 60% 结算。
   - 特色面拖到木灵上，复用 `NeedsAllyTarget` / `allySlot`；改五行走 `Unseal` 的路径。
3. **锐的改造**
   - 去掉"每层被动加伤"。
   - 改为只由斩面消耗。
4. **事件管线**（`BattleEngine.cs`）
   - 伤害上下文要带上来源和触发深度，三处伤害入口都要接入。
   - 状态统一走一个入口，收口现有约 21 处 `Statuses.Apply`；霜抗、冰滞、杜绝在这里拦截。
   - 击杀者通过 `ResolveDefeat` / `OnSummonDeath` 传出。
   - 新增挂点：回合开始 / 结束、`Compose`、`Dismantle`、阈值跌破。
   - 附着在产出上的被动，跟随该产出一起消亡。
5. **跨场效果**
   - `RunEngine` 维护一张「开局效果」表，记录剩余场数，每场开局结算后减 1。
   - 同类效果只保留最强的一份。
6. **范围**
   - `TargetShape` 改名为 `TargetArea`：`Single` / `Adjacent`（溅射）/ `Row`（横扫）/ `Column`（贯穿）/ `Scatter`（散射）/ `Chain`（弹射）/ `All`（全体）。
   - `All` 并入后，退役 `EffectKind.DamageAll`。
   - 同步修改 `Targeting.ExpandTargets`、管线 token 和详表。
7. **上限**
   - §5.2 的上限集中放在一个规则类里。
   - 战后护盾携带上限改为最大生命的 30%。
8. **快照**
   - 新增状态全部进 `BattleSnapshot` / `RunSnapshot`，并配全字段往返测试。
   - `StatusKind` 只能在末尾追加。
   - 拆字印记用计数字典实现，不改 `ForgeState.Pool`。
9. **管线**
   - 特性表按系拆成五个文件。
   - `extract_values.py` / `export_chars.py` 输出 `mainFace`、两面本体和 `traits`。
   - 移除旧的附加效果和旧价目。

## 11. 流程与验证

1. 用户审阅本 spec。
