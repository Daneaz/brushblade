# 字卡五特性体系 · 设计（v3）

> 状态：待用户审阅（2026-10-03）。v1 经设计评审修订为 v2，v2 吸收用户第一轮 8 条反馈成为 v3。
> 本稿不继承现有技能树与字卡附加效果；生效后，`rebalance_2026_09_05.py` 的特性价目体系与 09-05 字表平衡 spec 的「本体特性配额」作废。

## Context

**现状问题**：字卡等级（1~10）只放大数值，不解锁任何东西。卡面上的"特性"是效果列表里的附加效果（溅射/斩杀/破甲…），按档定额、从主数值里扣价，没有独立数据，也没有成长感。引擎没有触发系统，所有被动都写死在结算分支里。

**目标**：把字卡升级做成"能力解锁"。每张字 5 个特性，随等级解锁，与字义绑定；稀有度越高，特性越强、越独占。

**设计约束**：不继承现有技能树和现有字卡附加效果，从零设计。只保留以下内容：
- 55 张字的名单与稀有度
- 五行归属
- 本体形态：主数值、单体/全体、攻/护两面

**v3 相对 v2 的修改**：
- 统一了术语（§0）
- 把灼烧伤害写实（§2.2）
- Boss 改为「冰滞」，与普通减速拉开差异（R1）
- 收紧「本场」类效果，只留白名单（R5）
- 双面字扩展为三面，新增「灵面·点化」（§3）
- 写明阈值类触发在复活时怎么处理，去掉依赖站位的条件（§5）
- 取消通用池，改为全部用系池，产出跟本系走（§7）
- 新增 UI 反馈要求，并规定实现前先交 designer 出稿（§9）

## 0. 术语（全稿统一口径）

| 词 | 含义 |
|---|---|
| 回合 | 玩家身上的效果按玩家回合计；敌人身上的状态按该敌人的行动次数计 |
| **场 / 本场** | 一场战斗，即一关（一层）。战斗结束即清 |
| **段** | 5 关，第 5 关是 Boss |
| **场景** | 10 关，一个主题。例如「字林」= 第 1~10 关 |
| **爬塔 / 本塔** | 一次登塔，直到死亡或放弃 |

各类载体的生命周期：
- 本场清空：灼、冻/缓、锐、落款卷轴、点化
- 跨场保留：字灵（召唤物），随本塔延续，所以挂在字灵身上的被动也跨场生效

| 系 | 关键词 | 规则 | Lv1（按档） | Lv3 强化 |
|---|---|---|---|---|
| 火 | **灼** | 见 §2.2 | 白 / 绿 / 蓝 1 层，紫 2，金 / 橙 3，红 4 | +1 层（红 +2，且首次结算不衰减） |

| 土 | **坚** | 玩家护甲，减伤 = 甲 / (甲+100)，持续 T 回合 | 护甲 A（按档），2 回合 | 4 回合（金档以上另 +50% 护甲；红为 6 回合） |
| 木 | **灵** | 召唤字灵，每只字灵带一条「本命被动」 | 召唤 + 本命被动 | 本命被动的离散量强化 |

### 2.1 等级缩放

- **离散量**（层数、回合、次数、段数、概率档）永不吃等级，只在 Lv3 变化。这顺带修掉现有"冻结 1 回合到 Lv2 变成 2 回合"的 bug。
- **连续量**（伤害、护盾、治疗、护甲点数）吃等级系数：系数 = 1 + 6% × (等级 − 1)，Lv8 = 1.42，Lv10 = 1.54。

### 2.2 灼烧伤害（取代 v2 里定义模糊的 D）

**单次结算伤害** = **20 × 火力 × 层数** × 玩家攻击% × 生克倍率

- 敌人身上的「灼」记两个数：
  - **层数**：上限 10（燚落款时 15）。注意上限 10 指的是层数，不是伤害。
  - **火力**：曾给它上过灼的火字里，最高的等级系数。只升不降。
- 每次结算后层数 −1。从 N 层自然烧完的总伤害为 20 × 火力 × N(N+1)/2。
- 引爆：一次性打出"烧完总伤害"，然后清层。

| 情形 | 每层 | 单次结算 | 烧完 / 引爆总计 |
|---|---|---|---|
| 热 Lv1，灼 1 | 20 | 20 | 20 |
| 烈 Lv3，灼 3（火力 1.12） | 22 | 67 | 134 |
| 任意 Lv1 叠满 10 层 | 20 | 200 | 1100 |
| 燚 Lv8，灼 6（火力 1.42） | 28 | 170 | 596 |

### 2.3 全局规则

**R1 控制**
- 冻结中的目标不能再被冻结，也不能延长冻结。
- 冻结结束后获得「霜抗」，回合数 = 刚结束那次冻结的回合数。霜抗在冻结递减之后挂上。
- 减速：速度 −50%，**不叠加，只刷新**，持续 N 回合。
- 概率定身一律视为冻结，吃霜抗。

**R1b Boss：冰滞（冻结的降级版，刻意和减速不同）**

| | 冰滞（冻结作用于 Boss 时） | 减速（作用于任何单位） |
|---|---|---|
| 时间效果 | **立即**把行动条回退 50% × 冻结回合数（最多 100%，等于推迟一整拍） | 持续 N 回合，速度 −50% |
| 附加 | 冰滞期间（直到它下次行动）受到伤害 +15%（「破冰」） | 无 |
| 叠加 | 之后获得霜抗，霜抗期间不能再冰滞 | 只刷新 |
| 视觉 | 冰裂纹，行动条结霜后回退的动画 | 水纹 chip，行动条变慢 |

- 一句话区分：冰滞是一次性的"打断节奏 + 易伤窗口"，减速是持续的"拖慢"。
- 只有红档的覆水难收能让 Boss 真正被冻结。

**R2 斩杀**
- 所有斩杀对 Boss 统一改为"本次伤害 ×2"。

**R3 结算顺序**
- 条件按**出字前**的状态判定。
- 顺序：伤害修饰 → 伤害 → Lv1/Lv3 状态 → Lv5/Lv8 后效。

**R4 防循环**
- 由特性触发的伤害，不再触发受击类和死亡类被动。
- 自损算"失去生命"，不算受击。
- 代价类效果（如 AP −1）不算减益，不能被净化或免疫。

**R5 持续时间与「本场」白名单**
- 默认规则：持续类效果一律写明回合数（通常 2~3 回合）；同名效果重复打出只刷新回合数，不叠加。
- 「本场」级效果只允许下表这些：

| 类别 | 条目 |
|---|---|
| 关键词资源 | 锐（本场保留） |
| 红档 Lv8 改规则 | 四火不熄、覆水难收、金刚不坏、厚德载物、擎天 |
| 灵面点化（§3，用户提议） | 字灵五行改变、土系嘲讽 |

- v2 中其余的「本场」条目已全部改为有时限：

| 条目 | v2 | v3 |
|---|---|---|
| 𨰻 百炼 | 本场累计暴伤 | 溢出时，下一张金字暴伤 +30% |
| 鑫 金玉满堂 | 本场锐上限 +3 | 3 回合内锐上限 +3 并补满，之后回落 |
| 圭 厚实 | 本场累计护甲 | 护甲 +5，持续 3 回合（可叠，≤+30） |
| 㙓 深厚 | 本场累计护甲 | 护盾被击碎时，获得击碎前护盾 20% 的护甲，持续 2 回合 |
| 㙓 Lv3 | 本场持续 | 6 回合 |
| 林 独木不成林 | 本场 | 3 回合 |
| 荆 荆天棘地 | 本场 | 3 回合 |
| 箭 万箭齐发 | 本场 | 接下来 3 次攻击 |
| 楸 一叶知秋 | 字灵在场期间（跨场） | 3 回合 |
| 桂 桂冠 | 未写时限 | 3 回合 |

- 同名字灵的 Lv4/Lv6 被动只生效一份。
- 护甲以外的减伤，合计上限 60%。

**R6 形状**
- 绑定现有 `TargetShape`：相邻 = Cleave，整排 = Sweep，一列 / 身后 = Skewer。
- Boss 占 2×2，被同一形状覆盖时只吃一次伤害；贯穿 Boss 时没有"身后"。

**R7 计数口径**
- "本场此前"不含本张，也不含部件直接出手。
- "段"（打击段数）指同一次出字对同一目标的分次结算；弹射、召唤物攻击不算。
- 注意区分：这里的打击"段"与 §0 的关卡"段"同字不同义，文案里打击统一写作「击」。

## 3. 出字三面：攻 / 护 / 灵（扩展原双面字）

原双面字有三个目的，三面方案逐一回应：

| 原目的 | 三面里怎么满足 |
|---|---|
| a. 木字防卡手：场上召唤物已满、都是最强的字又满血时，木字没处用 | 灵面·**嫁接**：打在已有字灵上，强化它而不是再召唤 |
| b. 克制补位：比如没有水字时，高护甲火怪只能慢慢磨 | 攻面保留，同时灵面·**点化**能把字灵改成克制它的五行 |
| c. 水只能奶、土只能盾，缺少可玩性 | 攻面保留；点化又让水、土字能经由字灵转化成进攻 |

三面的定义：

| 面 | 拖到哪里 | 结算内容 |
|---|---|---|
| **攻面** | 敌人 | 本体伤害 + Lv1/Lv3 + Lv5/Lv8（标为"攻"或"两面"的条目） |
| **护面** | 自己 / 空地 | 水治疗、土护盾、木召唤、利/锋增益 + Lv1/Lv3 + Lv5/Lv8（标为"护"或"两面"的条目）。火、金攻击字没有护面 |
| **灵面**（新） | **己方字灵** | 下表的「点化」；Lv5/Lv8 **不触发**；Lv4/Lv6 照常落款 |

**点化效果**（所有系都有，1 AP，字照常消耗）：

| 本字所属系 | 字灵五行变为（本场） | 附加效果 |
|---|---|---|
| 火 | 火 | 字灵攻击附带灼，层数 = 本字 Lv1/Lv3 的层数，本场有效 |
| 水 | 水 | 字灵回复本字的治疗量；攻击附带减速 1 回合（每回合 1 次） |
| 金 | 金 | 字灵获得自己的锐，层数 = 本字的层数（上限 5，本场） |
| 土 | 土 | 字灵获得**嘲讽（本场）**，外加本字的护盾量 |
| 木 | 不变 | **嫁接**：字灵回满生命，并获得本字的本命被动（本场；每只字灵最多嫁接 1 条） |

- 叠加规则：点化多次时，五行以最后一次为准；同类加成只刷新，不叠加。
- 引擎复用：现有 `NeedsAllyTarget` / `allySlot` 的友方目标流程，以及 `Unseal` 改召唤物属性的路径（`BattleEngine.cs` 约 3037 行）。

R6 中原有的双面细则保留：
- 土的「坚」攻、护两面都给。
- 水字在治疗面没有敌方目标时，控制施加给"下一个行动的敌人"。
- 木字走攻面出手时不召唤，被动改走落款。

## 4. 被动载体：落款卷轴

- **落款**：字打出后（攻面、护面、灵面都算），在卷轴上落款，已解锁的被动（最多 2 条）本场生效。没有已解锁被动的字不落款。
- **卷轴容量**：3 格，满了以后先进先出。
- **叠墨**：同名字再次打出时叠墨，而不是占新格。
  - 连续量 +50%（加法），最多叠 2 次。
  - 百分比、上限、阈值不放大。
  - 次数阀按"字 + 特性"计，被挤出卷轴后重新落款也不重置。
- **木系池被动**：在卷轴上时，作用对象是全部字灵；挂在字灵身上时，只作用于该字灵。
- **字形特性**（成字 / 拆字）：卡面自带，不走落款，每场每字 1 次。

## 5. 触发词表与规则

| 类别 | 触发点 |
|---|---|
| 受击 | 我方受击、护盾被击碎、生命跌破 50%、字灵受击 |
| 减益 | 我方施加减益；带某减益的敌人行动 / 受击 / 死亡；减益结束；我方被施加减益 |
| 战果 | 击杀、暴击、字灵阵亡 |
| 节奏 | 回合开始、回合结束、本回合打出 ≥2 张本系字、本场已打出 N 张某系字 |
| **字形** | **成字**、**拆字** |

**阈值类触发与复活**
- 「跌破 X%」：生命从 ≥X% 降到 <X% 时触发。
- 每个单位每场只触发 1 次。
- 以下复活都**不重置**这个计数，复活本身带来的血量变化也不算"跌破"：
  - 玩家看广告复活（每次爬塔 1 次，满血续战）
  - 字灵被复活（栉风沐雨 / 万木回春 / 擎天）
- 「致命伤保留 1 血」（扎根、盘根）同样是每单位每场 1 次，复活不重置。

**站位公平**
- 不设计"本回合未受伤"这类条件。原因：前排有字灵时，后排字灵和玩家只会被远程攻击打到，这类条件会让后排白拿收益（v2 的稳守因此删除）。
- 受击类触发保留：前排更容易触发，这是站位取舍的一部分。

**次数阀**：每条被动都带每回合或每场的次数上限。

## 7. 系池（取消通用池，产出全部跟本系走）

每系 6 条被动 + 2 条主动。每系都有一条"生命跌破 50%"阈值类和一条"本回合打出 ≥2 张本系字"节奏类，用来替代原通用池的振作和稳守。

| 系 | 被动 | 主动 |
|---|---|---|
| 火 | **反燎**：我方受击时，攻击者 +灼 1（每回合 1 次）<br>**火种**：灼烧中的敌人死亡时，相邻敌人 +灼 2<br>**焦躁**：灼 ≥3 层的敌人行动前，先结算一次灼烧（不衰减）<br>**烟熏**：灼烧中的敌人命中 −15%<br>**引火**：生命跌破 50% 时，全体敌人 +灼 2<br>**续薪**：本回合打出 ≥2 张火字时，回合结束随机 2 名敌人各 +灼 1 | **添薪**：目标已在灼烧时，额外 +2 层<br>**引燃**：引爆灼烧层数最高的一名敌人 |
| 水 | **寒意**：我方受击时，攻击者减速 1 回合（每回合 1 次）<br>**涤净**：被施加减益时回复 X（每回合 1 次）<br>**冰缚**：冻结中的敌人受伤 +20%<br>**回流**：治疗溢出的 50% 转为护盾<br>**回春**：生命跌破 50% 时回复 X<br>**潮汐**：本回合打出 ≥2 张水字时，回合结束回复 X | **凝冰**：目标已减速时，改为冻结 1 回合<br>**涓流**：清除我方 1 个减益，并回复 X |

## 9. UI 反馈要求（实现前交 designer 出稿）

**原则**：所有新增特性，包括被动，都要有可见的反馈。没有反馈的特性等于不存在（参考 2026-09-02 势/水势"全绿但不可见"的教训）。

| 场景 | 要设计的反馈 |
|---|---|
| 详情页 | 5 个特性槽：锁定 / 已解锁、解锁等级、类型图标（被动 / 受击 / 减益 / 主动 / 字形）、作用面标记【攻 / 护 / 两】 |
| 升级预览 | 新解锁的特性高亮，并展示其效果 |
| 落款卷轴 | 战斗内一条 3 格的卷轴：落款入场、被挤出、叠墨层数、次数阀剩余；被动触发时对应格闪烁，并飘出特性名 |
| 主动特性 | 出字时飘出特性名，与本体伤害数字区分 |
| 字形触发 | 合成 / 拆字动画上标注触发的特性；带印记的部件加角标 |
| 新状态 chip | 霜抗、冰滞、致命、标记、干涸、附着、桂冠、嘲讽 |
| 灵面 | 拖到己方字灵时的高亮和预览（变成什么五行、获得什么加成）；点化后字灵带五行角标 |
| 字灵被动 | 字灵身上显示已挂载的被动图标，触发时闪烁 |
| 关键词 | 灼（层数 + 火力）、锐（层数 / 上限）、冰滞 vs 减速的区分 |

**交付方式**：spec 定稿后，用 SendMessage 把本节清单和 spec 路径发给 designer 会话。P4 表现层要等 designer 交稿后再实现；P1–P3 可以同时并行推进。

## 10. 引擎与数据改造（实现要点）

1. **数据模型**
   - 新增 `TraitDef`：槽位、解锁等级、触发、条件、效果（复用 `EffectDef`）、次数阀、作用面。
   - `CharDef.Traits` 存放特性列表。
   - 出字时按 R3 的顺序结算。
2. **事件管线**（`BattleEngine.cs`）
   - **伤害上下文**：记录来源和触发深度，接入 `DamageEnemy`、`DamagePlayerDirect`、`DamageSummon` 三处。
   - **状态统一入口**：收口约 21 处 `Statuses.Apply`；霜抗、冰滞、杜绝的拦截都放在这里。
   - **击杀者**：经由 `ResolveDefeat` 和 `OnSummonDeath` 传出。
   - **新挂点**：回合开始 / 结束、`Compose`、`Dismantle`、阈值跌破。
   - **遍历顺序**：固定为先卷轴、后字灵槽位。
   - **随机**：特性使用独立的子随机流，并写入快照。
3. **新机制**
   - 落款卷轴、计数器、改规则开关、点化状态：全部进 `BattleSnapshot`，并补存读往返测试。
   - 冰滞：直接操作 `TurnScheduler` 的行动条（`Threshold = 10000`）。
   - 新增 `StatusKind`：只在末尾追加。
   - 拆字印记：不改动 `ForgeState.Pool`，另用一个计数字典记录。
   - 灵面：复用 `NeedsAllyTarget` 和 `Unseal` 的路径。
3a. **阈值类触发**：按单位、按场计数，复活不重置。
4. **管线**
   - 特性表按系拆成五个独立文件。
   - `extract_values.py` / `export_chars.py` 输出 `traits`，由 `ConfigLoader` 解析。
   - 移除旧的附加效果和 `rebalance_2026_09_05.py` 的价目体系。
5. **数值**
   - 每级成长从 +11.7% 降到 +6%。
   - 离散量不吃等级。
6. **表现层**：按 §9 的 designer 稿实现。新状态要同时接三处：`StatusText.Of`、`BattleView` 的 chip、`CharInfo`。新文案进字符串表后重跑字体子集。

## 11. 流程与验证

**流程**

1. 本 spec 提交并请用户审阅。
2. 审阅通过后，通知 designer（§9），同时用 writing-plans 拆出实施计划。
3. 分阶段执行：

| 阶段 | 内容 |
|---|---|
| P1 | Core 事件管线、`TraitDef`、落款、冰滞、灵面。先做"零特性时结果逐位恒等"，用 `tools/trace` 对照 |
| P2 | 管线与数据格式 |
| P3 | 五系特性数据，五系并行 |
| P4 | 表现层（等 designer 稿） |
| P5 | 平衡定标 |

**验证**

- **Core 走 TDD**：每条特性先写失败测试；重点覆盖 R1–R7、阈值与复活、灵面。
- **全量通过**：
  - pytest 六个目录
  - `tools/coretests`
  - `tools/prescompile`（在 worktree 里要覆盖程序集路径）
  - `tools/balance`、`tools/chestsim`、`tools/trace` 三处 build
- **仿真**：用 `tools/balance` 跑各档 Lv1 / Lv5 / Lv8 的卒层，确认呈梯度。
- **人工验收**：用户在 Unity 里跑 EditMode，并实际试玩。
