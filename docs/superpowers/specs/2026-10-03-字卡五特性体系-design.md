# 字卡五特性体系 · 设计（v4）

> 状态：待用户审阅（2026-10-03）。
> 版本沿革：v1 → v2 设计评审；v2 → v3 用户第一轮 8 条反馈；v3 → v4 用户第二轮 5 条反馈。
> 本稿不继承现有技能树和字卡附加效果。生效后，以下两项作废：`rebalance_2026_09_05.py` 的特性价目体系，以及 09-05 字表平衡 spec 中的「本体特性配额」。

## Context

**现状问题**：字卡等级（1~10）只放大数值，不解锁任何东西。卡面上的"特性"是效果列表里的附加效果，没有独立数据，也没有成长感。引擎没有触发系统。

**目标**：
- 每张字 5 个特性，随等级解锁，与字义绑定，稀有度越高越强、越独占。
- 每张字有 **攻 / 护 / 灵** 三面。在合适的场景下，三面都值得用，不会被别的字替代。

**v4 相对 v3 的主要变化**：

| # | 用户反馈 | v4 的处理 |
|---|---|---|
| 1 | 部分特性应能跨场、跨段、跨场景，但要防止无限叠加 | 新增 §4 存续层级 + 防无限叠加六律 |
| 2 | Cleave/Sweep/Skewer 是动作名，不是范围名 | 改名为范围语义的 `TargetArea`（§6） |
| 3 | 加入三面后，详情页要重设计 | 列入 §11，交 designer |
| 4 | 每一面都要有存在价值；不受现有攻 / 护面束缚 | 三面从零重做，每张字定一个主面；特性按「三面各得其一」分配（§2） |
| 5 | 落款卷轴难上手 | **取消落款**。被动改为叠加在面上：要么修饰本字某一面，要么附着在该面产出的东西上（§2.3） |

## 0. 术语

| 词 | 含义 |
|---|---|
| 回合 | 玩家身上的效果按玩家回合计；敌人身上的状态按该敌人的行动次数计 |
| **场** | 一场战斗 = 一关 = 一层 |
| **段** | 5 关，第 5 关为 Boss |
| **场景** | 10 关，一个主题，例如「字林」= 第 1~10 关 |
| **爬塔 / 本塔** | 一次登塔，直到死亡或放弃 |
| **灵** | 场上的友方单位，统称「字灵」，分两类：**战灵**（木系，会普攻）和**器灵**（其余四系，不普攻、按回合生效） |
| **击** | 一次出字对同一目标的分次结算。用来和关卡的「段」区分 |

## 1. 等级阶梯（用户拍板）

| 等级 | 内容 | 作用的面 |
|---|---|---|
| Lv1 | ① 基础特性：本系关键词 | 三面通用 |
| Lv2 | 只涨数值 | — |
| Lv3 | ① 强化：放大 Lv1 的离散量 | 三面通用 |
| Lv4 | ② **通面被动**：修饰本字所有面 | 三面通用 |
| Lv5 | ③ **主动 I** | 副面 A 专属 |
| Lv6 | ④ **被动** | 副面 B 专属 |
| Lv7 | 只涨数值 | — |
| Lv8 | ⑤ **主动 II**：招牌 | **主面**专属 |
| Lv9 / 10 | 只涨数值 | — |

数值成长为每级 +6%（Lv8 为 ×1.42，Lv10 为 ×1.54）。离散量（层、回合、次数、击数、概率档）永不吃等级缩放，只在 Lv3 变化。

## 2. 三面：攻 / 护 / 灵

### 2.1 三面的定义（从零重做）

| 面 | 拖到哪里 | 定位 | 一句话 |
|---|---|---|---|
| **攻** | 敌人 | 当下输出 | 打出伤害，同时用本系关键词进攻 |
| **护** | 玩家 / 己方 | 当下保命 | 用本系的方式守 |
| **灵** | 空灵位 → **化灵**；已有的灵 → **点化** | **投资**（跨回合，可跨场） | 把这张字留在场上 |

- 三面都消耗 1 AP，用完这张字即消耗。
- 每张字有一个**主面**：本体数值按 100% 结算。另两面是**副面**：本体数值按 60% 结算（具体比例待仿真定标）。
- 副面的价值不靠本体数值，而靠 Lv5 / Lv6 给它的情境能力。

### 2.2 特性分配：三面各得其一

- **主面**拿 Lv8。
- **副面 A** 拿 Lv5。
- **副面 B** 拿 Lv6。
- Lv1、Lv3、Lv4 三面通用。

所以满级字的每一面都至少有一个专属特性，玩家不会因为选了某一面而"丢掉"一条特性。

### 2.3 被动的落点（取消落款）

被动只有两种形态：

1. **面修饰**：改变本字某一面的数值或条件。例如"本字克制时 +15%"、"本字施加的灼 +1 层"。
2. **产出附着**：挂在这一面**产出的东西**上。产出可以是护面给出的护盾或架势、灵面化出的灵、攻面施加的状态。被动随这个产出存续，受击触发、减益触发都由产出来承载。

两种形态都不需要玩家身上的额外载体。

### 2.4 灵面：化灵与点化

**化灵**：拖到空灵位时，按本字五行化出一只灵。

| 系 | 灵 | 默认行为 |
|---|---|---|
| 火 | 火灵（器） | 每回合开始给随机一名敌人 +灼 N |
| 水 | 泉灵（器） | 每回合开始治疗生命最低的友方；受击时让攻击者减速 1 回合 |
| 金 | 剑灵（器） | 每回合开始斩击生命最低的敌人（本体 40%，吃锐） |
| 土 | 石灵（器） | 生命高，带嘲讽，护甲 = 本字护甲 |
| 木 | 木灵（**战**） | 会普攻，带本命被动；「生」：每场战斗开始攻击和生命 +10%（最多 3 次） |

**点化**：拖到已有的灵身上。
- 该灵的五行改为本字五行（本场有效），并获得本字关键词带来的加成：

| 本字系 | 灵获得的加成 |
|---|---|
| 火 | 攻击 / 生效时附灼 N |
| 水 | 回复本字治疗量，受击时攻击者减速 |
| 金 | 获得自己的锐 N |
| 土 | 嘲讽（本场）+ 本字护盾量 |
| 木 | 嫁接本字的本命被动（本场），并回满生命 |

- 如果点化的是同名的灵，则改为**续灵**：刷新存续时间并回满生命。
- 点化正好解决原双面字的三个目的：
  - 木字防卡手：灵位满了也能嫁接。
  - 克制补位：把灵改成克制敌人的五行。
  - 水、土字缺进攻：经由灵转化为输出。

**灵位**：沿用现有召唤槽位（最多 8 个，前后排各 4，按层数解锁）。同名的灵在场上唯一。

## 3. 五系关键词与三面表达

| 系 | 关键词 | 攻面 Lv1 | 护面 Lv1 | 灵面 Lv1 | Lv3 |
|---|---|---|---|---|---|
| 火 | **灼**（§3.1） | 伤害 + 灼 N | **炎甲**：护盾 + 2 回合内受击时攻击者 +灼 N（每回合 2 次） | 火灵每回合施灼 N | N+1（红档 +2） |
| 水 | **寒**（冻结 / 减速，§5 R1） | 伤害 + 冻结或减速 1 回合 | 治疗 + 下一个行动的敌人减速 1 回合 | 泉灵 | 回合 +1 |
| 金 | **锐**（玩家层数 ≤5，本场保留；每层金系伤害 +8%） | 伤害 + 锐 N | **架势**：格挡 2 次（受击减伤 40% 并反击本体 30%）+ 锐 N | 剑灵 + 锐 N | 锐 +1（红档 +2） |
| 土 | **坚**（护甲 / 破甲） | 伤害 + 目标破甲 A，2 回合 | 护盾 + 护甲 A，2 回合 | 石灵，护甲 A | 持续 4 回合；石灵护甲 +50% |
| 木 | **生**（回复 / 成长） | 伤害 + **种** 2 回合（目标每次行动，我方生命最低的单位回复 X） | **荫**：全体字灵回复 X，玩家回复 X×50% | 木灵 + 本命被动 | 种 +1 回合；本命被动强化 |

各档 N：
- 灼：白 / 绿 / 蓝 1 层，紫 2，金 / 橙 3，红 4。
- 锐：白 / 绿 / 蓝 1，紫 / 金 2，橙 / 红 3。
- 护甲 A：按档递增，数值由仿真定标。

### 3.1 灼烧伤害

**单次结算伤害 = 20 × 火力 × 层数 × 玩家攻击% × 生克倍率**

- 层数上限为 10（燚 Lv4 可提到 15）。这里限制的是层数，不是伤害。
- **火力**：曾给目标上过灼的火字里，最高的等级系数。只升不降。
- 每次结算后层数 −1。从 N 层自然烧完，总伤害 = 20 × 火力 × N(N+1)/2。
- 引爆：一次性打出上面这个"烧完总伤害"，然后清层。

| 情形 | 单次结算 | 烧完 / 引爆总计 |
|---|---|---|
| 热 Lv1，灼 1 | 20 | 20 |
| 烈 Lv3，灼 3（火力 1.12） | 67 | 134 |
| 任意 Lv1 叠满 10 层 | 200 | 1100 |
| 燚 Lv8，灼 6（火力 1.42） | 170 | 596 |

## 4. 存续层级与防无限叠加（反馈 1）

### 4.1 存续层级

| 层级 | 何时清除 | 允许用于 |
|---|---|---|
| 即时 | 本次结算后 | 主动特性 |
| N 回合 | N 回合后 | 多数状态、护面增益 |
| 本场 | 战斗结束 | 灼、寒、锐、点化、红档改规则 |
| **跨场** | N 场后（按场数计） | 蓝 / 紫档的器灵（3 场）、留存护盾 |
| **跨段** | 5 场 | 金 / 橙档的器灵 |
| **跨场景** | 10 场 | 红档的器灵 |
| 本塔 | 死亡时 | **只有木灵**（直到阵亡），以及它的成长（上限 3 次） |

白 / 绿档的器灵只存续本场。稀有度越高，器灵留得越久，这是高档灵面的核心价值。

### 4.2 防无限叠加六律

以「无限叠盾 + 盾反 = 无敌」为反例逐条堵住：

1. **同类取最强**：同一载体上的同类持续效果（护盾附加属性、反伤、减伤、增攻）不叠加，只保留最强的一份并刷新存续。
2. **硬上限**：
   - 护盾 ≤ 最大生命 100%。
   - 跨场携带的护盾 ≤ 最大生命 30%（红档厚德载物可提到 60%）。
   - 锐 ≤ 5（红档金刚不坏可提到 10）。
   - 灼 ≤ 10 层。
3. **反伤封顶**：所有反伤来源（炎甲、反震、荆棘、格挡反击）合计不超过本次所受伤害的 60%。反伤不吃增伤乘区、不暴击，也不能产生护盾。
4. **减伤封顶**：护甲以外的减伤合计 ≤ 60%。
5. **跨场只存不长**：跨场的效果在后续战斗中数值冻结，不再成长。唯一例外是木灵的「生」，且有上限。
6. **跨场以场数计**：跨场效果一律有明确的场数或次数，不存在无限存续。Boss 的倾覆（清空护盾）保留，作为天然的反制。

**护盾的留存规则**：护盾默认在回合末清除。标注了「留存」的护盾不清除，但留存总量受第 2 律的 30% 上限约束。

## 5. 全局规则

**R1 寒（控制）**
- 冻结中的目标不能再冻结，也不能延长冻结。
- 冻结结束后获得「霜抗」，回合数等于刚结束那次冻结的回合数。
- 减速为速度 −50%，不叠加，只刷新。
- 概率定身一律视为冻结。

**R1b Boss 冰滞**
- 冻结作用于 Boss 时变为「冰滞」：立即把行动条回退 50% × 冻结回合数（最多 100%）。冰滞持续到它下次行动，期间受到伤害 +15%。之后获得霜抗。
- 与减速的区别：减速是持续变慢，冰滞是一次性打断节奏并打开易伤窗口；视觉上也要区分。
- 只有红档的「覆水难收」能让 Boss 真正被冻结。

**R2 斩杀**：对 Boss 一律改为本次伤害 ×2。

**R3 结算顺序**
- 条件按出字之前的状态判定。
- 顺序：伤害修饰 → 伤害 → Lv1 / Lv3 状态 → Lv5 / Lv8 后效。

**R4 防循环**
- 由特性触发的伤害，不再触发受击类和死亡类被动。
- 自损算"失去生命"，不算受击。
- 代价类效果（如 AP −1）不算减益，不能被净化或免疫。

**R5 阈值与复活**
- 「跌破 X%」= 生命从 ≥X% 降到 <X%。每个单位每场只触发 1 次。
- 玩家看广告复活、字灵被复活，都不重置这个计数。复活本身带来的血量变化也不算一次跌破。
- 「致命伤保留 1 血」同样是每个单位每场 1 次。

**R6 站位公平**：不设计"本回合未受伤"之类的条件。后排灵和玩家常被前排挡住，这类条件会让它们白拿收益。

**R7 计数**：「本场此前」不含本张，也不含部件直出。

## 6. 目标范围改名（反馈 2）

现有 `TargetShape` 的值是动作名。改名为 **`TargetArea`**，按范围语义命名，复用现有的展开逻辑（`Targeting.ExpandTargets`）：

| 新名 | 中文 | 范围 | 原名 |
|---|---|---|---|
| `Single` | 单体 | 只打主目标 | Single |
| `Adjacent` | 相邻 | 主目标 + 同排左右邻格 | Cleave（溅射） |
| `Row` | 整排 | 主目标所在的整排 | Sweep（横扫） |
| `Column` | 整列 | 主目标所在列，前后排 | Skewer（贯穿） |
| `Scatter` | 散布 | 后排优先，取 N 个目标，不足时循环补足，可重复 | Volley（连发） |
| `Chain` | 连锁 | 主目标起，按距离跳到不重复的目标，逐跳衰减 | Chain（弹射） |
| `All` | 全体 | 全部敌人。并入后取代 `EffectKind.DamageAll` | 新增 |

- 卡面文案仍可以用「横扫」「贯穿」这类动词修辞，但规则和数据一律用范围名。
- Boss 占 2×2，被同一范围覆盖时只结算一次。

## 9. 全卡表（55 字）

- Lv1 / Lv3 按 §3 的系规则取档位数值，只有例外的字才单独写出。
- 「U·名」= 通用池，「池·名」= 系池。

## 10. 引擎与数据改造（实现要点）

1. **数据模型**
   - `TraitDef`：槽位、解锁等级、作用面（攻 / 护 / 灵 / 通面）、形态（主动 / 面修饰 / 产出附着 / 字形）、效果（复用 `EffectDef`）、次数阀。
   - `CharDef` 新增 `MainFace`、三面本体效果、`Traits`。
2. **出字**
   - `Cast` 新增面参数。灵面的友方目标沿用 `NeedsAllyTarget` / `allySlot`。
   - 改五行沿用 `Unseal` 改召唤物属性的路径。
   - 副面本体按 60% 结算。
3. **灵**
   - `SummonState` 增加类型字段（战灵 / 器灵）、器灵的回合行为、存续场数。
   - 存续场数由 `RunEngine` 的召唤物携带（`_carriedSummons`）逐场递减。
   - 同名的灵唯一。
4. **事件管线**（`BattleEngine.cs`）
   - 伤害上下文：来源 + 触发深度，接入 `DamageEnemy`、`DamagePlayerDirect`、`DamageSummon` 三个入口。
   - 状态统一入口：收口约 21 处 `Statuses.Apply`，霜抗、冰滞、杜绝的拦截都放在这里。
   - 击杀者：`ResolveDefeat` 和 `OnSummonDeath` 要带上击杀者。
   - 新挂点：回合开始 / 结束、`Compose`、`Dismantle`、阈值跌破。
   - 产出附着的被动挂在产出对象上（护盾 / 架势状态、灵、敌方状态），随对象消亡。
5. **范围**
   - `TargetShape` 改名为 `TargetArea`，并入 `All`，退役 `EffectKind.DamageAll`。
   - 同步修改 `Targeting.ExpandTargets`、管线 token 和详表。
6. **上限**
   - §4.2 的硬上限集中放在一个规则类里。
   - 战后护盾携带改为 ≤ 最大生命 30%（现为按 `ShieldCarryPercent` 保留 50%）。
7. **快照**
   - 新增的灵类型、存续、点化状态、各特性计数，全部进 `BattleSnapshot` / `RunSnapshot`，并配一个全字段的存读往返测试。
   - `StatusKind` 只能在末尾追加。
   - 拆字印记用一个计数字典，不改动 `ForgeState.Pool`。
8. **管线**
   - 特性表按系拆成五个文件。
   - `extract_values.py` / `export_chars.py` 输出 `mainFace`、三面和 `traits`；由 `ConfigLoader` 解析。
   - 移除旧的附加效果和 `rebalance_2026_09_05.py` 的价目体系。
