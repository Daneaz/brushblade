升级确认弹窗：花墨锭把一张字升一级之前的那一张对照表。实现是 `CollectionView.ShowUpgradePreview`。

## 为什么单独立一张卡
它是局外唯一一处**花钱且不可撤销**的确认，而它解决的问题是「玩家得自己在两串长句子里找哪个数变了」。那套「旧 → 新 (+差)」的读法与「没变的收成一行灰字」的收尾，是这张卡真正要定下来的东西。

## 版面（逻辑单位 → 稿面 pt，1pt = 2.093）
- 外壳 `Ui.Sheet` 1088×670（520×320pt），遮罩 `scrim`（55%，局外模态用满档），`dismissable: true` —— 点遮罩即关，因为它是可选操作。
- 自上而下五段：

| 段 | 内容 | 尺寸 |
| --- | --- | --- |
| 头 | 「升级「冰」」+ 右侧警示句 | 标题 34（16.2pt）宋体；警示 19（9.1pt）`text-faint` |
| 牌行 | 旧牌（压 `locked-paper`）→ `→` → 新牌 → 「升到 Lv.N」chip | 牌 130×163（62×78pt），gap 29；`→` 29 `exit-pink`；chip `jade` 底白字 21 |
| 正文 | 左「数值提升」/ 右「层数与特性」两栏并排 | gap 25，两栏各 `flex:1` |
| 收尾 | 「不变：斩杀 · 穿刺」一行灰字 | 18（8.6pt）`text-faint`，开 Wrap |
| 钮 | 「确认升级」（弹性宽）+「再想想」250 定宽 | 高 71（34pt），字号 24 |

## 差异行 `DeltaRow`（两栏共用，读法因此完全一致）
定高 54（25.8pt），`panel-inset` 底、圆角 12，左右内边距 17。一行的顺序是：
**[chip] 名 ——— 旧 → 新 (+差)**

- chip：有图标的走 `CardTraits.ChipColor` + 图标；没图标的退成词组 chip（`locked-bg` 底压 `text-main`）。
- 名 19（9.1pt）`text-dim`，`flexWidth:1` 把右边那组顶到行尾。
- 旧值 25 宋体 `text-faint` → `→` 18 `text-faint` → **新值 29 宋体 `upgrade-text`** → 增量 19 `upgrade-text`。
- 新值比旧值大一号、且是全行唯一的深绿 —— 一眼扫下去就是「变了的那一列」。

## 硬规则
- **不印重复卡与墨锭消耗**（2026-09-04 拍板）。不够根本走不到这一页 —— 详情页那颗按钮就是灰的、点不动。印出来只是把「你付得起」再说一遍。
- **没变的东西必须写出来。** 那一行灰字回答的是「我会不会丢掉什么」，不是凑字数。
- **一栏没有任何变化时写一句话占位**（「这一级没有数值变化」/「这一级没有层数或特性变化」），不留空 —— 空白读起来像没加载出来。
- 主钮是**赭金底压 `gold-text`**：赭金是「花墨锭」的语义（墨锭条、价格、`IngotGold` 都在这一支）。取消档「再想想」排最右，`locked-bg` 底。

## 使用方提供
字的定义、当前等级。前后两套数值与特性由 `CollectionStats.Of` / `CardTraits.Of` 各算一遍再逐条比对，调用方不用自己算差值。

## 关联
升完把详情弹窗重开（`ShowCharSheet`）——新等级与新数值就是这次操作的反馈。角标与牌脚见 CardFace，牌本身见 GlyphTile。

## 与实现的差异（本系统记录）
- 2026-09-21 把主钮从 `jade` + 白字（4.52:1，且与技能树的同语义钮是两套色）改成 `gold` + `gold-text`（5.47:1），与技能解锁钮并成一套。
- 同日把「+N」增量与新值的 `jade`（压 `panel-paper` 只有 4.26:1）换成 `upgrade-text`（8.32:1）。
- **画布上的四张角色升级弹窗稿（`LevelUp` / `LevelUpCapped` / `LevelUpMulti` / `LevelUpChest`）不是这一张。** 那四张画的是**角色**升级（叠在安全层与登塔结算之上），全仓搜不到实现；本卡是**字牌**升级。两件事别混。
