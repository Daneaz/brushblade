## 来源口径

**本系统描述的是游戏的现状，不是目标稿。** 2026-09-20 定下的口径：

- **设计系统 = 已实现的现状 + 拍板的规则。** token、原则、文案规则是硬规则；组件卡与整屏卡以 Unity 实现为准（尺寸常量取自代码，逻辑单位 ÷ 2.093）。
- **「字·斗 界面重设计」画布 = 草稿与提案。** 画布上的方案拍板、在 Unity 里实现之后，才同步进本系统；画布与本系统冲突时，以本系统为准，画布上的那一版视为未落地的提案。
- 例外是明确标了「重设计」的卡：它是拍板但未实现的目标稿，实现完成后改标「实现」。

- **`component/bundle.css` 里有一整块过期旧稿样式（46 行）在覆盖实现值。** Dialog / NavTab / InkCounter / ProgressBar 各有两套规则，新版在前、旧稿版在后，同特异度下旧版全胜 —— 于是墨锭长出了本不存在的胶囊底、四条层段进度条全画成赭金、血条轨道用了早已废弃的 `track-battle`。整段已删。同时把两处引用未定义 token `--lock-gray` 的地方改成 `text-faint`（`Theme.LockGray` 就是这一支）。

2026-09-20 把最后七张「稿」卡逐张按代码重画，标「稿」的已清零。那一轮改掉的主要出入：

组件卡片的样式是静态再现（`component/bundle.css`，类名 `zd-` 前缀），不是运行时组件库 —— 游戏本体是 Unity uGUI。仓库设计稿副本在 `docs/design/drafts/scenes/`（怪物设计、技能树两页只在画布里）。稿与实现不一致时，先确认是稿过时还是实现走样；改了哪边都要在稿的 README 里留痕。
