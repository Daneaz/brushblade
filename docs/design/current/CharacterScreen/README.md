## 读法 / 交互

- **两层横滚上下分开、不嵌套**：上面的等级奖励轨道自己横滚；下面只有统计面板套 `Ui.HScrollFill`（最小排版宽 `RightMinW` = 1265）：基准机铺满拖不动，16:9 下视口约 914，横向滚出约 351。
- **打开即聚焦**（`ScrollToClaimable`，等一帧拿视口宽）：把 `LevelRewardRules.FocusLevel`（Lv.2 起第一个宝箱或里程碑可领的格）滚到视口左侧、左边留 1 格；都领完（聚焦格 = 当前等级且它没东西可领）→ 当前等级那格的左缘落在视口 60% 处。Lv.1 停在最左。
- **重建保持滚动位置**：切页签、领宝箱、领里程碑都整页 `Rebuild`；重建前从 `_trackScroll` / `_statsScroll` 两个引用读出 `_trackScrollX` / `_rightScrollX`，重建后恢复。只有首次打开（`_trackScrollX` 为 null）才聚焦。
- **边缘小签**：点左签把左侧最近的屏外可领格滚到视口左（左留 1 格），点右签把右侧最近的屏外可领格滚到视口右（右留 1 格），直接跳、不做过渡动画。
- 「领奖励」「领 取」用石青 `cta`（2026-10-04 五色语义；每格一个决策区，同屏几颗不违规）。可领钉不再带光环（稿 `p-ready` 无光环）。
- 每级宝箱只填空箱位、从不占暂存位；箱位满时待领不作废，地图角色入口红点照样亮（`LevelRewardRules.HasClaimableReward`）。
- 属性值读 `MetaRules.BuildBattleConfig`（与局内、主界面同源，含技能加成）；「下一级」增量只按等级曲线算 `f(L+1) − f(L)`，AP 恒写「—」。暴击不上屏。
- 页签切换 = 改 `_tab` 后整页 `Rebuild`（只保留两处横向滚动位置，其余状态不保留）。
- 保底的展示顺序是金 → 橙 → 红（把 `ChestRules.PityRules` 的红 → 橙 → 金倒过来读），读的是真实计数 `GoldPity / OrangePity / RedPity`。

## 与拍板稿的差异（`drafts/character-chest-claim/Claim.dc.html` + `README.md` §1，按代码画）

1. **未达宝箱不去色**：稿「去色 70% + 45%」，uGUI 没有现成的去色材质，只压了 45% 透明度（`CharacterView.ChestIcon`）。
2. **里程碑全领完的顶条不随圆角**：稿是 `inset box-shadow`，贴着卡的圆角走；代码是一条直角 `Image` 挂在卡面顶边，左右两端在圆角处会探出卡面圆弧约 2–3 像素。
3. **边缘小签箭头 ◂ ▸ → ◀ ▶**：Noto Serif SC 没有 ◂ ▸ 字形，字体子集测试要求两套子集都覆盖全部文案字符（`tools/fonts/tests/test_subset.py`），换成两套都有的 ◀ ▶（`character.rewards.edge_left / edge_right`）。
4. **边缘小签**无投影（稿 `box-shadow 0 1px 4px`）；点了直接跳到目标位置，没有稿上 `.strip` 的 0.25s 过渡；左签滚到最近的左侧可领格（左留 1 格）、右签滚到最近的右侧可领格（右留 1 格）。
5. **底线颜色**：稿 README 写「`rarity-gold`（同现状）」，而旧现状其实是 `jade`；按稿取 `rarity-gold`（稿 CSS 是 #CA9D33 赭金，与 `rarity-gold` #C9A94A 肉眼难辨）。底线底色仍是 `Ui.Bar` 的 `paper-dim`（稿 `panel-border`，两者几乎同值）。
6. **副标「每 10 级」的切换点**：按稿的局面代码，当前等级 **≥ 50** 就写「每 10 级里程碑」（plan 写的是「> 50」）—— Lv.50 时轨道后面露出的下一个里程碑已是 Lv.60。
