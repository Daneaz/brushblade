安全层整屏（932×430pt 横屏）：v0.7 核心循环里唯一一个主动决策点 —— 继续深入，还是收官撤退。对应实现 `GameRoot.ShowSafeLayer`（2026-10-04 照代码重画：标题 / 段位行 / 状态行 / 岔路文案全部换成字符串表原文，补首破弹窗）。

## 为什么单独立一张卡
「取舍写在钮**下面**，不藏在小字里」这条规矩就是这一屏定义的。它存在的唯一理由是让人做这个取舍，把取舍写小了它就白存在。别处凡是要玩家在两条不可逆的路里挑一条，都照这一版。

## 何时出现
每段第 5 层（Boss 层）告捷、Boss 层战利品选完（或跳过）之后直接进入（2026-10-04 起不再经「本段告捷」那一屏；`OnSegmentEnded` → `ShowSafeLayer`）。示例：preview 上屏是第 25 层（精英 Boss 层），下屏是第 30 层（本段主题 Boss，首次击破，叠首破弹窗）。

- **角色升级弹窗**：这一段升了级时，`LevelUpPopup` 再叠在最上面（在首破弹窗之上）。现状见 `current/LevelUpSheet/`。

## 硬规则
- **取舍句写在钮下面，不是 tooltip、不是一行小字。** 「深入」的钮上写清进哪一段、打哪几层，钮下说这一步的得失；「收官撤退」下写清「层数纪录保留，下次从第 1 层重来」。
- **朱砂给「深入」（默认推进项），`ink-soft` 给「收官撤退」。** 一屏一个朱砂主钮（首破弹窗的「知道了」在弹窗里，不算这一屏）。不可逆的份量由钮下那句话承担，不由颜色喊。
- **本趟已挣那行刻意不用 `InkCounter`**（没有墨锭图标）。它报的是本趟的战绩总量，不是可花的余额 —— 余额在右上角标里。
- 说明文本必须自己定宽定高。`Text.preferredWidth` 报的是不换行时的整句宽，靠 `flexWidth` 撑列会退化成「谁的字长谁就宽」。

## 使用方提供
当前深度、本趟已挣墨锭（含首破）、下一段的段名与层区间、首破的层段（可空）、两条路的回调。

## 登塔结算（`ShowTowerSettle`）与本屏的异同
同样是居中宣纸卡 + `BalanceCorner`，但**底色不同**：结算页走 `NewView("TowerSettleView")` 没传层段色，底是纯 `paper`，**没有层段染色、没有巨字水印**。宣纸卡 1172×680（560×325pt），圆角 25、描边 2，内边距 上 42 / 左右 59 / 下 46，gap 21。内容：标题「登 塔 结 算」46 宋体 → headline 23 `text-dim`（「第 {depth} 层收官!本趟已挣墨锭 {ink}」/「卒于第 {depth} 层……」/「于第 {depth} 层弃塔……」）→ 墨锭大数（`Ui.IngotLabel` 84，带图标）→（破纪录时）`gold-soft`/`gold-deep` chip「新纪录 · {from} → {to} 层」→ 宝箱行 `ChestRow` →「返回地图」朱砂 544×84、字号 31。
`ChestRow` 高 105 = 色块 63 + 内边距 38 + 描边 4，白底 `panel-border` 边、圆角 21；**立绘取 `ChestView.State.Idle` 而不是 `Ready`** —— `Ready` 的金光晕在主界面的意思是「现在能开」，画在结算页是假承诺。标题「获得{tierName}」26 宋体，说明 20 `text-faint`（「第 {chestDepth} 层 Boss 战利」/ 箱位满暂存「箱位已满,开掉一只即可领取」/ 暂存也满「箱位已满,暂存也已有一只,这只没能收下」）。没破 Boss 时走空态：`paper` 底 + `text-faint` 边，「本次未破 Boss,无宝箱」。升级弹窗同样叠在结算页之上。

## 术语
同一个数（`EarnedInk` + 首破墨锭）在安全层与结算页统一叫「本趟已挣墨锭」（说明句里简称「本趟已挣」）。旧称「滚存」是半额结算时代的残留（2026-08-30 取消后它已是纯展示量），2026-10-04 起不再出现在玩家可见文案里；字符串 key 仍叫 `rollover_unit`，只是 key 名。
