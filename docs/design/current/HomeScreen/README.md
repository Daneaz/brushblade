## 16:9 屏比（2026-10-04 验算）

`CanvasScaler` 1600×900 按高匹配，画布高恒 900、宽随屏比变。两档：**基准机** 932×430pt，两侧刘海各让 62pt → 根宽 ≈ 1691，`.safe` 不再补，内容区 1691；**16:9 无刘海机**根宽 1600，`SafeArea.MissingInset()` 两侧各补 123 → 内容区 1354。两张浮层挂在根上、不扣补边：基准机 1691 / 16:9 1600。

## 读法

- 主钮上只放动作，层段与层数放在按钮下 —— 523 的钮里排不下「续 爬 ·「墨海」第 44 层」。
- 没有断点存档时：主钮文案换成「登 塔」，钮下只有一行「每 5 层一位 Boss,战胜后可收官或深入」21（10.03）`text-dim`，**不出**层数详情、血条、账目与断点说明。
- 红点各有各的判据，都问 Core：左栏 = `MilestoneRules.HasClaimable`（有里程碑可领）；收集 = 有字能升 **或** 有没看过的新字；图鉴 = 有已解锁未查阅的条目；技能 = 有技能现在就能升；商城 = `ShopRules.HasRedDot`。亮着而点进去无事可做是最烦人的那种假消息。
- 页签图标 PNG 缺失时**什么都不画**（名字就在旁边），不补兜底汉字。

角色数值（读 `MetaRules.BuildBattleConfig`，与局内同源，屏上不另算一遍；**暴击不上屏** —— 基准恒 0 且不随等级成长）、等级与经验（`MetaRules.LevelProgress`）、出手统计（`Stats.CardPlays`）、里程碑可领与否、层段进度、宝箱队列与暂存数、四格页签的计数与红点判据、结算提示文本。

## 已知差异

- **Unity 的 `UI.Text` 没有字距设置**：稿上所有 `letter-spacing` 在实现里恒为 0。标题里的间隔是**写进字符串**的空格（「字 · 斗」「续 爬」「登 塔」），不是排版属性。
- 段位行与本趟账目在稿上把数字挑出来放大加朱砂，实现里各是**一个** `Ui.ThemedLabel`、一种颜色 —— Unity 的 `Text` 不分段着色。
- `component/bundle.css` 的 `.zd-btn--ad` 照抄了宝箱钮的字号 9.08 / 圆角 6.69，与 72×46 这枚 `AdBadge` 的缩放值对不上；本卡 `preview.html` 用 `.dev .zd-btn--ad` 就地覆盖成实现值。通用的 `.zd-btn[disabled]`（`locked-bg` 底、`text-dim` 字）也不是 uGUI 的置灰路径，本卡同样就地覆盖。
