# 卡详情 · 五行说明弹窗

需求来源:session `card-detail-attribute-tips`(2026-10-21)转用户 —— 卡详情顶部右侧加「?」,点开该卡所属五行的说明,
点空白处或关闭钮关闭。文案由用户审定,**逐字使用**。同日用户补充:金系「锋刃回鞘」的伤害加成随技能树「断金」变化
(spec `docs/superpowers/specs/2026-10-19-金系锋刃回鞘-design.md` §2)。土系「破甲」措辞对应 spec `2026-10-21-土系破甲归零-design.md`。

现状:卡详情 = `UI/CharPreview.cs`(卡组 / 开箱 / 战斗长按同一屏),版式见 `drafts/abilitytext`、`current/CollectionScreen`。

## 画板
- `Popup.dc.html`:整屏。控制条:状态(入口 / 弹窗)· 五行 · 断金(未学 / 已学 N=100 / 已学 N=300)· 入口(卡组 / 战斗长按)· 屏宽。
- `Typeset.dc.html`:五系 + 金系已学断金,实尺寸排版检查(每条字数、估算行数、弹窗高)。
- `Spec.dc.html`:入口实尺寸、对比度、分段尺寸、两档屏宽。
- 数据 `wx.js`(文案原样 + 估算函数,口径同 `Ui.WrappedTextHeight` / `Ui.EstimateWidth`);`wx.css` 的 `:root` 从 `tokens.json` 原值抄录。

## 方案要点
1. **入口**:名字行(`CharPreview.NameRow`)弹簧之后、关闭钮 × 之前,放一颗与 × **同款**的「?」:`Ui.RoundButton` 46 × 46(22pt)、
   圆角 23、`panel-inset` 底、`text-dim` 黑体 22,间距沿用名字行 15。部件(`def.IsComponent`)那一支不加(没有五系说明可讲)。
2. **外壳**:`Ui.Sheet` 定宽 **1120**(536pt),高按内容(287–392),屏幕正中;叠在卡详情之上,遮罩用 `scrim-soft` 42%
   (底下已有卡详情的 55%,再叠 55% 会黑成一片);`dismissable: true`,点遮罩或右上 × 关,只关这一层、回到卡详情。
3. **版式**(逻辑单位):头行 46 = 标题宋体 34 `<el>-glyph`(文案原样「火 · 烈焰焚身」)+ 右端 ×;副题黑体 22 `text-dim`;
   条目黑体 23 `text-quiet`、行高 31、宽 1041,左侧 10 × 10 本系 `<el>` 色块,「:」前的标签加粗 `<el>-fg`;
   末行生克条 = `panel-inset` 底 44 高,「克金，被水克。」里两个系字加粗配该系 `-fg`。不加「知道了」钮(需求只要点空白 / 关闭钮)。
4. **动态值**(用户补充):金系「锋刃回鞘」那条 `+{pct}%` —— 未学断金 100;已学 = 100 + N,N 读 Core 现成的
   `RunConfig.MoraleReleasePercent`(局外由 `PerkRules.ElementBonus(meta, MoraleRelease, Metal)` 给),Presentation 不手算断金。
   数字加粗;已学时后跟小注「（含断金）」黑体 19 `text-dim`。稿上蓝虚框只是标注,实现不画。其余文案一字不改。
5. **折行**:正文开 Wrap + `Ui.NoBreakSpaces`(与卡详情释义同做法),高度用 `Ui.WrappedTextHeight` 估;弹窗定宽,两档屏宽折行位置一模一样。

## 需要拍板的取舍
1. **战斗长按也给「?」**(推荐):同一张卡详情、同一行,局内最需要查;只读说明不改变「长按只看不出手」的语义。
2. **弹窗居中 vs 贴着「?」下拉**:稿画居中 `Ui.Sheet`(与升级成本说明同口径,省一套定位逻辑);下拉气泡未画。
3. **断金小注「（含断金）」**:推荐加,告诉玩家数字为什么不是 100;不要就删 `{note}`。
4. **断金数值对不上**:spec §2 末尾写「用户 10-19 撤回为 +100%(合计 +200%)」,但代码 `PerkRules` 里 metal_4 仍是 **300**
   (测试 `PerkTests` 也钉 300)。弹窗读 Core,哪个对都会如实显示(+200% 或 +400%);数值以哪个为准请确认,不在本稿范围。
5. **行首孤点**:Unity 逐字折行不避头尾,火、金(未学)两条会把「。」「怪。」挤到第二行行首(见排版检查)。可接受;
   要避免就得逐条手调文案或改宽,但文案不许改,建议接受。
