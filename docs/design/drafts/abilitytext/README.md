## 定稿要点

1. **取色 = A 案(已拍板)**:正文 `text-quiet`(12.0:1),词条 `<el>-fg` 加粗(≥7.0),数字 `text-main` 加粗;
   spent 全行 `text-dim`;off 不变。不新增 token,`text-quiet`、`<el>-fg` 的 usage 各补一句。
2. **全平铺**:两面是同一张网格的两列,每一级(Lv1 / 3 / 4 / 5 / 6 / 8)两面各一行,同级并排、行高取大;
   两面效果相同也各写一遍。「两面」条取消(SharedStrip / CompactRow 删)。现数据缺的级画「待补」斜纹占位。
3. **数值格(每面第一行)**:攻击面只列「攻击」;五行面按系 ——
   金 反击 · 格挡次数 · 战意|水 治疗(+回合,仅「涓」)|火 慑 · 回合 · 灼|木 木灵生命 · 木灵攻击|土 护盾 · 护甲 · 回合。
   数值格不再重复 Lv1 特性。
4. **各系 Lv1**:攻击面 火 灼 / 水 冻结或减速 / 木 种 / 金 战意 / 土 破甲;
   五行面 火 慑(原减攻)/ 水 润泽(涓 多回合少量 · 涌 单回合大量 · 苏 复活)/ 木 本命 / 金 格挡(按次数)/ 土 护甲。
5. **本命行**:Lv1 + 本命 chip(朱砂)+ 本命名 +「本命 · 被动」+ 当前等级的效果句;左缘 2pt 朱砂。林本命只留「成林」,
   速度改为五行面 Lv5 被动「林风」(替换原新芽)。
6. **名 + 图标**:行头 Lv 标与名之间一枚图标 chip(= 战场 chip,同图标同底色);词条气泡每条同样带 chip。点击粒度不变。
7. **文案**:`term.spirit.desc` =「木系召唤的单位」;减攻 → 慑;新增 涓 / 涌 / 苏,润泽改为总称。改字符串表后重跑字体子集。

## 回填记录

设计验收按 2026-10-11 约定跳过截图比对,改为体验时反馈(清单见末尾)。每条「改了什么 · 为什么」:

1. **图标 chip 取色走战场 chip 四组色**(威胁朱砂 / 控制 #19507F / 守御 #2E7D46 / 增益赭金),不用稿上的 ink-soft / jade 近似色;速度归守御(战场 `SpeedModifier>0` 即守御),稿上速度画赭金、控制画 ink-soft,实现随战场(D2)。为什么:稿 Spec §6 要求「取色走战场 chip 的同一张表,不另写一份」,行头 chip 与战场 chip 才是同一个东西。
2. **不新增图标**:慑 = curse、涓 / 涌 = heal、苏 = lastlife、速度 = speed,全部复用(D1)。为什么:稿 `sheet-data.js` 本来就用这几枚,`weaken` / `regen` / `revive` 在管线里不存在;Task 4 核对稿用 19 枚图标全在 `build_icons.ICONS`。
3. **苏的数值格出两格「治疗 + 复活生命 %」**,稿只写复活 %。为什么:spec A 的苏数据是 `Heal` + `ReviveHp`(沐 98 / 50,㵘 210 / 60),治疗量是真实效果,不出格玩家看不到。同时 `Body`(升级预览)也会多出一格「复活生命」。
4. **涓的治疗格印每回合量 + 回合**(如「17 / 回合」+ 回合格),稿只写「治疗(+回合,仅涓)」。为什么:卡面原先看不到每回合量,是 spec A 终审遗留项。
5. **数值格「%」印在值上**(`StatValue` 带「N%」,`StatUnit` 不再加),反击、慑、复活生命都如此。为什么:单位位留给「/ 回合」「回合」等真单位,避免印出「50%%」。
6. **数值格标签**:攻击面「伤害」→「攻击」;木灵格叫「木灵生命 / 木灵攻击」(攻击为 0 的荆 / 柘也出格);「持续 N 回合」沿用旧标签,不改稿上的「回合」(D10)。为什么:该标签与升级预览差行共用,改了会印出「回合 2 回合」。
7. **chip 尺寸**:铺满版 27(13pt),战斗版 25 = 战斗版行头高(D18)。为什么:战斗版行头只有 25,铺满尺寸放不下。
8. **「待补」占位不画斜纹**,画 panel-border 空心环 + text-mute「Lv6 · 这一面待补」(D12)。为什么:uGUI 没有重复渐变;占位只防御缺数据,spec A 合并后不出现。
9. **词条气泡词名后带第一个别名**(「慑(减攻)」「木灵(召唤物)」),宽 262pt(Task 8);词名取本系 -fg,说明 text-quiet。为什么:稿 bubble 有别名列,旧名帮玩家过渡。苏的说明写「复活阵亡的木灵」而非稿上的「友方单位」(spec A:苏救不了玩家)(D15 / D16)。
10. **「拆 / 合」印随两面条删除搬进各面行头**(Lv 标之后、chip 之前,D14)。为什么:两面条没了,印没有别的位置。
11. **行头图标规则**:本命行取本命 chip,其余行取正文第一个有 chip 的词条(稿 Spec §5);与稿样例里逐行写死的个别图标不同时以规则为准(例:荆 Lv4 披荆,稿写流血,实现取正文首个词条)。无图标的本命(花 / 藤 / 箭 / 柘)Lv1 行照出,只是不画 chip。
12. **行头类别**:木系五行面 Lv1「本命 · 被动」、Lv3「本命强化」,水系五行面 Lv1「主动 · 润泽」(D13)。
13. **spent 态收成「去底;Lv 标 text-dim 实底白字;名 / 正文 / 词条 / 数字全 text-dim;chip .6」**,off 的 chip .4。
14. **`TraitRow` 的 `onFill` 参数随 `SharedStrip` 删除**(唯一调用方没了)。纯实现清理。
15. **数值格口径不并入 Lv4+**:`FaceStats.Sheet` 与 `Body` 同取 Lv1 + Lv3 折叠值,现数据下与实战一致(金系 Lv4+ 反击 % 都不高于 Lv3);以后若有 Lv4+ 特性抬高反击 %,数值格会比实战低,届时再并入。
16. **未改**:升级预览(`CollectionView`)D11 原样保留 `SharedTraits` / `SharedRow` / `FaceStats.Body`,不出 chip;不新增「反击」词条(D17);特性名(林风 / 森风 / 浮藻 / 木疾 等)是游戏数据,不做成词条(D3)。
17. **「幼苗」「小藻」并进「小木灵」**(D4):稿 `sheet-data.js:23,88` 仍写「幼苗」,实现统一为「小木灵」。为什么:全游戏只留一个召唤物称呼,稿数据不回改,对稿时以此为准。
18. **慑的别名写法**:稿 `sheet-data.js:32` 写「原「减攻」」,实现印「（减攻）」(`glossary.alias`)。为什么:与气泡词名并排,括注比「原…」省宽。
19. **背面 off(未解锁)行的类别字取 text-dim 78%**,稿 `sheet.css:67-68`(`.tr.bk.off` 不覆盖 `.tk`)沿用 text-faint。为什么:text-faint 在纸色底上对比度不足,类别字仍要读得出。
20. **「伤害 → 攻击」改名也带到升级预览差行**:`charsheet.stat.damage` 被 `CollectionView` 差行共用(D11 要求升级预览不改,实际被带动,第 6 条只写了数值格)。为什么:同一个标签 key,拆开要多一份文案,且「攻击」在差行里同样成立。
