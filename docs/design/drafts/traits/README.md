## 一个记号贯穿全部界面

**面印**:每一面一枚方印,印文是这一面的单字(焚燃 · 斩铠 · 涛润 · 震固 · 刺生)。

| | 主面 | 副面 |
| --- | --- | --- |
| 印 | 朱文:`<el>-glyph` 实底 + 白字 | 白文:纸底 + `<el>-glyph` 1pt 描边 + `<el>-fg` 字 |
| 纸 | 纸白(`card-face`) | 背面纸:手牌用 `<el>-soft`,详情大块用 `--tint`(`<el>-soft` 34% 混 `card-face`) |
| 手牌另加 | — | 右上折角(9pt 三角,`<el>-glyph`):金系淡底与纸白只差一线,靠它兜底 |

同一枚印出现在手牌、拆合台、详情、升级预览、出手飘字、开局卷轴 —— 玩家只认这一个东西。
不新增 token:`--tint` 是 `<el>-soft` 与 `card-face` 的定比混色(Unity 侧 `Color.Lerp`),
五个值写在 `traits.css`,其上 `text-faint` 4.52–4.63、`text-dim` 5.30–5.44、`<el>-fg` ≥ 6.8,全部过 AA。

## 需拍板

1. **「点一下翻面」与现有手势冲突。** 现在「点」已经有两层意思:点未选中的牌 = 选中,点已选中的牌 = 直接出字
   (`BattleView.OnLibraryCharClicked`)。本稿保留前者、把后者换成**翻面**;出字仍有拖出与「出」钮两条路。
   代价是习惯「连点两下出字」的玩家第二下会翻面 —— 不耗 AP、看得见、可再翻回,是安全的失败。
   另一个做法是只在拆合台放翻面钮、手牌上不能翻:保住旧手势,但翻面藏得深。
2. **副面 60% 乘在哪些量上。** 稿里只乘伤害 / 护盾 / 治疗 / 召唤属性,层数、回合、次数、百分比不打折
   (按 §1「层数、回合、次数、击数不随等级涨」类推)。spec 没写死,实现侧确认后告诉我,我改稿。
3. **翻面状态的生命期。** 稿里定为:跟着这张牌直到出手,出手后回到主面;回合结束不重置。
4. **剩余场数的口径。** 卷轴上「剩 N 场」含本场,落印后减一;减到 0 显示「用完」,本场之后消失。

## 顺带查出的 spec 问题(请 card-ability-system-redesign 处理)

- **林**的本命叫「成林」(§9 本命表),Lv5 刺面特性也叫「成林」—— 同一张字上两个东西同名,详情页里分不清。
- §3 词条表缺「**标记**」「**减攻**」两条,而 §12 的状态 chip 清单里有。稿里先补了两句(`traits-data.js` 的 `GLOSS`),朱色标出,待 spec 收录。
- 「≤25 字」有几条超了:冷 Lv8「冷却」约 30 字、林 Lv6「林荫」约 27 字。详情页能折行放下,但飘字与升级预览会挤。

## 实现落点

- **新组件 `FaceSeal`**(面印):三档尺寸 10 / 13 / 17–24pt,主 / 副两式。先补进 `component/` 再用(CLAUDE.md 六步之 3)。
- `CharPreview` + `CharSheetSections`:左右两栏改为「两面 + 两面条 + 右栏」;`Traits` 段按面分组。
- `BattleView`:手牌 `GlyphTile` 加面印、背面底色与折角;`OnLibraryCharClicked` 第二次点击改翻面;
  拖拽点亮沿用 `DragToAttack.onBeginDrag` / `onDragMove`,**两条都不许重绘**;两面字不再进入双向态。
- 状态三处同接:`StatusText.Of`、`BattleView` chip 列表、`CharInfo` 效果文案。
- **新图标 8 枚**(格挡 种 霜抗 冰滞 致命 标记 嘲讽 留存护盾)走图标三处对账;SVG 路径即 `traits-data.js` 的 `ICONS` 里标 NEW 的那几条。
  兜底字:挡 种 霜 滞 危 标 嘲 留。泉 / 厚复用技能树的 `perk_wellspring` / `perk_heft`。
- 改名两处:持续治疗 → 润泽、诅咒 → 减攻(只改字符串表)。
- **字体子集**:面印十字(焚燃斩铠涛润震固刺生)、全部特性名、词条表、兜底字都是新文案,上线前重跑 `tools/fonts/subset_fonts.py`。
