# 升级宝箱 · 主动领取

需求来自 session「角色升级宝箱主动领取」(2026-10-19)。现状:每级宝箱回地图 / 结算时自动塞进空箱位(`LevelRewardRules.GrantLevelChests`),
箱位满就欠着,玩家控制不了时机、也看不清还欠几只。改为:升级只记一只「待领」,玩家在角色页**里程碑轨道**上一只一只主动领。
用户已拍板:一只一只领、不做「全部领取」;档位规则不变(Lv.2–5 竹简 · 6–10 青瓷 · 11–20 紫檀 · 21–30 鎏金 · 31–40 朱漆 · 41+ 赤霄);
宝箱并进轨道、**每级一格**(用户原话:「就是每级都有一格可以领宝箱」);轨道变长后**打开角色页要聚焦到还没领的地方**。

底稿是 `../character/` 的 `Character.dc.html` / `LevelUp.dc.html`;颜色按 `current/` 现状(领取钮、「知道了」、「升 级」用 `cta` 石青)。

## 画板
- `Claim.dc.html`:角色页整屏。底部控件:五种局面(常态 / 积压 5 只跨档 / 箱位已满 / 全领完 / Lv.50 之后)、屏宽(基准机 / 16:9)、轨道「◂ 滚 / 聚焦 / 滚 ▸」。
- `LevelUp.dc.html`:升级弹窗(一档 + 一条里程碑)。

## 1. 角色页 ·「等级奖励」长轨道(原「等级里程碑」)
**左档案栏不动**(同现状;原「待发 N 只」欠箱 chip 删掉,封顶说明保持原文两行)。

**粒度**:每个等级一格,从 Lv.2 起(Lv.1 不发箱)。每格挂一只该级的升级宝箱;里程碑等级(Lv.5 / 10 / … / 50,之后每 10 级)的格子同时挂里程碑奖励。

**格**:定宽 115(54.95pt,= 现状 10 格等分时的格宽),格距 8(3.82);卡内净宽 ≈ 99(47pt),格内一律单行。纵向沿用面板定高 327。
- 钉:普通级 27(13pt)小钉、上下各让 7 与里程碑钉对齐;里程碑级 42(20pt)大钉外加赭金描圈(`gold-soft` 2pt + `rarity-gold` 1pt),一眼分出里程碑格。
  钉色:全领完 `jade` + 白勾;有可领 `cta`;未达 `panel-border` 描圈。底线 `rarity-gold`(同现状)染到当前等级。
- **普通格**(自上而下):「Lv.N」25(12pt)宋体 → 箱立绘 `ChestArt` 50(24pt,档位色)→ 箱名 17(8.12pt)`text-dim` → 底行。
- **里程碑格**:卡底 `gold-soft` 淡化(#FBF5E4)+ `rarity-gold` 60% 描边;「Lv.N」后面并排一枚 23(11pt)小箱立绘(该级宝箱的状态)→ 墨锭行(同现状)→「金字 3 选 1」(同现状)→ 底行。
- 宝箱状态画在立绘上:已领 = 立绘 35% + 右下 `jade` 小勾;可领 = 原色;未达 = 去色 70% + 45%。
- **底行**(每格一颗,一只一只领):
  | 情况 | 底行 |
  | --- | --- |
  | 里程碑可领(只在里程碑格) | 「领奖励」`cta`(点了开 `MilestonePickSheet`,不占箱位)—— **里程碑优先**,领完这颗钮变成宝箱的 |
  | 宝箱可领、有空箱位 | 普通格「领 取」/ 里程碑格「领宝箱」`cta`;点了直接放进一个空箱位(不占暂存位),格子原地换成已领 |
  | 宝箱可领、箱位已满 | 置灰 `locked-bg` 底 `text-faint`「箱位已满」(不可点);待领不作废 |
  | 都领完 | 「已领」18 `text-faint` |
  | 未达 | 「差 N 级」18 `text-faint` |
- 钮高 40(19pt)、撑满卡宽;「箱位已满」4 字 × 19 = 76 + 12 ≤ 99 ✓。
- 宽度验算(卡内 99):「Lv.20」+ 小箱 = 41 + 4 + 23 = 68 ✓;最长箱名「紫檀匣」3 × 17 = 51 ✓;墨锭行与「金字 3 选 1」同现状。
  **Lv.100 起的里程碑格**「Lv.100」+ 小箱 = 83 + 27 = 110 > 99 → 三位数等级时 Lv 字号 25 → 21(69 + 27 = 96 ✓)。
- 纵向(面板 327 内,轨道区约 241):钉行 42 + 4 + 卡(内边距 8×2 + Lv 31 + 墨锭 25 + 稀有度 23 + 钮 40 + 间距 4×4)≈ 197 ≤ 241 ✓;普通格更矮。

**标题行**:「等级奖励」+「每级 1 只宝箱 · 每 5 级里程碑」(Lv.50 后改「每 10 级里程碑」)+ 分隔线 + 右端「待领 宝箱 N · 里程碑 M · 箱位 n / 4」
(没有待领时只写「箱位 n / 4」;箱位满时数字 `cinnabar-dark`)。原「已领 x / 10」与「Lv.50 之后每 10 级 · …」两句删掉(后者由格子本身说明)。
16:9 下面板宽 ≈ 914:标题 + 副标 + 右端最长 ≈ 830 ≤ 872 ✓(副标去掉括号段才放得下)。

**轨道范围与滚动**
- 范围:Lv.2 → max(Lv.50, 当前等级 + 5, 下一个里程碑等级)(Lv.50 兜底见回填记录)。末端总露出下一个里程碑。Lv.62 时 69 格 ≈ 8,000 宽,轨道是独立的横向 `ScrollRect`(只横向、惯性、无滚动条)。
- **打开即聚焦**(沿用 `ScrollToClaimable` 的口径):滚到第一个还有「已达到但未领」的宝箱或里程碑的格,目标格左侧留 1 格上下文;都领完 → 当前等级的格落在视口约 60% 处(右边露出后几级)。
- 两侧 18pt 纸色渐隐提示还能滚;**屏外还有可领**时贴边出一枚 `cta` 小签「◂ 2 待领」/「3 待领 ▸」,点了滚过去。
- **领取后重建保持滚动位置**:记 `_trackScrollX`(同现状 `_rightScrollX` 的做法),`Rebuild` 后恢复;只有首次打开才聚焦。
- **与右栏横滚的手势冲突**:里程碑面板**移出** `HScrollFill`,宽 = 右栏视口宽,轨道在面板内自己横滚;`HScrollFill` 只包统计面板(最小排版宽 1265 不变,16:9 下照旧横滚)。
  两层横向滚动区上下分开、不嵌套,没有手势争夺。基准机两者都铺满,统计面板拖不动、轨道照常滚。
